## 실행

웹은 `~/webapp`에서 서버의 Python 환경 `~/venv/web`으로 실행된다.
브라우저 주소는 `http://220.69.208.201:8500`이다.

```bash
ssh raon bash /home/crc_unity/webapp/web_start.sh
ssh raon bash /home/crc_unity/webapp/web_stop.sh
```

설정은 서버 `~/webapp/Web/.env`. `SESSION_URL=http://127.0.0.1:8000`,
`SESSION_TOKEN`을 등록 API의 `SESSION_TOKEN`과 일치시킨다. 코드에 기본 접속 토큰은 없다.
기존 `RAON_URL/RAON_TOKEN` 이름과 Raon bootstrap·억양 토글은 폐기했다.
파일과 환경을 고친 뒤 웹을 재시작하고 `/status`에서 등록 API 연결을 확인한다.

## 등록과 3D

동의 → 음성·사진 업로드 → 그분의 정보·기억 카드·마음·대화 방식 입력 → 참조 미리 듣기 → 인물 확인 → 등록.
인물 확인에 도달하면 현재 설문으로 확인 내용을 만든다. 설문을 바꾸면 확인 내용과 최종 확인란이
함께 무효가 되고 다시 확인해야 등록할 수 있다. 인물 텍스트를 화면에서 직접 편집하지 않는다 —
편집 기준을 설문 하나로 두어야 무엇이 등록됐는지 대조할 수 있다.
첫 화면은 빈 설문이며, 상단 `테스트`에서 가상 인물(할머니·친구)을 고를 때만 입력이 채워진다.
세션 ID는 입력하지 않으며 서버가 UUID4를 발급한다.
기존 등록 인물은 보관하고 새로 등록한 인물을 현재 체험 대상으로 선택한다.
인물·설문 저장 또는 모델 접수의 부분 실패는 완료 화면에서 별도로 알린다.
사진이 없으면 3D 생성 없이 인물만 등록된다. 웹은 SQLite에 생성 작업을 넣고,
`Survey/model_worker.py`가 별도 프로세스에서 Tripo 요청·결과 다운로드·등록 API 전달을 수행한다.
완성된 GLB가 `/session/{sid}/model`로 전달된 뒤 완료 상태가 된다. Unity가 현재 인물과 GLB를 조회한다.
웹을 재시작해도 작업 ID는 남는다. `/status`의 `model_worker`에서 작업자 상태를 확인한다.
참조 음성은 24kHz 모노로 변환하며 `/last_ref.wav`에서 실제 전송 파일을 확인할 수 있다.

## 오디오 변환

참조 음성은 **24kHz 모노 PCM16**으로 맞춘다. 음량만 보정하고 내부 쉼과 말하기 속도는 보존한다.

- **먼저 libsndfile(librosa)로 그대로 읽어 본다.** 읽는 형식은 빌드·버전에 따라 다르다
  (WAV·FLAC·OGG는 기본이고, MP3처럼 환경에 따라 직접 읽히는 것도 있다).
- **읽지 못하면 ffmpeg로 넘어간다.** 운영 환경의 M4A/AAC는 여기로 온다. 2026-09-16 이전에는
  libsndfile의 `Format not recognised`가 처리되지 않아 `text/plain`의 `Internal Server Error`
  500이 나갔고, 화면이 JSON으로 읽다가 `Unexpected token 'I'`를 참여자에게 그대로 보여줬다.
  어느 경로로 읽었든 결과는 같은 24kHz 모노 PCM16이다.
- ffmpeg는 `imageio-ffmpeg`가 함께 배포하는 정적 바이너리를 쓴다. **sudo나 시스템 설치가 필요 없다.**
  `pip install -r requirements.txt`로 들어가며, PATH에 `ffmpeg`가 있으면 그것도 쓴다.
- 쓸 수 있는 ffmpeg가 없거나, 경로는 있는데 실행되지 않으면(지워짐·권한 없음·플랫폼 불일치)
  변환이 필요한 형식만 **503**으로 거절하고 WAV로 올리도록 안내한다.
  손상되었거나 소리가 없는 파일은 **400**, 변환이 너무 오래 걸리면 **504**다.
  실패는 모두 JSON이며, 서버 경로나 ffmpeg 원문은 화면에 보내지 않고 서버 로그에만 남긴다.
- 업로드는 요청마다 다른 임시 파일에 쓰고 성공·실패 모두 지운다. 첫 오디오 트랙만 사용한다.

등록 화면은 서버 응답을 글로 먼저 읽는다. JSON이 아닌 오류·깨진 성공 응답도 한국어 한 줄로
보여주고, **설문·파일·확인 상태를 지우지 않으므로 그 자리에서 다시 시도**할 수 있다.
등록은 200이어도 **하이픈 없는 32자리 UUID4 세션 코드**가 와야 완료 화면으로 넘어간다.

**한 사람이 말하는 녹음 파일 하나**를 올린다. 화자 분리·자동 판별은 제공하지 않으므로,
여러 사람이 섞인 녹음은 한 사람만 나오는 구간을 잘라서 올린다.
웹은 파일 업로드 방식이며, 브라우저 마이크를 새로 도입하면 HTTPS 연결도 준비해야 한다.

3D API 키는 `Tools > 서버 연결 상태 확인` 또는 관리자 인증이 필요한 `/admin/tripo`로 설정한다.
키의 원문은 반환하지 않는다. 참가자 자료·참조 음성·API 키·관리자 비밀번호를 저장소에 넣지 않는다.
관리자 비밀번호가 비어 있으면 관리자 API는 설정 오류로 접근을 거부한다.
Tripo 키 변경은 작업자가 다음 작업을 시작할 때 읽는다. 대화 AI 재시작은 필요하지 않다.
