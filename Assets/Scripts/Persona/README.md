# 등록 캐릭터 로딩·이동·애니메이션 설정

기준일: 2026-10-25. 현재 등록 체험 씬은 `Assets/Scenes/Scene_2.unity`다.
등록 서버의 GLB를 glTFast로 불러오고 고정 몸체의 뼈대에 Unity Humanoid 동작을 연결한다.
등록 순서는 [Scene_2 체험](../../../docs/Scene_2_웹설문_테스트.md), 본 매핑·검사 이력은
[머리 파이프라인](../../../docs/Tripo_머리_생성_파이프라인.md)을 따른다.

## 1. 현재 데이터 흐름

```text
웹 설문·참조 음성·사진 등록 → UUID4 발급 + 별도 모델 작업 접수
  → Tripo 머리 생성 → Blender 정리·고정 몸체 결합
  → 등록 서버에 리그 포함 model.glb 전달
  → Unity에서 현재 세션·has_model 확인 → GLB 다운로드·로드
  → 체험 시작 → 모델 표시·경로 이동·인사·착석 + 음성 대화
```

`PersonaSpawner`는 같은 씬의 `DialogueVoiceClient`가 있으면 주소·토큰·세션을 따라간다.
없으면 자체 `serverUrl`·`token`으로 `/session/current`와 `/session/{id}/model.glb`를 조회한다.
사진·모델 없는 등록은 캐릭터 로드 조건을 충족하지 않는다. 실제 키·세션 ID는 문서에 기록하지 않는다.
현재 동작은 HTTP 기반이다. 이전 Streamlit/Meshy·`current_session.txt`·로컬 자료 폴더 안내는 적용하지 않는다.

## 2. 씬 연결과 자주 조절하는 값

Scene_2에 있는 캐릭터 로더와 입장 동선을 사용한다. glTFast 6.14.1은 프로젝트에 포함돼 있다.

| 컴포넌트·설정 | 의미·현재 Scene_2 기준 |
|---|---|
| `PersonaSpawner.spawnPoint` | 모델 배치 기준 위치·회전 |
| `targetHeightMeters` | 키 자동 보정. Scene_2는 `0`으로 원본 크기 유지 |
| `scaleMultiplier` | 얼굴·머리·몸체 전체의 추가 배율. Scene_2는 `1.2` |
| `bodyShapeProfile` |6개 체형 키 설정. 비워두면 `Assets/Resources/PersonaBodyShape.asset` 사용 |
| `seatedHeadLiftDeg` | 착석 후 고개 높이 보정. Scene_2는 `15`도 |
| `stabilizeHeadWhileSitting` | Scene_2는 켬. 앉기 클립의 혼합 비중에 맞춰 목·머리의 상대 회전을 안정화하고 착석 후 시선 복귀 |
| `fillNeckInterior` | Scene_2는 켬. 별도 피부 목 구조가 있는 모델의 열린 윗면·어두운 내부 면을 피부색으로 채움. 모델 로드 시 적용 |
| `arrival` | 이동·인사·착석을 제어하는 `PersonaArrival` |
| `PersonaArrival.walkSpeed` | Scene_2는 `0.8m/s`. 선택한 걷기와 최종 몸체의 보폭에 맞춘 값 |
| `PersonaArrival.sitDownPlaybackSpeed` | Scene_2는 `1.3`. 3.1초 앉기 클립을 약2.385초에 재생하며 위치 보간도 함께 조절 |
| `waitForExperienceStart` | Scene_2는 켬. 로드를 마쳐도 체험 시작 전에는 숨김 |
| `ExperienceControl.spawner` | 체험 시작·종료를 캐릭터 표시와 입장 연출에 연결 |
| `PersonaArrival.referencePose` | 고정 Human의 Humanoid 기준 자세 보정 자산 |
| `PersonaArrival.groundPath` | 직접 그린 바닥 경로 |
| `greetOnPath`·`greetPathProgress` | 경로 도중 인사 여부·전체 길이 대비 인사 위치 |

`scaleMultiplier`는 몸체와 얼굴에 함께 적용한다. 값을 저장하려면 Edit Mode에서 수정한다.
Play 중 수정은 확인용이며 종료하면 되돌아갈 수 있다. AI_Response_Test·Tripo_Model_Test는
목적과 접속 설정이 다른 씬이므로 설정을 서로 복사하지 않는다.

### 체형 조절

10월13일부터 기본 몸체는 상체 폭·두께, 허리 폭, 배 볼륨, 팔·다리 굵기의6개 Blend Shape를 포함한다.
`Tools > 다시봄 > 캐릭터 > 체형 조절 열기`에서−1~1로 조절하며0은 원래 체형이다.
설정 자산을 저장하면 Play 종료 후에도 유지되고, 로더는 모델을 표시하기 전에 해당 설정을 연결한다.
컨트롤러는 각 렌더러의 가중치만 바꾸며 본·바인드 행렬·공유 메시·머리·손을 수정하지 않는다.
키가 없는 이전 GLB에는 체형 변형이 적용되지 않으며, 기존 등록 모델을 자동 재제작하지 않는다.
제작 원본과 검사는 [몸체 제작 안내](../../../tools/model_sources/README.md)를 따른다.

얼굴과 몸체를 붙인 상태의 별도 작업은 `Tools > 다시봄 > 캐릭터 > 얼굴·몸체 비율 조절 씬 열기`를 사용한다.
`Persona_BodyShape_Preview`에서 Play 없이 T포즈·서있기·앉기를 바꾸며 체형6개 키와 전체 크기·머리 크기/높이/앞뒤를 조절한다.
별도 미리보기 설정을 저장하며 **기본 체형에 적용**을 눌러야 위 공용 설정으로 복사한다.
`PersonaModelProportions`는 원본 옷깃을 복원하고 분리 머리 전체를 접합점에 맞춰 이동한다. 머리3개 키를 유지하며 원통형 목은 추가하지 않는다.
전체 크기는 리깅 전체 배율이며 팔다리 개별 길이는 고정한다. [결합 보정 기록](../../../docs/머리_목_결합_수정_20261024.md)을 따른다.
[체형 미리보기 사용법](../../../docs/얼굴_몸체_체형_미리보기_20261023.md)을 따른다.

## 3. 경로와 애니메이션

`Tools > 다시봄 > 캐릭터 > 이동 경로 편집`에서 바닥 경로와 인사 지점을 편집한다.
전체 메뉴 분류와 초기 설정·검사 도구는 [Unity 도구 사용법](../../../docs/Unity_도구_사용법.md)을 따른다.
Scene_2의 `입장 동선 / 04_이동 경로 (바닥)`이 현재 연결된 경로다. 가구를 피하는 경로를 직접 그린다.

```text
UnityMaleIdle → NaturalWalk → 사용자 쪽 회전 → NaturalGreeting
     → 경로 방향 회전 → NaturalWalk
     → 의자 방향 정렬 (좌/우 회전) → SitDown (1.3배) → Sitting Idle
```

실제 이동은 코드가 담당하며 Animator Root Motion은 끈다. 속도에 맞춰 걷기 재생과
Idle/Walk 비율을 조절하고 PlayableGraph로 동작을 섞는다. 회전은 경로·최종 착석 방향을 따라 보간한다.
현재 NavMesh 장애물 회피나 매 프레임 신발 바닥 추종은 없다. 9월 30일 사용자 요청으로
자동 바닥 추종을 제거했으며 이동·인사·회전 중 루트 높이를 고정한다.

현재 걷기는 Quaternius, 인사는 Mesh2Motion 클립이다. 인사 진입의 손목·아래팔3개 곡선을 보정했다.
보행 중 골반·다리 IK는 사용하지 않는다. 착석 발 보정은 `Sitting Idle`의 실제 혼합 비중에 맞춰 적용한다.
클립 출처·고정 버전·라이선스는 [클립 구성](../../Animations/PersonaPerformance/Source.md),
실제 Editor 검사·남은 HMD 범위는 [동작·목 내부 기록](../../../docs/머리_목_결합_수정_20261024.md#착석-배속인사-진입-손목목-내부-피부색--2026-10-25)을 따른다.

착석 후 기본은 `Sitting Idle`이다. NPC 음성이 실제 재생되는 답변에서6초 `CalmSeatedTalk`를
평균 25%로 선택하고 다음 답변은 강제로 건너뛴다. 정확히 매 네 번째마다 실행하는 규칙은 아니다.
같은 답변의 음성 조각이나 재개는 다시 추첨하지 않는다. 상체 마스크로 다리는 앉은 자세를 유지한다.

### 듣는 반응과 공간 음향

10월23일부터 Scene_2에서 확정된 사용자 발화에 작은 끄덕임을 적용한다.
착석·대화 연결 이후 길이1.2초 이상의 발화가 확인되면 최대4.5도·0.9초로 한 번 고개를 내렸다 돌린다.
반응 간격은4.5~7초이며, 인물이 말하거나 다른 제스처가 재생 중이면 새 반응을 만들지 않는다.
단순 마이크 음량이나 자막 표시 여부로 결정하지 않는다. 서버가 발화를 확정한 직후의 듣기 반응이며,
말의 내용·감정에 동의하는 기능은 아니다. 기존 시선·호흡·착석 고개 보정 위에 목35%·머리65%로 얹는다.
`PersonaArrival`의 `Auto Nod While Listening`, `Nod After Listening Sec`, `Listening Nod Degrees/Seconds`로 조절한다.

캐릭터 로더의 `PersonaVoiceSpatialAudio`가 기존 음원을 머리 위치에 따라 붙인다.
`Spatial Voice`로 켜고 끄며 `Min Distance`1.5m·`Max Distance`18m의 선형 감쇠를 쓴다.
도플러는 끄고, 기존 Meta XR Audio를 PCM 필터 뒤에 적용한다. 사용자 음량·스트리밍·끼어들기 커서는 보존한다.
모델이 없는 음성 전용 체험은2D로 돌아가고, 컴포넌트를 비활성화하면 원래 음원 설정을 복원한다.
다른 씬에 이 컴포넌트를 자동으로 추가하지 않는다.

검사 메뉴는 `Tools > 다시봄 > 개발 도구 > 캐릭터 검사`의 `듣기 반응·공간 음향`과 `공간 음향 실제 출력 (Play)`이다.
후자는 Play 중 체험 시작 전에 합성 소리를 재생해 최종 좌우 출력을 확인한다.
설정·실제 검사와 남은 HMD 청취 범위는 [구현 기록](../../../docs/캐릭터_듣기_반응_공간음향_20261023.md)을 따른다.

## 4. 시작·종료와 미리보기

- Scene_2의 `체험 시작`은 같은 버튼으로 등록·서버·마이크 장치·모델과 입장 준비를 재확인한다. 미준비 상태에서 누르면 버튼 위에 빨간 미완료 항목을 표시한다.
- 별도 `준비 다시 확인` 버튼은 제거했다. 준비 조건을 통과해야 입장하며, 입장 중 음성을 준비하고 착석 뒤 새 마이크 입력을 시작한다. 시작 버튼은 대화 초기화 바로 위다. [시작 준비와 검사](../../../docs/체험_시작_준비_20261024.md)를 따른다.
- `체험 종료`는 입력·음성을 멈추고0.8초 페이드아웃 뒤 인물을 숨긴다. 다음 시작 때 화면이 밝아지고 같은 모델을 경로 처음부터 사용한다. 연결 실패·컴포넌트 비활성화 시에는 즉시 정리한다.
- `Tools > 다시봄 > 캐릭터 > 모델 미리보기 열기`는 로컬 GLB 확인용이며 여는 것만으로 Tripo API를 호출하지 않는다.
- `Tools > 다시봄 > 캐릭터 > 전체 리깅 보기`에서 Play 중 실제 Skin 본과 Humanoid 연결을 표시한다. `F8`로 표시를 전환한다.
- `Tools > 다시봄 > 개발 도구 > 캐릭터 검사 > 고정 몸체 애니메이션`은 별도 미리보기 씬에서 FBX와 준비된 GLB의 변형을 검사한다.

현재 머리 결합 GLB는 skin을 보존하고 클립은 넣지 않는다. 걷기·인사·착석은
`Assets/Models/use_animation/` 등의 Unity 클립으로 재생한다. 기존 턴 클립과 기준 자세용 Walking은 별도 참조를 유지한다.
얼굴 표정 리그·립싱크·머리카락 물리는 자동 생성하지 않는다.

## 5. 문제 확인 순서

| 증상 | 먼저 확인할 것 |
|---|---|
| Play만 했는데 인물이 안 보임 | 체험 시작 버튼, 모델 생성 완료 여부 |
| 생성 완료인데 Unity에 안 나옴 | 등록 서버 `has_model`, 세션 일치, GLB 다운로드·로드 오류 |
| 너무 크거나 작음 | `targetHeightMeters`·`scaleMultiplier`를 함께 확인 |
| 팔다리가 접히거나 손이 몸을 통과함 | 본 매핑·기준 자세·클립 Avatar 확인. 몸체 준비 시 `tools/body_prep.py` 사용 |
| 인사 위치·방향이 이상함 | 경로 점, 인사 진행률, 사용자 카메라·최종 착석 방향 |
| 앉은 뒤 고개가 낮음 | `seatedHeadLiftDeg` 확인 |
| 얼굴이 잘리거나 목 경계가 이상함 | 서버의 머리 정리·결합 결과 확인 |

날짜별 실제 Play·음성 검사 범위와 남은 VR 장치 검증은
[현재 구현 현황](../../../docs/현재_구현_현황.md)에 있다. 10월23일에는 합성 신호·공통 몸체·Play의 합성 PCM 출력을
확인했으며, 실제 등록 목소리로 새 대화 왕복이나 HMD 청취 검사를 수행한 것은 아니다.
