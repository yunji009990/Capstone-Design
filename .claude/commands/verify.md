증상: $ARGUMENTS

Codex 를 **독립 진단자**로 띄운다. 다른 모델 계열의 두 번째 의견을 받는 것이 목적이다.

## 지켜야 할 것

**내 결론을 프롬프트에 넣지 마라.** 넣으면 동조한다. 증상·재현 조건·관련 파일 경로만
주고 원인을 스스로 찾게 한다. 대조는 결과가 온 뒤에 내가 한다.

의심 파일은 지목해도 된다(어디를 볼지는 정보다). **무엇이 원인이라고 생각하는지는 말하지 않는다.**

## 실행

`.claude/work/` 를 만들고, 아래를 `run_in_background: true` 로 띄운다.

```bash
codex exec \
  -m gpt-5.6-luna \
  -c model_reasoning_effort="max" \
  -s read-only \
  --ephemeral \
  -o "C:/Users/user/Documents/GitHub/Capstone-Design/.claude/work/verify-$(date +%H%M%S).md" \
  "<증상·재현조건·관련경로만 담은 프롬프트>" < /dev/null
```

**`< /dev/null` 을 빠뜨리지 마라.** `codex exec` 는 stdin 이 열려 있으면 EOF 를 기다리며
멈춘다 — 13분이 지나도 안 끝난다(실측). 붙이면 같은 프롬프트가 5.3초에 끝난다.

프롬프트에 반드시 넣을 것:
- 증상과 재현 조건
- 관련 파일 경로 (`Server/app.py`, `Web/app.py` 등)
- **"docs/ 를 먼저 읽어라. 이미 기각된 가설이 그 안에 있다"**
- **"원인 후보를 3개까지 대고, 각각을 어떻게 확인할지 적어라"**
- **"확신이 안 서면 미확정이라고 적어라. 확신하는 척하지 마라"**

## 기다리는 동안

메인은 **자기 진단을 따로 적어 둔다.** Codex 결과를 보고 나서 만들면 그쪽에 끌려간다.

## 결과가 오면

1. `-o` 파일을 읽는다 (전체 로그는 읽지 않는다)
2. 내 진단과 **어디가 갈리는지**부터 본다. 같은 결론이면 그건 확인이지 검증이 아니다
3. 갈리면 **어느 쪽이 맞는지 실측으로 가른다** — 두 진단을 놓고 고르지 말 것.
   한 번에 한 변수, 오디오는 소스 3개·회차 3회
4. 결론을 사용자에게 보고할 때 **두 진단이 갈렸다는 사실을 숨기지 않는다**
