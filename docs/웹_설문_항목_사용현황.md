# 웹 설문 항목 사용 현황

**아래는 수정 전 조사 기록이다.** 같은 날 사용자 요청으로 설문 재작성·기본 예시 제거·무작위 ID 발급을
수정하고 서버에 적용했다. 현재 동작과 검증 결과는 [웹 등록 흐름 개선](웹_등록_흐름_개선.md)을 따른다.
말투·이름 예문 문제는 후속 논의를 위해 그대로 두었다.

조사일: 2026-09-15. 수정 전 `jw` 소스와 당시 서버 배포 파일을 읽고, 가상 입력으로 전달 경로를 검사했다.
이 문서의 ‘사용’은 입력이 해당 처리에 전달된다는 뜻이다. 실제 Gemma가 매 답변에서 정확하게 반영한다는 품질 판정은 아니다.

## 1. 확인 결과

설문 JSON의 **16개 항목 중 12개는 대화 프롬프트에 사용**한다. 나머지 4개인 사별 기간과 동의 3개는
설문 기록·관리자 조회·웹 화면의 안내와 진행 조건에 사용한다. 정상 저장 경로에서는 16개 모두 설문 DB에 남는다.
사진·음성·화자 수·세션 ID·직접 편집한 인물 설정은 설문 JSON과 별도로 전달한다.

대화 AI가 설문 DB를 직접 읽는 구조는 아니다.

1. 웹 9단계에서 설문을 `/persona`로 보내 `Web/persona.py`의 규칙 기반 템플릿으로 인물·사전지식을 만든다.
2. 사용자가 이 두 텍스트를 확인·편집한다. 웹의 ‘세션 시작’은 최종 텍스트와 참조 음성을 등록 API에 보낸다.
3. 설문 원문은 별도의 DB에 기록하고, 사진이 있으면 별도의 3D 생성 작업을 등록한다.
4. Unity에서 체험을 시작하면 대화 서버가 등록 API의 `persona`, `knowledge`, `rules`, 참조 음성을 읽는다.
5. Gemma에는 공통 규칙 + 인물 + 사전지식 + 말투 예시가 전달되고, Qwen3-TTS에는 생성할 대사와 참조 음성이 전달된다.

설문 변환 자체는 LLM 호출이 아니다. 현재 Gemma 공통 규칙은 대화 서버에서 추가된다.
등록 정보를 바꾼 뒤에는 체험 연결을 다시 시작해야 새 인물 설정을 읽는다.

## 2. 설문 16개 항목

| 웹 입력 | 내부 항목 | 대화 AI에서의 사용 | 다른 사용처·제한 |
|---|---|---|---|
| 관계 | `relation` | 캐릭터 관계, 자기 지칭, 어미·추임새·대화 예시 결정 | 관계 문자열을 어른/손위/손아래/또래로 분류. DB·관리자에도 저장·표시 |
| 성별 | `sex` | 인물 소개 문장에 추가 | TTS 목소리 성별이나 3D 외형을 선택하는 매개변수로는 보내지 않음 |
| 그분을 부르던 호칭 | `honorific` | 사용자가 캐릭터를 부르는 말. 어른 유형이면 캐릭터 자기 지칭에도 사용 | 별도의 인물 실명 필드는 아님 |
| 그분이 나를 부르던 말 | `calls_user` | 캐릭터가 사용자를 부르는 호칭·사용 빈도 | 인물·사전지식 모두에 포함 |
| 내 이름 | `user_name` | 사용자의 이름을 사전지식에 추가 | 인물의 재답변 예문에도 들어가는 문제가 있음. 아래 4절 참고 |
| 성격 선택·기타 성격 | `personality_traits` | 인물의 성격 지시 | 선택값과 자유 입력을 하나의 목록으로 합침. 몸짓·애니메이션에는 미연결 |
| 자주 쓰던 말·말버릇 | `speech_quirks` | 자주 사용할 표현, 조건에 맞는 짧은 표현은 첫 인사 예시에도 추가 | 웹 입력은 3칸. TTS에 별도 말버릇 옵션으로 전달하지는 않음 |
| 함께한 추억·언제쯤인지 | `shared_memories` | 사전지식의 회상 근거 | 시점과 장면을 한 문장으로 합침. 장면 없이 시점만 입력하면 해당 항목은 빠짐 |
| 가장 그리운 순간 | `missed_moment` | 사용자가 그리워하는 장면을 사전지식에 추가 | ‘캐릭터가 실제로 겪은 추가 사실’로 자동 보완하지 않음 |
| 전하지 못한 말 | `unsaid_words` | 사전지식에 넣되 사용자가 먼저 꺼낼 때까지 언급하지 말라는 지시 추가 | 프로그램으로 발언을 차단하는 장치는 아니므로 실제 준수 여부는 답변 평가가 필요 |
| 다시 듣고 싶은 말 | `wished_to_hear` | 위와 동일하게 조건부 대화 소재로 사용 | 시작하자마자 해당 말을 자동 재생하는 기능은 아님 |
| 대화 톤 | `tone_setting` | 위로형/평소 대화형/자유 대화형에 해당하는 문장을 인물 설정에 추가 | 일반·추론 모드 선택, TTS 감정·속도 수치, 애니메이션 선택과는 별개 |
| 사별 후 경과 주 | `bereavement_weeks` | **프롬프트에 넣지 않음** | DB·관리자 조회와 웹의 4주 미만 안내에 사용. 경과 주에 따른 대화 정책 변경은 없음 |
| 사진 사용 동의 | `consent_image` | **프롬프트에 넣지 않음** | DB·관리자에 기록, 웹 1단계 진행 조건. 사진을 올리지 않아도 현재는 동의해야 진행 가능 |
| 음성 사용 동의 | `consent_voice` | **프롬프트에 넣지 않음** | DB·관리자에 기록, 웹 1단계 진행 조건 |
| 재현임을 이해한다는 동의 | `consent_understand` | **프롬프트에 넣지 않음** | DB·관리자에 기록, 웹 1단계 진행 조건 |

근거: [설문 화면·전송](../Web/static/index.html), [인물·사전지식 변환](../Web/persona.py),
[설문 저장](../Survey/core/database.py), [관리자 조회](../Web/static/admin.html).

사별 기간을 프롬프트에서 제외한 것은 기존 구현의 의도다. 과거 비교 실험에 대한 주석이 있지만,
그 실험을 현재 Gemma 설정에서 다시 검증한 것은 아니다. ‘쓰지 않으니 삭제해도 되는 항목’으로 분류하지 않는다.

## 3. 설문 JSON 외의 입력

| 입력 | 실제 사용 | 대화 내용·모델과의 관계 |
|---|---|---|
| 오디오·영상 파일 | 직접 참조 음성 또는 화자 분리의 입력. 등록 시 24kHz 모노로 변환하고 대화 시작 시 최대 12초의 연속 구간을 골라 전사 | 선택한 목소리·말투를 Qwen3-TTS의 참조로 사용. 녹음의 내용을 인물 추억이나 사전지식으로 자동 저장하지 않음. 영상 프레임도 인물 정보로 분석하지 않음 |
| 화자 수·선택한 화자 | 한 명이면 분리를 건너뜀. 자동/다수이면 분리기의 설정으로 쓰고 선택한 화자의 참조를 등록 | LLM 성격 설정과 무관. 추출 작업 자료에 남을 수 있지만 설문 JSON에는 없음. 이번 검사에서는 실제 분리 엔진을 실행하지 않음 |
| 사진 | 설문 자산으로 저장 → Tripo 작업자 → GLB → 등록 API → Unity | 대화 LLM에 사진을 보내지 않음. 사진에서 이름·성격·추억을 추출하지 않음 |
| 세션 ID | 인물·참조 음성·설문·모델을 연결하고 현재 인물을 선택 | 비우면 생성. 기존 ID 재사용 시 설문 DB 불일치 문제가 있음 |
| 인물 텍스트 직접 편집 | 편집된 `persona`를 등록 API가 저장하고 Gemma 인물 설정으로 사용 | 설문 DB에는 편집 전후의 최종 인물 텍스트가 별도 버전으로 저장되지 않음 |
| 사전지식 직접 편집 | 편집된 `knowledge`를 등록 API가 저장하고 Gemma의 지식 근거로 사용 | 설문 JSON 원문은 따로 저장되므로 관리자 설문 화면과 다를 수 있음 |

추론 중 대기 리액션을 만들 때에는 인물 설정과 참조 음성을 사용한다. 등록 사전지식·추억은 리액션 생성에 넣지 않는다.
웹에 별도 `rules` 입력란은 없고, 웹 등록 요청에도 `rules`가 없어 등록 API 기본값인 빈 문자열로 저장한다.
대화 서버의 공통 규칙은 별도로 적용된다.

운영 웹의 사진 경로는 현재 업로드 사진을 Tripo 생성에 직접 전달한다.
이 작업자에는 T포즈 이미지 편집 단계가 연결되어 있지 않으며, 로컬 T포즈 실험·동작 팩 제작 경로와 구별해야 한다.
설문 성격·톤·성별로 Tripo 생성 설정이나 동작을 고르는 처리도 없다. 이 부분은 3D 담당의 연결 범위다.

[등록 제공자](../Server/registration/app.py), [대화 인물 조회](../Server/persona_client.py),

## 4. 수정 전 발견한 불일치와 우선순위

| 우선순위 | 확인한 동작 | 영향과 다음 수정 방향 |
|---|---|---|
| 1 | 인물 텍스트를 직접 편집한 뒤 앞 단계의 관계·톤·추억을 바꿔도 `personaEdited` 때문에 다시 변환하지 않음 | 가상 실행에서 설문은 ‘친구/위로형’, 등록 인물은 ‘할머니/평소 대화형’으로 갈라짐. 재생성 여부와 변경 내용을 확인하고 최종 텍스트·설문 원문의 관계를 기록해야 함 |
| 1 | `/persona` 생성 실패를 화면에 표시한 뒤에도 9단계로 이동하고 등록을 계속할 수 있음 | 실제 인물 대신 초기 친구 예시가 전송되는 경로를 가상 실행에서 재현. 생성 실패 시 이전 예시를 유효한 결과로 취급하지 않도록 해야 함 |
| 1 | 같은 세션 ID의 설문을 다시 저장하면 SQLite 기본키 중복 오류. `_record_and_model`은 오류를 로그에 남기고 반환 | 등록 API의 최신 인물 텍스트와 오래된 설문이 다를 수 있으며 사진 저장·모델 접수도 건너뜀. 신규 등록/수정 정책을 명시하고 부분 실패를 웹에 전달해야 함 |
| 2 | `user_name`이 인물 재답변 예문의 ‘○○이란다/○○이야’에 들어감 | 사용자 이름을 캐릭터 이름처럼 해석할 여지가 있는 예문이 최종 Gemma 프롬프트에도 남음. 이름 없는 예문으로 바꾸거나 발화의 대상을 분명히 해야 함. 실제 답변에서 혼동하는 빈도는 이번에 측정하지 않음 |
| 2 | 관계 템플릿은 모든 갈래에 ‘반말로 말합니다’를 넣으며 미분류 관계는 또래로 처리 | ‘교수님/직장 상사’도 또래로 분류되고 손아래 인물도 반말 지시를 받음. 관계 정보가 들어간다는 것과 원하는 말투를 재현한다는 것은 다름. 존댓말/반말·실제 말투를 별도 설정할 필요가 있음 |
| 3 | 동의 3개를 웹의 단계 이동에서만 검사. 등록 엔드포인트에서는 동의 여부로 처리를 막지 않음 | 현재 동의 값은 서버에서 기록하는 정보다. 입력 검증 책임을 웹/등록 경계에 정리해야 하며, 사진 없는 체험의 사진 동의 요구도 함께 정리해야 함 |
| 3 | 화면은 새 등록 시 이전 인물이 삭제되고 한 명만 보관한다고 안내 | 현재 등록 API는 여러 인물 폴더를 보관하면서 현재 인물을 바꿈. 안내 문구와 실제 보관 동작을 맞춰야 함 |

현재 과제의 핵심은 미사용 문항을 없애는 것보다 **최종 등록된 인물 설정과 설문 기록을 일치시키고,
실패했을 때 다른 인물의 설정이 들어가는 경로를 막는 것**이다.
이 조사 당시에는 수정하지 않았다. 이후 설문 재작성·예시 제거·자동 ID·부분 실패 표시·보관 안내는
[등록 흐름 개선](웹_등록_흐름_개선.md)에서 적용했다. 관계별 말투·이름 예문과 동의 정책의 추가 개선은 남아 있다.
웹·등록 공통 경계 변경은 팀원과 공유할 범위다.

## 5. 검증 근거와 범위

- 서버 배포 소스 14개를 로컬과 대조했다. 원시 해시가 다르던 파일은 원본 해시 또는 내려받은 텍스트의 줄바꿈 정규화로 확인했고 모두 내용이 같았다.
- 가상 설문의 16개 필드를 한 번에 하나씩 바꿨다. 12개는 최종 대화 프롬프트를 바꾸고, 사별·동의 4개는 바꾸지 않았다.
- 실제 인물 변환 함수, 실제 등록 API를 사용하는 프로세스 내 HTTP, 실제 `PersonaClient` 및 프롬프트 조립 함수로 텍스트·참조 음성 해시 전달을 확인했다.
- 설문 DB에 16개 항목이 보존되는 것과 같은 ID 재저장 실패를 로컬 SQLite에서 확인했다.
- 실제 웹 JavaScript를 가상 DOM·가상 HTTP에서 실행하여 정상 16개 항목 전송, 수동 편집 후 불일치, 인물 생성 실패 후 예시 전송, 사진 없이 사진 동의를 요구하는 동작을 확인했다.
- 브라우저 화면·실제 LLM/TTS/화자 분리·Tripo·Unity 체험을 새로 실행한 검사는 아니다. 운영 인물·자료·설정·서비스는 변경하지 않았다.

진단 자료는 Git에서 제외되는 `tools/_work/survey_usage_20260915/`에 있다.

첫 로컬 진단은 등록 모듈의 기본 경로가 샌드박스 밖 사용자 홈을 가리켜 중단됐다.
진단의 `SESSION_DIR`을 작업 폴더 안으로 지정한 후 완료했으며, 이 설정은 운영 환경과 무관하다.
운영 구현 소스는 바꾸지 않아 이미 통과한 전체 회귀 검사·Unity 검사는 반복하지 않았다.
