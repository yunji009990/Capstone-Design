## 1. 전체 구조

```
[Web/]  다시, 봄 등록 도구 (체험장 PC, 포트 8500)
   │  9단계 — 동의 · 목소리 · 기본정보 · 추억 · 마음 · 대화 톤

   │  목소리를 2단계에서 받아 **뒤에서** 화자 분리를 돌린다. 답을 적는 동안

   │  설문 답 → 페르소나·사전지식 자동 생성 (Web/persona.py, 운영자가 고칠 수 있다)
   │  사진 → Tripo 3D 모델 → 완성되면 서버로

   │  세션별 목소리·페르소나 보관. STT → LLM → TTS 를 한 모델이 처리
```

세 화면이 한 주소에 있다.

| 주소 | 무엇 |
|---|---|
| `/` | 등록 (9단계). 접근 코드가 설정돼 있으면 먼저 묻는다 |
| `/after` | 체험 후 안내와 **본인 세션 코드로 자료 폐기** |

`Server/` 는 실 서버(`~/server`)의 **사본**이다. 서버를 고치면 여기에도 반영해 커밋해야
둘이 어긋나지 않는다. 실 서버 자체도 `~/server` 에서 git 으로 관리 중.

## 2. 구성요소

### Unity — `Assets/Scripts/Raon/`

| 파일 | 역할 |
|---|---|
| `RaonVoiceClient.cs` | 마이크 상시 청취 + VAD, 세션 추적, 스트리밍/비스트리밍 두 경로 |
| `RaonPcmStream.cs` | raw PCM 청크를 링 버퍼로 받아 `AudioClip.Create(stream:true)` 로 재생 |
| `RaonVoiceUI.cs` | 상태 점·상태 줄·마이크 목록·대화 초기화. 표시는 아래 부품들이 나눠 맡는다 |
| `OperatorHUD.cs` | 운영자 화면. 체험자 시야를 카메라 하나 더 두어 찍고, 서버·인물·체험 상태를 적는다 |
| `ConversationLog.cs` | 오간 말을 쌓아 스크롤로 되짚어 본다. 위로 올려 읽는 중이면 따라가지 않는다 |
| `ExperienceControl.cs` | 체험 시작·종료. **시작 전에는 듣지 않는다** — 준비 중에 오간 말이 서버로 가면 안 된다 |
| `LevelMeter.cs` | 마이크 세기 막대. 자식 칸의 너비를 늘려 그린다 |
| `SubtitleToggle.cs` | 체험자 말을 받아쓸지. 켜면 기록에 남고 0.5초 늦어진다 |
| `MicDropdownRefresh.cs` | 목록을 펼치는 순간 마이크를 다시 찾는다 |
| `VRMoveControl.cs` | 체험자 자리를 운영자가 옮긴다. MainScene 의 ButtonController 에서 이동만 뽑았다 |
| `Fonts/` | 맑은 고딕 Dynamic TMP 에셋. 프로젝트에 한글 폰트가 없어서 추가 (약 20MB) |

`Assets/Scripts/Persona/PersonaSpawner.cs` 는 `/session/current` 를 지켜보다가 모델이
생기면 `/session/{id}/model.glb` 를 받아 메모리에서 바로 띄운다. 예전에는 Streamlit 이
쓰던 로컬 폴더를 읽었는데, 빌드해서 기기에 넣으면 그 경로가 없어 아무것도 안 떴다.

**운영자 화면은 `Assets/Editor/BuildOperatorHUD.cs` 가 한 번에 짓는다.** 배치를 고치려면
맨 위 `SPLIT`·`ROW` 를 바꾸고 메뉴 `다시봄 > 운영자 화면 다시 짓기` 를 누른다.
일회용 도구이므로 자리가 잡히면 지운다.

**`ProjectSettings` 의 `insecureHttpOption: 2` 가 필수.** 아니면 HTTP 가 조용히 차단된다.

### 서버 — `Server/`

| 엔드포인트 | 용도 |
|---|---|
| `POST /talk` | 전체 버퍼링. 폴백용 |
| `POST /talk_stream` | 프레임 단위 스트리밍. Unity 기본 경로 |
| `POST /session/start` | persona, knowledge, voice(wav), model(glb) 등록 |
| `POST /session/{id}/model` | Meshy 생성이 늦을 때 모델만 나중에 |
| `GET /session/current` | Unity 가 현재 세션 조회 (5초 폴링) |
| `GET /session/{id}/model.glb` | 모델 다운로드 |
| `POST /session/end` | 음성·모델·대화기록 삭제 |
| `POST /chat` | 텍스트로 묻고 텍스트로 답한다. **프롬프트 시험용** — 유니티는 안 쓴다 |
| `/tts` `/stt` `/reset` `/health` | 기존 (`/tts` 는 고장 — 아래 참고) |

`/session/start` 는 `rules` 를 함께 받으면 그것을 공통 규칙으로 쓴다. 안 보내면 서버의
`BASE_RULES` 가 쓰인다. 규칙 자체가 답변 품질을 좌우해서 재배포 없이 바꿔가며 재보려는 것이다.

**기본 음성도 기본 인물도 없다.** 등록되지 않은 세션의 요청은 **409** 로 거절한다.
폴백이 있으면 등록을 잊었을 때 오류가 아니라 엉뚱한 목소리로 답해서 코드 결함처럼 보인다.
Unity 도 `HasSession` 이 false 면 대화를 막고 "인물이 등록되지 않았습니다" 를 띄운다.

세션은 **한 번에 하나만** 보관한다. 새로 등록하면 이전 인물을 지운다 —
세션 ID 를 비우면 시각으로 자동 생성되므로 안 지우면 등록할 때마다 쌓인다.

`modeling_raon.patch` 는 모델 파일에 넣은 프레임 스트리밍 훅. **모델을 다시 받으면 재적용 필요**:

```bash
patch ~/models/AX-K2-Raon-Speech/modeling_raon.py < ~/server/modeling_raon.patch
rm -rf ~/hf_home/modules/transformers_modules/AX_hyphen_K2_hyphen_Raon_hyphen_Speech
```

캐시 삭제가 중요하다. transformers 는 `trust_remote_code` 파일을 `hf_home/modules/` 로
복사해서 쓰므로, 지워야 수정본이 다시 복사된다.

### 웹 — `Web/`

`python -m uvicorn app:app --port 8500` → `http://localhost:8500`

설문 저장과 3D 모델 생성은 `Survey/core/` 의 것을 그대로 쓴다. 스키마와 작업 추적이 이미
있어서 다시 만들 이유가 없다. `Survey/` 는 이제 **화면 없는 라이브러리**다 — 예전 Streamlit
앱은 `Web/` 이 같은 일을 다 하게 되면서 지웠다.
`Survey/data/` 에 참여자 사진·음성·설문이 쌓이며 저장소에는 올라가지 않는다.

`Web/persona.py` 가 설문 답을 페르소나·사전지식으로 바꾼다. 관계 낱말로 말투 갈래를
찾아 종결어미를 나열하고 대화 예시 다섯 쌍을 만든다. 근거는
[`페르소나_작성규격.md`](페르소나_작성규격.md).

오른쪽 위 **테스트** 단추는 시험용 값 한 벌을 채운다. 제출 전에 뺄 것.

#### 순서 — 목소리를 맨 앞에서 받는다

2단계에서 **다음**을 누르는 것이 곧 화자 분리 시작이다. 따로 시작 단추는 없다.
분리는 스레드로 돌고 화면은 3단계로 넘어가므로, 기본정보·추억·마음·대화 톤을
적는 동안 뒤에서 끝난다. 7단계에 닿으면 결과가 도착해 있다.

- 되짚어 와서 다음을 다시 눌러도 새로 돌리지 않는다(`start()` 가 `job` 을 본다).
  파일이나 화자 수를 **바꿨을 때만** 초기화한다
- 실패는 7단계에서야 드러난다. `jobErr` 로 "도는 중"과 "실패"를 갈라 말하고,
  같은 파일로 그 자리에서 다시 거는 단추를 둔다
- 화자 수는 드롭다운이다. **한 명 (분리 안 함)** 을 고르면 분리기를 건너뛰고
  파일을 그대로 참조로 쓴다 — 예전 "오디오 직접 지정" 탭이 이것이다

#### 화자 분리 엔진

새로 만들지 않고 `Desktop/capstone/voice_clone_studio` 의 **NeMo MSDD 엔진을
서브프로세스로 호출**한다(`VCS_DIR` 로 경로 변경 가능). 그쪽 서버는 띄우지 않는다.

CPU 전용(`torch 2.13.0+cpu`)이다. **실측 63~99초**(3~10MB, 6분 24초 오디오가 66초).
오디오 길이의 1/6쯤이다. GPU 로 옮기면 이걸 아끼는데, 위 순서 바꾸기로 대기가
이미 사라져서 **지금은 GPU 로 가지 않기로 했다.**

다만 **엔진이 저장소 밖에 있는 것은 그대로 문제다.** 다른 PC 에서 받으면 화자 분리가
아예 안 돈다. 공모전에 코드를 낸다면 받자마자 반쪽이 된다. 무거운 것은 `nemo_env`
가상환경이지 코드가 아니므로, 코드만 들이고 환경 만드는 법을 적어두면 된다.

## 3. 지연 최적화 — 4.5초 → 1.5~2.2초

첫 소리까지 기준. 순서대로 적용했다.

| 작업 | 효과 |
|---|---|
| `RAON_VERIFY=0` 합성 검증 끄기 | −0.5초 |
| `torch.compile(code_predictor)` | −0.66초 |
| 페르소나로 답변 길이 통제 | 세션이 길어지면 −2초 이상 |
| `show_heard=0` (인식을 응답 뒤로) | −0.5초 |
| **프레임 단위 스트리밍** | 첫 소리를 답변 길이와 분리 |

### 병목의 성질

GPU 사용률 40%, 전력 150W/600W → **커널 런치 오버헤드 병목**이지 계산 병목이 아니다.
양자화·Flash Attention 은 무의미하다.

오디오는 12.5Hz 프레임이고 프레임마다 코드 그룹 16개를 순차 예측한다. 즉 아주 작은
모델(5층/1024)을 초당 200번 부른다. 커널이 너무 빨리 끝나서 GPU 가 CPU 를 기다린다.

### 합성 비용 모델 (실측)

```
합성 시간 ≈ 1.0초(호출당 고정비) + 오디오길이 / 1.8
```

생성은 실시간의 1.8배로 빠르지만 **호출마다 1.0초의 시동 비용**이 붙는다.
그래서 2.25초보다 짧은 청크는 재생 시간보다 합성 시간이 길어져 손해다.
문장 단위로 쪼개면 문장마다 이 비용을 내므로 공백이 생긴다 —
프레임 단위 스트리밍으로 간 이유가 이것이다.

## 4. 반드시 알아야 할 함정

이번 세션에서 시간을 크게 잡아먹은 것들. **다시 밟지 말 것.**

### `torch.compile(mode="reduce-overhead")` 는 세그폴트를 낸다

파이썬 예외가 아니라 네이티브 크래시라 로그에 아무것도 안 남고 서버가 조용히 사라진다.
CUDA 그래프는 transformers 캐시의 `cumulative_length.add_()` in-place 변형 때문에
어차피 비활성화되므로, `mode` 를 빼도 잃는 게 없다.

### `./start.sh` 를 포그라운드 명령과 `&&` 로 묶지 말 것

```bash
./start.sh && tail -f server.log     # ← Ctrl-C 가 서버까지 죽인다
```

`nohup` 은 SIGHUP 만 막고 SIGINT 는 못 막는다. 두 명령을 따로 실행할 것.

### Unity 인스펙터 직렬화 값이 C# 기본값을 덮어쓴다

코드에서 `public float x = 1.0f` 로 바꿔도, 씬에 이미 저장된 값이 있으면 무시된다.
Play 모드 중에 인스펙터에서 바꾼 값도 종료 시 되돌아간다.
**확실히 하려면 씬 파일에 직렬화하고 저장할 것.** 이걸 몰라서 프리버퍼 값을
세 번 바꾸며 헛테스트했다.

### Unity `AudioClip` 은 `Play()` 직후 약 0.86초를 한꺼번에 당겨간다

스트리밍 재생에서 프리버퍼가 그보다 작으면 시작 직후 반드시 끊긴다.
현재 `streamPrebufferSec = 1.2`. 부족분이 프리버퍼와 무관하게 항상 0.56초로
일정했던 게 단서였다.

### AspectRatioFitter 는 앵커를 무시하고 "부모"에 맞춘다

우측 상단에 놓으려고 앵커를 잡아 뒀는데 화면 전체를 덮었다. 부모가 화면 전체였기
때문이다. **놓일 자리만큼의 빈 칸으로 한 번 감싸야** 그 안에서만 맞춘다.

### Image 의 Filled 는 스프라이트가 있어야 동작한다

스프라이트 없이 `fillAmount` 를 넣으면 꽉 찬 네모 그대로라 색만 바뀌고 길이가 안 변한다.
유니티 기본 스프라이트는 모서리가 둥글어서 잘린 자리가 일그러진다 —
**자식 칸의 너비를 직접 늘리는 편이 낫다**(`LevelMeter`).

### 씬을 옮기면 다른 씬을 가리키던 참조가 끊긴다

`RaonVoiceUI.client` 와 `PersonaSpawner.voiceClient` 가 그렇게 끊겨
`NullReferenceException` 을 세 번 냈다. 옮긴 뒤에는 참조를 하나씩 확인할 것.

### `manage_scene save` 에 씬 이름을 주면 그 이름의 파일을 새로 만든다

활성 씬을 그 이름으로 저장해 버려서 Scene_1 이 엉뚱한 경로에 복사됐다.
**활성 씬을 먼저 바꾸고 이름 없이 저장할 것.**

### 윈도우에서 자식 프로세스는 콘솔이 아니라 **로케일**로 인코딩한다

화자 분리 진행 문구의 한글이 전부 깨졌다. `Web/app.py` 는 `encoding="utf-8"` 로
읽는데, 파이썬은 출력이 파이프일 때 `locale.getpreferredencoding()` 을 쓴다 —
이 PC 는 **cp949**다. 터미널이 UTF-8 이어도 소용없다.

주의할 것이 둘이다.

- **자기 셸에서 재현되지 않을 수 있다.** `PYTHONIOENCODING` 이 껴 있는 환경에서
  돌리면 멀쩡히 나온다. 사용자 터미널과 같은 조건(그 변수를 지운 환경)으로 볼 것.
- **`PYTHONIOENCODING` 만 넘기면 더 나빠진다.** 화자 분리는 세 겹으로 돈다
  (`app.py` → `extract_runner` → `nemo_env` 의 `nemo_diarize`). 가운데 단은
  손자를 `text=True` 로만 읽어 로케일 인코딩을 쓰므로, 손자만 UTF-8 이 되면
  거기서 `UnicodeDecodeError` 로 **터진다**. 실측에서 중간단 출력이 통째로 끊겼다.

그래서 `_utf8_env()` 가 `PYTHONUTF8=1` 을 함께 넘겨 로케일 자체를 UTF-8 로 바꾼다.
새로 서브프로세스를 띄울 때는 이 함수를 쓸 것.

### 화면이 둘로 갈라지면 사실이 한쪽에만 남는다

등록이 끝나면 `#main` 이 통째로 숨고 `#done` 이 뜬다. 모델 진행 상황은 `#modelinfo` 에
쓰고 있었는데 그게 `#main` 안이라, 유가족은 못 보고 **끝 화면은 사진을 냈다는 이유만으로
늘 "빚고 있습니다"** 라고 말했다. 키가 없어 건너뛴 경우에도 그랬다.

사별한 사람에게 오지 않을 것을 기다리게 하는 것은 그냥 버그가 아니다. 화면을 가를 때는
**바뀌는 사실이 양쪽에 다 닿는지** 확인할 것. `watchModel` 이 이제 둘 다 고쳐 쓴다.

### 세션 페르소나는 전역 설정을 통째로 대체한다

그래서 서버가 `BASE_RULES`(이모지 금지, 길이, 비서 말투 금지)를 **항상 앞에 붙인다**.
웹이 매번 기술 제약을 적어 보내게 하면 반드시 빠뜨린다.
빠뜨렸을 때 모델이 마크다운 목록과 되묻기를 뱉으며 텍스트 생성에만 9.8초를 썼다.

### 대화 예시가 말투를 결정한다 — 규칙만으로는 안 된다

같은 인물, 같은 목소리로 통제 실험한 결과:

| | 규칙만 (120자) | 예시 4쌍 포함 (722자) |
|---|---|---|
| "존댓말 쓰지 마세요" 준수 | ✗ | ✓ |
| 캐릭터 유지 | ✗ 불특정 인물 | ✓ |

**웹이 설문 결과로 페르소나를 생성할 때 반드시 대화 예시를 만들어야 한다.**
성격을 나열하는 것보다 어려운 요구라 미리 설계에 반영할 것.

예시의 부작용도 있다 — 문장을 그대로 베낀다. 페르소나에
"예시는 말투 참고용이지 그대로 쓰지 말 것"을 넣어 완화했다.

### 억양은 `tts()` 로 복제되지 않는다 — 참조 구성이 전부다

`tts()` 는 참조 음성을 **화자 임베딩 토큰 하나로 압축**해 넘긴다. 담기는 건 **음색뿐**이고
억양·속도·리듬은 전달되지 않아 모델의 기본 낭독체가 그 자리를 채운다.
`tts_continuation()` 은 참조를 **"방금 생성한 출력"으로 문맥에 깔고 그 뒤를 잇게** 한다.
`RAON_CONT=1` 로 전환한다.

**참조 음성의 조건이 까다롭다.** 실측:

| 참조 | 결과 |
|---|---|
| 12초, 조각 3개 이어붙임 | 동작하지만 억양은 참조(낭독체) 그대로 |
| 6.3초 | 깨짐 — 같은 문장에 0초 / 8.6초 / 4.3초 |
| 13.7초, 쉼 많고 SNR 17.8dB | 깨짐 — 짧은 답변에 14초 오디오 |
| **연속 녹음 2개(사용자 준비)** | ✅ 억양·말투 복제됨 |

**참조에 없는 말투는 나오지 않는다.** 낭독조를 넣으면 낭독조가 나온다.
화자 분리가 만드는 `ref.wav`(조각 이어붙임)는 그대로 쓴다 — 조각이라서 문제가 되진
않는다는 것을 실측으로 확인했다. 다만 어떤 소리가 넘어가는지 볼 수 없어서
**`오디오 직접 지정`** 경로를 따로 두었다.

비용은 **첫 소리 +0.5~0.9초**(참조 프리필). 그리고 `ref_text`(참조 전사)가 필요한데
없으면 합성마다 STT 를 다시 도므로 `REF_TEXT` 에 세션당 1회만 캐시한다.

프레임 스트리밍 훅은 **수정 없이 그대로 동작한다.** `generate()` 가 프리필 프레임을
`audio_codes` 에 남기지 않아 `_raon_sent = [0]` 이 참조를 흘리지 않는다(실측 확인).

### 효과가 없었던 것

- **`voice.wav` 앞뒤 무음 트림** — 생성 오디오의 무음은 참조 음성과 무관했다. 효과 0.
- **양자화 / Flash Attention** — 오버헤드 병목이라 무의미.

### 유용한 사실

- `load_audio` 에 캐시가 없다 → **`voice.wav` 를 바꾸면 재시작 없이 즉시 반영**된다.
  명세서의 "재시작 필요"는 사실과 다르다.
- 이 모델은 `delays = None` → `max_delay = 0`. 지연 코드 패턴이 없어 스트리밍 선행 대기가 0이다.

### VRAM — 새는 게 아니라 상한이 좁았던 것이다

2026-08-02 에 `/chat` 과 `/tts` 가 500 을 내기 시작했다(`/talk` 과 `/stt` 는 멀쩡했다).
큰 할당이 필요한 호출만 실패하는 상태였고, 원인은 **`RAON_MEM_FRACTION=0.60`** 이었다.

```
GPU 총량                97887 MiB = 95.6GB   (nvidia-smi, 이 서버는 우리가 혼자 쓴다)
0.60 상한                          57.4GB
실제 최고점            48~51GB (작업이 섞이면 56GB)   ← 상한 바로 아래
```

**누수가 아니라는 것은 확인했다.** 같은 20턴 대화를 세 번 반복해 최고점을 비교하니
48.3 / 48.8 / 48.7 로 평평했다. `/talk` 8턴도 48.4 였다. 0.70(66.9GB)으로 올려
여유 18GB 를 뒀다.

> **`torch.cuda.memory_allocated()` 를 추세로 읽지 말 것.** 그 순간 살아있는 텐서라
> 직전 호출이 무엇이었냐에 따라 45~51GB 를 오간다. 6000자 프롬프트가 3000자보다
> 낮게 나오기도 한다. 한 번 찍고 "턴당 몇 MB 씩 샌다"고 적었다가 두 번 틀렸다.
> **같은 작업을 반복해 최고점을 비교하는 것**이 맞는 방법이다.

모델 가중치 39.8GB 위에 작업 공간 8~9GB 가 얹힌다. 21B MoE 에 음성 인코더·코덱까지
붙은 모델이라 이상한 값은 아니다(KV 캐시만 따지면 200MB 지만, 활성화 버퍼 · MoE 라우팅 ·
오디오 코덱 · `torch.compile` 작업 공간이 모두 더해진다).

셋을 먼저 갖춰야 한다. **GPU 도 접었다** — 아끼는 것이 1분 남짓인데 순서 바꾸기로
그 1분이 이미 사라졌다.

**꼬리 반복은 프롬프트로 두 번 실패했다** — 금지형("반복하지 마세요")도 지시형

**남은 것**

1. **격려 클리셰** — `넌 충분히 잘할 거야` `넌 항상 잘 해왔잖아` 가 힘든 얘기에 붙는다.
   20턴당 3.5. 페르소나에 "판단은 상대가 물을 때만"을 넣었더니 **오히려 늘었다**.
   남은 방법은 **대화 예시에 "격려하지 않는 위로" 쌍을 여러 개 넣는 것.** 예시가
   어투를 잡는다는 건 확인됐다(§아래) — 아직 안 해봤다
2. **길이초과** — 20턴당 8.8. 목표 5에 못 미친다
3. **맥락 이탈** — `준비는 그럭저럭 했는데 잘 될지 모르겠어` → `그럼 뭐 하고 있었어?`
   어느 지표에도 안 잡힌다. 사람이 읽어야 한다
4. **대화 예시를 실제 메시지 턴으로** — 지금은 시스템 프롬프트 안의 텍스트다.

   (`Raon모델_분석.md` §6.8)

**대화 예시는 반드시 넣어야 한다.** 예시 248자만 빼고 재봤더니 설교조(일반론·잠언)가
0.5 → 2.0 으로 늘었다 — `회사에서 깨지는 건 누구나 겪는 일이야. 중요한 건 그 경험에서
뭘 배우느냐지.` 친구가 아니라 자기계발서가 된다. 반면 **반말 유지에는 예시가 필요 없다**
(양쪽 다 존댓말 0). `[말투]` 에 종결어미를 나열하면 그것으로 충분하다.
**예시가 하는 일은 말투 유지가 아니라 어투 유지다.**

### 3순위 — 오디오 문제

2026-08-01 에 **여덟 가지를 시험했고 하나만 남았다.** 상세는
[`Raon모델_분석.md`](Raon모델_분석.md) §6.5·§6.6.

#### 지지직 (고주파 아티팩트) — 원인 미특정, 실용적으로는 참조를 가려 쓸 것

참조가 결정한다(직접 녹음 30/30 없음, 유튜버 녹음 40/40 있음). **참조의 대역
분포가 관여하는 것은 양방향으로 확인**했으나(스펙트럼을 맞바꾸면 없어지고 생긴다)
되돌려도 완치가 안 되고 떨림이 새로 생긴다.

**목소리·마이크 거리는 무관하다.** 같은 사람이 같은 장비로 평소 톤·방송 톤·높은
목소리·먼 거리 네 가지로 녹음했는데 전부 깨끗했다. 사람이 만들 수 있는 저역 범위는
58.6% 까지이고 문제 참조는 4~6% 다 — **방송용 후처리로만 나오는 값**이다.

**유튜브 클립이라고 못 쓰는 게 아니다.** 채널 3곳의 클립 4개 중 2개가 문제없었다
(저역 38.2%·59.1%). 문제 채널만 두 클립 모두 저역 4~6% 로 재현된다.

→ **1~4kHz 비율이 참조를 미리 거르는 지표다.** `Web/app.py` 에 **25% 이상 경고**로
넣었다(`MID_SAFE`).

처음에는 저역 비율(0~300Hz) 30% 미만으로 걸렀는데 **그건 틀렸다.** 성인·근접 녹음
12개에만 맞는 기준이었다. 아동 검사 세션(교실 원거리 마이크)에서 저역 26.7% 짜리가
가장 좋게 나왔고, 저역이 같은데 결과가 갈리는 쌍이 나왔다(7.1% 정상 / 5.8% 심함).
가림 청취 9조건 전향적 검증에서 판정 가능한 8개 중 **새 기준 7 · 옛 기준 3** 적중.
상세는 `Raon모델_분석.md` §6.7.

**하지 말 것** — 전부 시험하고 기각:
저역통과 · 잡음 제거 · Demucs · 참조 자르기 · 참조 길이 조정 · 쉼 넣기 ·
RAS 끄기 · `temperature` 낮추기 · `top_k` 조이기.
**SNR 로는 못 거른다** (35dB 가 통과하면서 실패하고, 59dB 로 올려도 그대로다).

남은 길: **화자 3~4명 녹음을 더 모아 경계 찾기.** 지금 표본은 화자 2명이라
"유튜버 녹음이라서"인지 "그 목소리라서"인지 못 가린다.

#### 꼬리 무음 — 해결. `Web/app.py` 에 구현했다

문장을 다 말하고도 **3~8초 무음을 더 생성**하다 16초 상한에 걸려 끝나던 문제.
원인은 **참조의 쉼 비율**이었다. 같은 참조에서 쉼만 잘라 인과를 확인했다 —
유튜브 클립 22%→0% 는 꼬리 7.4초→0.5초에 정상 1/5→5/5, 직접 녹음 27.6%→6% 는
8.4초→0.6초에 0/5→5/5. 전사는 원본과 같았다.

`_cut_silence()` 로 등록 때 자동 처리한다. **쉼 20% 초과일 때만** 건다 — 18% 짜리를
잘랐더니 얻은 것 없이 지지직만 올랐다(0.24→0.76).

남은 보강(급하지 않음):

1. **`continuation_silence_frames`** — `task_params` 에 `2` 로 들어있다. 안 건드렸다
2. **꼬리 무음 잘라내기** — 서버가 반환하기 전 후처리. 참조 쪽으로 대부분 잡혔다
3. **프레임 훅에서 무음이 이어지면 조기 종료** — 지연까지 줄지만 손댈 곳이 깊다

#### 별개로 고칠 것

**RAS 재추첨이 `top_k`/`top_p` 를 건너뛴다** — `logits=processed_logits` 한 단어.
지지직의 원인은 아니지만(꺼도 그대로였다) 코드상 분명한 결함이다.

## 8. 시험 도구

```
RAON_EVAL_VOICE=<참조.wav> python tools/prompt_eval.py <변형> -n 4
```

20턴 대화를 끊지 않고 걸어 답변 글을 15개 지표로 채점한다. 앞에서 사실을 심고 뒤에서
되물어 회상까지 본다. 프롬프트 변형은 `tools/prompts/<이름>.{persona,knowledge,rules}.md`.

- **소리는 안 잰다.** 지지직·억양·속도는 귀로 들어야 한다
- **최소 4회차.** 같은 설정을 다섯 번 돌렸더니 4, 4, 8, 17, 6 이 나왔다
- 돌리면 서버의 등록 인물이 `eval` 로 교체된다. 시연 전에 웹에서 다시 등록할 것
- [`RAON_UNITY_구현명세.md`](RAON_UNITY_구현명세.md) — 서버 팀이 준 원본 명세. 서버 운영법, 트러블슈팅
- [`../Server/README.md`](../Server/README.md) — 서버 복구 절차, 환경변수
- [`../Web/README.md`](../Web/README.md) — 등록 도구 사용법
