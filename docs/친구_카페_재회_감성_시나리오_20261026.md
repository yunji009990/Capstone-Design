# 친구와 카페에서 함께하던 시간을 떠올리는 시연 시나리오

작성일: 2026-10-26. 이야기 이름은 **네 것도 시켰어**다.
발표는5분이며 시연 영상은40초~1분이다. 시연자 본인의 참조 음성을 사용하는 가상의 또래 친구와 재회한다.
영상은 약50초를 기준으로 VR 돌입5초·NPC 착석5초·대화 약39~40초·종료 페이드로 구성한다.
실제 발화·말끝 판정·LLM과 음성 응답 대기·쉼을 포함한 분량은 리허설에서 확인한다.

친구가 힘들 때마다 카페로 불러내 함께 앉아 있던 평범한 행동이 이야기의 중심이다.
친구가 떠난 뒤 혼자 그 카페에 가 본 체험자는, 함께 앉아 있던 시간이 자기에게 어떤 의미였는지 처음 말한다.
NPC는 평소 친구의 말투로 받아 주며, 마지막에는 현재의 마주 앉음 자체가 답이 된다.

## 영상 시간 배분

| 영상의 목표 구간 | 내용 |
|---|---|
| 0~5초 | VR 돌입 |
| 5~10초 | NPC가 의자에 접근해 자리에 앉는 장면 |
| 10~22초 | 첫 번째 왕복. “네 것도 시켰어”라는 과거 카페 습관 |
| 22~38초 | 두 번째 왕복. 혼자 다시 찾은 카페와 빈자리 |
| 38~49초 | 세 번째 왕복. 지금 함께 앉아 있자는 말 |
| 49~50초 | 답변 음성이 끝난 뒤 기존0.8초 종료 페이드 |

이 표는 편집용 목표 시간이며 실측한 재생 시간이 아니다.
착석5초는 영상에서 선택할 구간이다. 캐릭터의 전체 입장 경로와 인사·회전을5초로 압축하는 기능 변경은 하지 않는다.
영상 전체가1분 안에 들어가도록 남은 약10초를 리허설 후 조절 여유로 둔다.

## 인물과 만남

준호와 민수는 동갑인 대학 친구다. 준호는 이미 세상을 떠났으며 민수는 이번 만남에서 준호와 다시 마주 앉는다.
두 사람은 시연용 가상 인물이다. 대사는 시연자가 직접 읽어 보고 자기 목소리에 편한 단어로 조절한다.

준호는 평소 실없는 이야기를 하며 편하게 지내던 친구다. 민수가 진지해지면 장난을 멈추고 짧게 듣는다.
반말을 쓰되 사투리·거친 표현·말버릇 반복을 강제하지 않는다.

생전 준호는 민수가 힘든 일이 있어 연락하면 학교 앞 카페로 불러냈다.
먼저 가서 음료를 주문해 두고 “나와. 네 것도 시켰어.”라고 말하곤 했다.
둘은 창가 자리에 마주 앉아 별 해결책 없이 이런저런 이야기를 하다가 늦게 헤어지곤 했다.
준호도 민수와 그렇게 함께 있는 시간을 좋아했다.

현재 카페는 이번 재회의 장소이며 과거의 학교 앞 카페와 구분한다.
준호가 떠난 뒤 이곳에서 기다렸거나, 지금 민수의 음료를 주문했다는 설정은 넣지 않는다.

## 시연 대화

대화는 세 번 왕복한다. 아래는 실제 LLM 답변의 방향을 준비하기 위한 예시다.
착석 후 입력이 열리면 민수가 먼저 말하며, 실제 생성된 답변에 맞춰 이어 간다.

### 1 함께하던 카페의 기억

> 민수: “나와. 네 것도 시켰어.” 너 맨날 그랬잖아.
>
> 준호: 그랬지. 늘 창가 자리였잖아.

친구의 평범했던 한마디와 장소를 짧게 공유한다. 현재 주문을 했다는 뜻이 되지 않도록 과거의 말을 인용한다.

### 2 친구가 없던 빈자리

> 민수: 너 없고 나서 혼자 가 봤어. 커피는 똑같은데, 네가 없더라.
>
> 준호: 혼자 갔었구나. 나도 너랑 있는 게 좋았어.

준호가 지금 처음 들은 일을 먼저 받아 주고, 함께 있던 시간이 좋았다는 생전의 마음을 짧게 전한다.
민수의 “네가 없더라” 앞뒤에는 짧은 쉼을 둘 수 있다.

### 3 지금 함께 앉아 있는 순간

> 민수: 오늘은 그냥 좀 같이 앉아 있자.
>
> 준호: 그래. 말 안 해도 돼.

답변 음성이 끝나면 기존 종료 버튼과0.8초 페이드아웃으로 마친다.
현재 만남의 짧은 수용으로 끝내며 별도 작별 인사나 이후 만남의 약속은 추가하지 않는다.

## 친구 설정에 넣을 정보

| 준호가 미리 아는 과거의 사실 | 쓰임 |
|---|---|
| 두 사람은 동갑인 대학 친구다. | 관계와 편한 반말의 기준 |
| 생전 두 사람은 학교 앞 카페 창가에 자주 마주 앉았다. | 익숙한 장소와 자리의 기억 |
| 민수가 힘든 일이 있어 연락하면 준호가 그 카페로 불러내곤 했다. | 연락과 만남의 맥락 |
| 준호는 먼저 음료를 주문해 두고 “나와. 네 것도 시켰어.”라고 말하곤 했다. | 과거의 구체적인 말과 행동 |
| 둘은 조언이나 해결책 없이 실없는 이야기를 하다가 늦게 헤어지곤 했다. | 평범한 친구 대화와 작은 농담 |
| 준호도 민수와 카페에 함께 앉아 이야기하는 시간을 좋아했다. | 고마움을 받는 현재 반응의 근거 |

준호가 떠난 뒤 민수가 혼자 카페에 갔던 일과 그때 느낀 빈자리는 두 번째 왕복에서 처음 전한다.
못 전한 감사나 커피보다 함께할 사람이 필요했다는 생각도, 사용자가 실제로 말한 내용만 알게 한다.
이 정보는 친구의 사전 기억이나 `news`·`heart.unsaid_words`에 미리 넣지 않는다.
사망 원인·날짜·현재 민수의 생활이나 카페 이름·음료 종류·금액은 정하지 않는다.

생전 카페 습관은 과거의 사실로 분명히 전달한다. “오늘도 네 것 시켜 놨어”, “여기서 기다렸어”,
“네가 혼자 오는 걸 봤어” 같은 답변은 이 설정과 맞지 않는다.
선택한 친구 설정으로 리허설할 때는 이 카페 기억을 중심으로 프리셋을 구성한다.

## 촬영과 대화 확인

맞은편 빈 의자와 캐릭터 착석을 같은 구도로 연결하고, 상반신과 카페 공간이 함께 보이는 거리에서 대화한다.
처음의 편한 속도에서 이야기를 이어 가되,두 번째 왕복에서는 잠깐 멈추거나 짧게 말해도 된다.
눈물 연기나 슬픈 배경음 없이도 말의 의미와 실제 음성이 전달되는지 먼저 확인한다.
컵을 건네거나 마시는 동작, 특정 표정·끄덕임은 필수 장면으로 지정하지 않는다.

리허설에서는 다음을 확인한다.

- 두 번째 왕복의 혼자 카페에 갔던 일을 준호가 처음 듣는 정보로 받아들이는가.
- 과거의 음료 주문을 현재 주문이나 떠난 뒤의 기다림으로 바꾸지 않는가.
- 진지한 말에 장난을 멈추고, 떠난 뒤 지켜봤다거나 늘 곁에 있었다는 말을 덧붙이지 않는가.
- 사용자가 준비한 문장과 다르게 말하거나 가벼운 화제로 돌아가도 그 말에 맞춰 반응하는가.
- 마지막에 지금 함께 앉아 있자는 뜻을 받아들이고 조언·작별·미래 약속으로 길어지지 않는가.

첫 입력부터 마지막 NPC 음성 종료까지 실제 시간을 잰다. 시간 초과 시 사용자 발화와 답변 길이를 먼저 줄이고,
실제 응답 대기를 편집으로 줄였다면 영상에 그 사실을 표시한다. 목표 구간에 맞추기 위해 음성이 끝나기 전에 종료하지 않는다.

## 검토와 적용 상태

사용자의 감정 강화 요청과 발표5분·영상40초~1분 조건을 반영해 Claude Code와 추가 검토했다.
카페에서 함께하던 시간을 중심으로 한 이 안을 추천했고,3번 왕복으로 압축하면서 새 소식을 먼저 받아 주는 응답을 보강했다.
선택 이유·시간 조건 검토와 원문은 Git 제외 `tools/_work/friend_scenario_20261026/round3.*`, `round4.*`에 보관한다.
### 웹에서 사용하기

웹을 새로고침한 뒤 **테스트 → 친구 시연 · 카페 재회**를 선택한다.
`friend_cafe_demo` 프리셋이 관계·생전 카페 기억·짧은 반말과 반응 선호를 설문에 채운다.
기존 할머니·친구 항목은 그대로다. 테스트 메뉴는 프리셋 목록을 읽어 새 버튼을 자동으로 표시한다.

선택하면 이전 사진·음성 선택이 비워진다. 시연자 본인의 참조 음성과 필요한 사진을2~3단계에서 다시 고르고,
인물 확인을 거쳐 등록해야 새 설정으로 체험한다. 프리셋 버튼 자체는 기존 등록 인물을 바꾸거나 등록을 제출하지 않는다.
지금 처음 말할 소식·못 전한 마음과 사망 경위·날짜는 미리 채우지 않는다.

사진을 포함한 새 등록은 새 모델 제작도 접수한다. 현재 니트 몸체는 기존 서버 모델과 일치할 때만 쓰는 Editor 로컬 시험본이므로
새 완성 모델에는 자동으로 이어지지 않는다. 같은 니트 외관으로 촬영하려면 새 얼굴과의 조합·로컬 연결을 다시 확인한다.
10월26일 연결 검사에서는 당시 현재 모델의 니트 몸체·52개 본·유효 Humanoid·이동 후 착석을 확인했으며 새 등록은 하지 않았다.
검사 근거는 Git 제외 `tools/_work/body_link_check_20261026/result.json`이다.

프롬프트는 기존 설문 변환기의 인물·사전지식·추가 규칙으로 만든다. 추가 선호에는 짧은 한두 문장,
추억 하나를 활용하는 답변, 외로움을 먼저 받아 주고 함께하던 시간이 좋았다는 반응,
함께 앉아 있자는 말에 대한 짧은 동의를 담았다. 선택된 인물의 규칙이며 공통 LLM 프롬프트·모델은 유지한다.
AI 전달 자유 텍스트는560자로800자 제한 안에 있다.

### 적용과 실제 검사

10월26일 운영 웹의 `Web/static/presets_v2.json` 하나를 백업·원자 교체했다.
배포 전후 해시와 HTTP 응답의 일치·대화 API의 `ready`를 확인했다. 서비스 재시작·기존 등록 인물 수정은 없었다.

- 전체 기본 검사: **583개 통과·건너뜀0개**.
  `tools/_work/checks/20261026T050936Z-all-4c084d39/report.json`.

  사망 경위·날짜 혼입 방지, 운영 `/persona` 변환과 로컬 변환의 일치 등11개 항목을 확인했다.
- 실제 운영 Gemma: 웹 화면의 실제 설문에서 만든 프롬프트를 정상 경로·동일 대화 기록으로16턴 검사했다.
  시연 대본은seed3회·9턴이며 첫 답변36~40자·외로움 반응38~43자·마지막 동의8~23자였다.
  시연9턴의 추가 질문은0개였다. 초기 근황 모름→전달 후 회상, 미설정 메뉴 모름,
  기다림 부인·떠난 뒤 생활을 만들지 않는 반응과 가벼운 잡담 전환도 확인했다.
  자유 질문의 일부에는 되묻기가 있었으므로 모든 답변의 질문을 금지한 것으로 설명하지 않는다.

검사는 실제 STT·TTS·참조 음성 재생·Unity·HMD·40초 대화 실측을 포함하지 않는다.
예상 대사와 정확히 같은 문장을 보장하지 않으며, 실제 음성을 붙인 리허설로 말맛과 영상 길이를 확인한다.

근거는 Git 제외 `tools/_work/friend_cafe_demo_20261026/`의 `deployment.json`, `browser.json`,
