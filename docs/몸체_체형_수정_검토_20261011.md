# 고정 몸체 구조와 체형 수정 검토

최신 작업일: 2026-10-13. 최초 구조 분석일: 2026-10-11. 분석 기준 커밋: `11e0c94e` (`main`).

사용자 요청으로 Blender MCP에 불러온 고정 몸체, 원본 `.blend`, FBX와 머리 결합 코드를 비교했다.
최초 분석 당시에는 원본 모델 자산과 운영 코드를 수정하지 않았다. 손 작업 결과는20장, 리깅 표시와 추가 굽힘 확인은21장을 따른다.
18~19장은 사용자가 외형을 지적한 이전 사본과 그 재검토 기록이다.
Unity 기본 몸체 반영은22장, 서버·현재 등록 모델 반영은23장, Blender 체형 조절 사본은24장을 따른다.
Unity Inspector 체형 조절과 현재 캐릭터의 체형 키 후속 반영은25장이 최신 기준이다.
각 장의 검사·적용 범위와 당시 기록을 구분한다.
체형 변형 검사는 별도 Blender 백그라운드 프로세스에서
검사 사본과 단순 구체 머리를 사용했다. 서버·참여자 자료·등록 세션은 사용하지 않았다.

## 1. 판단

**기존 몸체에 체형 조절용 Shape Key를 추가할 수 있다.**
원본 `Human.blend`는 대부분 사각형 면이며 좌우 대칭이 맞아, 부위별 변형을 작성하기에 적합하다.
원본에서 만든 작은 상체 변형을 현재 GLB에 옮기고 기존 머리 결합 스크립트를 실행했을 때,
변형 키와 60개 본 스킨이 결과 GLB에 보존되는 것을 확인했다.

첫 구현은 **상체 폭·두께, 허리/배, 팔·다리 굵기**의 소수 변형 키를 권장한다.
목·옷깃·손발 끝과 관절 위치를 고정하는 범위부터 시작한다.
머리 크기와 목 연결 위치는 별도로 맞추며, 키와 팔다리 길이 변경은 골격·동작 검증을 추가한다.

Shape Key는 같은 메시의 정점 위치를 여러 형태로 기록하고 가중치로 섞는 방식이다.
형태를 작성할 때 정점을 추가하거나 삭제하지 않는 흐름이 기본이다.
[Blender 4.5 Shape Key 소개](https://docs.blender.org/manual/en/4.5/animation/shape_keys/introduction.html),
[작성 절차](https://docs.blender.org/manual/en/4.5/animation/shape_keys/workflow.html).

원본 리그에는 IK, Copy Rotation, Stretch To 등 편집용 제약이 있다. 출력 리그에는 그 제약이 없다.
344개 본을 그대로 게임용 GLB에 추가할 필요는 없다. 기존 게임용 본 이름과 바인드 관계를 유지한다.

원본 사각형 면의 삼각형 환산 수가 GLB의 35,134개와 일치한다.
GLB의 정점 증가는 UV/노멀 경계에서 정점을 분리하는 출력 구조와 맞는다.
현재 GLB를 원본 좌표에 대응시킨 검사에서 최대 오차는 약 **0.96μm**였다.
원본 사각형 메시에서 작성한 변형을 GLB의 대응 정점에 전달하는 방법을 사본에서 확인했다.

몸체 단독의 기본 좌표 범위는 약 폭 1.761m, 깊이 0.385m, 높이 1.900m다.
이는 팔을 펼친 몸체 자산 치수다. 최종 캐릭터 키는 머리 결합과 Unity 스폰 설정으로 정해진다.

## 3. 메시·재질·웨이트

- 상의·바지·손·신발이 같은 메시와 재질에 들어 있다. 부위별 독립 옷 오브젝트는 없다.
- 원본의 연결된 기하 조각은 2개다. 본체 17,519정점과 전면 중앙의 약 6~7mm 조각 52정점이다.
  작은 조각의 용도는 이번 검사에서 확정하지 않았다.
- GLB는 UV 등의 경계 분리 때문에 연결 조각이 25개로 보인다. 분석용 BMesh에서만
  10μm 이내 중복 좌표를 합치면 원본과 같은 2개가 되고, 열린 경계는 0개다.
  분석용 용접 결과는 원래 메시로 써넣지 않았다.
- 원본과 GLB 모두 월드 X=0 기준으로 모든 정점이 1mm 이내에서 좌우 대응된다.
- 몸체의 모든 정점에 변형용 본 웨이트가 있다. 현재 GLB의 정점당 본 영향은 1~4개이며,
  웨이트 합은 부동소수점 오차 범위에서 1이다.
- 원본·FBX에는 정점당 최대 7개 본 영향이 있고, 원본의 변형 본 웨이트 합 범위는
  약 0.815~1.089다. 현재 GLB 출력은 상위 4개 영향과 정규화된 합을 사용한다.
  수정 후에도 같은 출력 기준으로 손·관절 변형을 확인해야 한다.
- 원본·GLB에는 2048×2048 Base Color와 Roughness 이미지가 포함되어 있다.
  GLB에는 실제 Normal 텍스처 연결이 없다. 원본 Normal Map 노드의 Color 입력에도 이미지 연결이 없다.

체형 키를 만들면 옷의 실루엣도 같이 바뀐다. 현재 복장 안에서 체격을 달리하는 용도로 사용할 수 있다.
옷을 부위별로 교체하거나 부위 색상을 독립적으로 바꾸려면 메시·재질 또는 UV 마스크 구성을 추가로 정리한다.

## 4. 수정할 수 있는 범위

| 대상 | 구현 방법 | 검토 결과 |
|---|---|---|
| 상체 폭·두께 | 사각형 메시의 좌우 대칭 Shape Key, 부드러운 부위 마스크 | 우선 대상. 목·팔 관절 이동을 제한 |
| 허리·배·골반 실루엣 | 앞/뒤/좌우로 정점 이동하는 Shape Key | 우선 대상. 옷도 함께 변형 |
| 팔·다리 굵기 | 각 부위 중심축 주변의 정점 변형 | 가능. 손발 끝·관절 전환부를 보호하고 포즈 확인 |
| 어깨 간격·팔 길이·다리 길이 | 메시와 관절 위치/기준 자세를 함께 수정 | 추가 검증 대상. 기존 Humanoid·착석·걷기 검사를 다시 수행 |
| 전체 키 | 스폰의 `targetHeightMeters` 및 전체 배율, 필요 시 인물별 값 | 설정 구조 확인. 체형과 머리 비율도 함께 평가 |
| 머리 크기·연결 높이 | 머리 결합의 `--head-share`, `--scale`, `--lift`와 목 재배치 | 스크립트에 지원. 사용자 조절 UI·인물별 저장은 추가 구현 필요 |
| 자세·동작 | 기존 60개 본과 Unity Humanoid 클립 | 기존 기능 보존. 이번 분석에서 새 클립 재생은 하지 않음 |

작업 순서는 다음을 권장한다.

1. 원본을 별도 작업 사본으로 사용하고, 편집용 메시와 게임용 리그를 구분한다.
2. 상체·허리/배 등 목과 관절 위치를 움직이지 않는 3~4개 키를 만든다.
3. 작은 범위의 마름·표준·체격 있는 프리셋을 조합하고 정면·옆면·앉은 자세로 평가한다.
4. 머리 크기·목 연결 위치를 함께 맞춘다.
5. 실제 GLB 로딩 뒤 체형 값을 적용하는 Unity Inspector와 인물별 값 저장을 연결한다.
6. 실제 생성 머리·현재 동작·HMD에서 외관과 프레임 시간을 확인한다.

새 인물별 체형 저장·자동 얼굴 분석·체형 추정·Inspector는 현재 구현된 기능이 아니다.
얼굴만으로 실제 체형을 결정하는 기능의 정확도는 이번 작업에서 평가하지 않았다.

## 5. 머리 결합과 Unity의 연결 조건

현재 경로는 [머리 결합 스크립트](../Survey/blender/head_body_merge.py)에서
목 본부터 머리 본 사이의 가장 좁은 단면을 찾고, 그 위를 BMesh로 잘라 낸 뒤 생성 머리를 붙인다.

- 목 단면과 몸체 높이는 `obj.data.vertices`의 기본 좌표로 측정한다. Shape Key 가중치가 적용된
  평가 메시를 재는 구현은 아니다. 목 높이·옷깃 폭·키를 바꾸는 키를 사용할 때는 머리 배치도 함께 갱신해야 한다.
- 첫 체형 키에서 목·옷깃을 고정하면 기존 연결 기준을 유지할 수 있다.
- `--scale`과 `--lift`는 결합 스크립트에 있지만, 현재 작업자는 이 값을 인물별 입력에서 전달하지 않는다.
  현재 작업자가 전달하는 비율·방향·전체 배율은 공통 환경 설정이다.
- [PersonaSpawner](../Assets/Scripts/Persona/PersonaSpawner.cs)는 GLB 생성 후 `NormalizeHeight`로
  전체 Renderer 높이를 맞춘다. 기본 `targetHeightMeters`는 1.7이다. 실행 중 씬의 실제 Inspector 값은
  이번 검사에서 조회하지 않았다. 키 프리셋을 구현할 때 이 정규화 설정까지 연결해야 한다.
- [PersonaHumanoid](../Assets/Scripts/Persona/PersonaHumanoidProbe.cs)는 본 이름과 스킨 바인드 행렬을 사용한다.
  메시만 크게 늘리거나, 리그에 남은 0.01 배율을 임의로 적용하면 기존 연결 조건이 달라질 수 있다.
- GLB를 Blender로 재임포트한 리그에서는 본 tail와 보조 도형 표시가 크게 보인다.
  이 표시의 크기를 캐릭터의 실제 관절 위치나 메시 크기로 사용하지 않는다.
  현재 Blender 화면에서는 보조 도형과 리그 표시를 숨기고 몸체 메시만 보이게 했다.

설치된 `com.unity.cloud.gltfast`는 **6.14.1**이다. 로컬 패키지의 `MorphTargetsGenerator.cs`는
`Mesh.AddBlendShapeFrame(name, 1f, ...)`를 사용하고, `GameObjectInstantiator.cs`는 로드된 가중치를
`SetBlendShapeWeight`에 그대로 전달한다. **이 GLB 경로의 형태 키 가중치는 0~1을 기준으로 다룬다.**
조절 도구를 만들 때는 `GetBlendShapeFrameWeight` 등으로 실제 최대 가중치를 읽는 방법도 사용할 수 있다.
일반 FBX 설명에서의 0~100을 이 경로에 그대로 넣지 않는다.
[Unity의 Blend Shape 조절 API](https://docs.unity3d.com/2022.3/Documentation/Manual/BlendShapes.html).

## 6. 실제 사본 검사와 검증 한계

Blender 4.5.10 LTS의 별도 백그라운드 프로세스에서 다음을 실행했다.

1. `Human.blend`의 사각형 메시에 `Basis`와 `Audit_TorsoBulk`를 생성했다.
2. 목과 옷깃 위쪽을 고정하고 상체 6,596정점에 최대 약 4.48cm 변형을 작성했다.
3. 좌표 대응으로 현재 GLB의 정점에 변형을 전달했다. 최대 대응 오차 약 0.96μm.
4. `probe_body.glb` 출력에서 형태 키 1개, 스킨 본 60개, 변화 정점 6,985개를 확인했다.
5. 검사 전용 구체 머리와 저장소의 실제 `head_body_merge.py`를 사용해 결합했다.
6. 결합 GLB에서 형태 키 이름과 비영(非零) 변형 6,985정점, 스킨 본 60개를 확인했다.
   목 절단으로 몸체 정점 수는 18,537이 됐고 키의 위치 배열도 그 수와 맞았다.
7. BLEND·FBX·원본 몸체 GLB의 SHA-256이 모두 보존됐음을 확인했다.

**확인된 범위는 구조·변형 전달·GLB 출력·목 절단/머리 결합의 키 보존이다.**
Unity의 실제 GLB 로딩·키 조절·Humanoid 클립 재생, 실제 생성 머리와의 외관,
HMD 양안·성능, 인물별 체형 저장은 검증하지 않았다. 시연 품질이 확보된 체형 프리셋도 아직 없다.
운영 서버의 Blender 버전과 로컬 검사 버전은 구분한다. 서버에는 배포하지 않았다.

검사 파일은 Git에서 제외된 `tools/_work/model_structure_20261011/`에 있다.

|---|---|
| `source_blend.json`, `source_fbx.json`, `current_glb.json` | 메시·토폴로지·재질·웨이트·본 구조 측정 |
| `pipeline_probe.json` | 원본 대조·형태 키 전송·실제 결합 결과 |

## 7. 체형 키 작성 전 손가락 수정 사본

**초기 검토 기록이다.** 사용자는 이 사본의 변화가 거의 보이지 않는다고 평가했고,
이어서 손 전체 구조를 고쳐 달라고 요청했다. 현재 검토 사본과 검증 결과는 8장을 따른다.
이 장의 파일을 최종 몸체로 사용하지 않는다.

같은 날 후속 사용자 요청으로 **원본을 보존한 손가락 수정 사본**을 만들었다.
위 1~6장은 구조 분석 당시의 결과이며, 이번 수정도 원본 BLEND·FBX·몸체 GLB와 운영 모델을 바꾸지 않았다.

확대 검사에서 기존 GLB의 저장된 첫 프레임은 왼손 검지 중간/끝 관절이 약 26도씩,
중지·약지·소지가 약 25도씩 굽어 있었다. 오른손은 거의 펴져 있었다.
기본 메시 자체의 길이와 저장된 포즈 때문에 짧아 보이는 현상을 구분했다.
당시 Blender 화면에는 수정된 메시와 별도의 편안한 양손 자세를 보여 줬다.

- 원본 사각형 메시에서 관절축에 수직인 손가락 두께를 완만하게 줄이고 표면을 조금 고르게 했다.
  최대 정점 이동은 약 **1.00mm**, 변화 정점은 원본 1,207개·GLB 1,552개다.
- 정점 수와 UV는 유지했고 체형 Shape Key는 만들지 않았다. 손목·몸통·옷·목은 변경하지 않았다.
- 기존 GLB에서 손의 `POSITION`·`NORMAL` 데이터만 갱신했다. 본 60개·스킨 바인드 행렬·웨이트·
  UV·삼각형 인덱스·텍스처·재질·기존 노드/애니메이션 자료는 원본과 대조해 보존을 확인했다.
- `Natural_Hand_Relaxed_PREVIEW`는 별도 Blender 미리보기 액션이다. 양손 검지→소지의 굽힘을
  조금씩 달리하고 기존 왼손의 과한 굽힘을 줄였다. **이 액션은 Unity 클립에 연결하지 않았다.**

Blender 4.5.10 LTS에서 수정 GLB를 실제로 다시 불러오고, 원본과 같은 0·15·35도 손가락 굽힘을 대조했다.
세 자세 모두 새 면 반전·새 퇴화 삼각형이 0개였고, 손 밖 정점의 위치 차이는 0이었다.
손등·손바닥·사선과 양손을 확대해 확인했다. 이 검사는 기존 Unity의 걷기·착석·대화 클립 재생이나
실제 HMD 검사가 아니다. 서버와 등록 인물 모델에는 배포하지 않았다.

산출물은 Git에서 제외된 `tools/_work/hand_refinement_20261011/`에 있다.

| 파일 | 용도 |
|---|---|
| `Human_HandsRefined_Source.blend` | 손 형태가 수정된 사각형 메시·원래 편집 리그 사본. 이후 체형 키 작성용 |
| `Human_HandsRefined_Preview.blend` | 기존 게임용 리그와 수정 메시·편안한 손 자세 사본 |

## 8. 기존 관절에 맞춘 손 구조 사본 — 후속 사본으로 대체

사용자가 보낸 확대 사진에서 손바닥이 평평하고 손가락 뿌리·관절·엄지의 연결이
한 덩어리처럼 보이는 문제를 확인했다. 초기 1mm 수정과 자세 변경만으로는 충분하지 않았다.
손가락을 가늘게 만드는 중간 사본도 최종안으로 채택하지 않고, 관절과 손톱 자리가 있는
기본 손 메시를 기존 몸체 크기·관절 위치에 맞춘 **별도 검토 사본**을 작성했다.

### 변경 범위

- [MakeHuman 기본 메시](https://github.com/makehumancommunity/makehuman/blob/a8bc2d54ff0ac92e78ff71431b1023eda42bf482/makehuman/data/3dobjs/base.obj)의
  손 부분과 기본 리그·웨이트 자료를 참고했다. 사용한 자산은
  [CC0 자산 라이선스](https://github.com/makehumancommunity/makehuman/blob/a8bc2d54ff0ac92e78ff71431b1023eda42bf482/LICENSE.ASSETS.md) 대상이며,
  MakeHuman 프로그램 코드를 실행하거나 가져오지 않았다. 기준 commit은
  `a8bc2d54ff0ac92e78ff71431b1023eda42bf482`다.
- 손바닥 볼륨·엄지 뿌리·손가락 사이 연결·관절과 손톱 자리의 메시를 바꿨다.
  엄지 말절은 기존 본 tail의 길이를 그대로 메시 길이로 쓰지 않고 35mm를 기준으로 맞췄다.
  **본 위치나 길이를 변경한 것은 아니다.**
- 원래 소매의 노출된 경계를 보존하는 방식으로 기존 손 피부를 제거하고,
  새 손목 끝은 소매 안쪽으로 들어가도록 배치했다. 소매 끝과 손목은 각각 닫힌 기하다.
  단일한 피부 표면으로 용접한 구조로 설명하지 않는다.
- 원래 피부색을 새 손 UV에 Blender로 베이크하고, 색의 작은 투영 경계는 메시 색상 속성으로
  보간했다. 손톱 재질에는 피부색을 중복 곱하지 않도록 색상 값을 분리했다.
  몸체·손 피부·손톱의 재질 3개를 사용한다.
- 편집용 메시 19,220정점·19,236면을 작성하고 게임용 본 60개에 다시 연결했다.
  손목 근처의 팔/손 가중치를 보간했으며 정점당 영향 본은 최대 4개다.
  **손의 토폴로지·UV·웨이트를 모두 유지한 수정이 아니다.** 체형 Shape Key는 아직 없다.
- 원본 `Human.blend`·`Human.fbx`·`fixed_body_animation/body.glb`는 SHA-256 대조로 보존을 확인했다.
  Unity 자산, 운영 서버, 등록 인물 모델에는 적용하지 않았다.

## 9. 성인 남성 손으로 교체한 검토 사본 — 연결·표면 수정으로 대체

사용자가 8장의 손바닥·엄지·손끝 형태를 보고 기존 손을 유지하지 않아도 된다며,
평범한 남성 손으로 교체하도록 요청했다. **8장 사본은 최종안으로 사용하지 않는다.**
기존 관절 위치에 새 메시를 다시 늘이는 방식이 짧은 손가락과 긴 손바닥 비율을 남겼으므로,
이번 사본은 새 손의 비율을 먼저 작성하고 손가락 본을 그 위치에 맞췄다.

- 같은 MakeHuman CC0 자산의 성인 남성 target과 손가락 굵기·간격 target을 참고했다.
  사용한 파일·기준 commit·계수는 `reference/provenance.json`과 `male_rebuild/rebuild_report.json`에 기록했다.
  프로그램 코드는 가져오지 않았다. 참고 자산의 원래 관절과 연결을 사용하며 이전 몸체의
  손가락 위치에 맞추는 개별 구간 재변형은 제거했다.
- 기본 몸체 좌표에서 손목~중지 끝 기준 길이는 약19.3cm, 손목~중지 MCP는 약10.68cm,
  중지 관절 사슬 길이는 약9.19cm다. Unity의 키 정규화 전 수치다.
- 손바닥·엄지 뿌리·손가락 비율과 둥근 손끝을 작성했다. 깊은 손톱 홈은 완화하고,
  짧고 얕은 손톱판을 별도 닫힌 기하로 만들었다. 손 표면만 한 단계 세분화했다.
- 본 이름·부모 관계·개수는 60개로 유지했다. **양손 손가락 본 30개의 기준 위치·길이·roll을 변경했다.**
  손목·팔을 포함한 나머지 30개 본은 재출력 수치 오차 범위에서 동일하다.
  원래 344본 리그가 들어 있는 중간 파일은 새 손의 동작용 리그로 쓰지 않는다.
- 소매는 보존했고 손목 끝은 소매 안으로 들어간다. 소매와 손의 피부 표면을 용접한 구조는 아니다.
  피부는 원래 색을 Blender로 베이크한 뒤 메시 정점색으로 보간했다. 피부결 텍스처를 새로 제작한 것은 아니다.
  손톱은 별도 재질이다. 몸체·손 피부·손톱 재질 3개, 편집 메시 31,890정점·31,902면이다.

원본 `.blend`·FBX·기존 `body.glb`의 SHA-256은 그대로다. Unity 자산·등록 인물·서버에는 적용하지 않았다.
손가락 골격 변경 후 실제 Unity Humanoid 동작·재질·걷기·착석·대화 클립과 HMD 검사는 남아 있다.
관절/손톱의 최종 외관 판단도 사용자 확인 전이다. 열린 경계·퇴화 면 검사는 자기 교차 검사가 아니다.

## 10. 전체 몸체에서 양손을 이어 수정한 사본 — 길이·손톱·엄지 수정으로 대체

사용자가 손의 외관이 어색하며 손만 따로 빼지 말고 모델에 붙은 상태에서 수정하라고 요청했다.
9장의 확대 화면은 잘라 낸 복제였고 실제 몸체의 손도 소매 안에 겹친 별도 연결 성분이었다.
최신 사본에서는 **전체 `avatar_body` 메시에서 소매와 양손 경계를 실제 면으로 이었다.**
Blender에는 손 복제 없이 전체 몸체를 표시한다.

- 양쪽 소매의 이전 막음 면을 열고 손목 경계를 146개 면으로 연결했다.
  팔·몸체·양손이 같은 연결 성분이며 소매 안에 겹친 손목 끝으로 분리된 구조는 제거했다.
- 손바닥의 길이 방향을 7% 줄이고 엄지 이외 손가락은 1.5% 늘렸다. 같은 전체 메시 안에서
  마디의 과한 볼륨과 손바닥 굴곡을 완화했으며 손가락 본 위치도 그 형태에 맞췄다.
  손목·팔·몸통 등 나머지 본 위치는 유지했다. 저장된 이전 손가락 포즈는 초기화했다.
- 별개 손톱판을 없애고 손가락 표면 일부 면에 손톱 재질과 얕은 손톱 경계를 만들었다.
  피부와 가까운 색상으로 보간해 흰 판의 테두리가 남지 않게 했다. 손톱도 같은 연결된 피부 메시다.
- 손목에 남아 있던 회색 옷색 베이크를 피부색으로 맞추고 새 연결부의 정점색 경계를 정리했다.
  몸체·손 피부·손톱의 재질 3개와 게임용 본 60개를 사용한다.

편집 메시의 정점/면은 **28,996개 / 29,066개**다. 실제 출력 GLB를 다시 불러와 UV·색상 분할을
진단용으로만 합친 결과, 몸체·양손 연결 성분 28,944정점과 원래 바지 버튼 52정점이 확인됐다.
열린 경계와 비정상 연결 가장자리는 0개다. 몸체의 모든 기하가 단일 연결 성분이라는 뜻은 아니다.
손 밖 `abs(world X) < 0.69m` 구역 16,580정점의 원본 대비 최대 좌표 차이는 약1.56μm다.
본 이름·부모 관계 60개와 최대 4개 피부 영향 본을 유지했다.

손가락 0·15·35도, 손가락 15도와 손목 ±30도의 Blender 검사에서 새 퇴화 삼각형은 0개였고
가장자리 길이 변화 비율은 최대 약2.55였다. 기존 머리 결합 스크립트를 단순 구체 머리로 실행한
최신 결과에서도 본 이름·부모와 손 표면이 유지됐다. 출력 배율을 제거한 손 좌표 차이는 최대 약1.45μm,
피부 정점색 차이는 약0.00432, 손톱 정점색 차이는 약0.00380이다.
최초 색상 대조에서는 손목의 같은 좌표에 다른 색을 가진 정점이 중복되어 위치 단독 대응이 실패했다.
진단으로 같은 위치·UV의 대응 색을 확인했고, 연결부의 옷색을 피부색으로 이어 준 최신 출력은 재검사를 통과했다.

Unity 자산·서버·등록 인물에는 적용하지 않았고 Unity 동작·실제 HMD 검사는 남아 있다.
최종 외관은 사용자 확인 전이며 연결·퇴화 면 검사는 자기 교차나 HMD 체감 자연스러움 검사가 아니다.

## 11. 손가락 길이·손톱·엄지를 수정한 사본 — 연속 단면·관절 수정으로 대체

사용자가 10장 사본의 손가락이 짧고 손톱이 보이지 않으며 엄지가 어색하다고 지적했다.
10장의 1.5% 길이 변경과 피부에 가까운 손톱색은 외관 개선이 충분하지 않았다.
현재 사본은 **손목이 연결된 전체 `avatar_body`에서 양손을 수정**했다. 손이나 손톱을
별도 오브젝트로 잘라 내지 않았으며 이전 사본은 비교 자료로 남겨 둔다.

- 검지·새끼는 20%, 중지·약지는 18% 길이를 늘렸다. 길이 수치는 이전 사본의
  관절 사슬을 기준으로 한 값이며, 화면에서 보이는 손가락 뿌리~끝 길이와 구분한다.
  손바닥 평면을 기준으로 각 마디 방향을 8·12·16도로 정리해 끝마디가 과하게 말리지 않도록 했다.
- 엄지의 첫 본과 손목은 유지하고 다음 두 마디를 각각 10%·16% 늘렸다. 끝마디의
  방향을 앞 마디에 가깝게 맞추고 단면 굵기를 연속적으로 정리해 손끝의 단차를 줄였다.
- 손톱은 같은 손가락 표면에 연결된 면이다. 경계 정점을 둥근 사각형 윤곽에 맞추고
  얕은 큐티클·연분홍 바닥·짧은 상아색 끝을 넣었다. 손 피부/손톱 Roughness는 0.65/0.38이다.
  이전처럼 색을 넓게 보간해 손톱 경계가 지워지지 않도록 손톱 면의 색을 구분했다.
- 전체 편집 메시 28,996정점·29,066면, 본 60개와 원래 부모 관계를 유지한다.
  손가락 본 30개는 수정한 형태에 맞췄고 손목·팔·몸통의 30개 본은 유지했다.
  손목의 연결 면과 몸체 정점은 이번 길이 수정으로 움직이지 않았다.

## 12. 엄지·손끝의 연속 단면과 관절을 다시 조형한 현재 사본

사용자가 11장 사본의 엄지 끝마디 꺾임, 손톱 주변 피부색/굵기 변화, 관절 표현 부족을 지적했다.
손끝만 별도 단면으로 강제 맞추던 처리와 손톱 경계 정점 이동을 제거했다.
전체 `avatar_body`에 붙은 양손에서 손가락 전체의 중심과 단면을 이어서 조정했다.

- 엄지는 노출된 두 마디의 피부 중심을 함께 맞추고, 네 손가락도 마디 사이의 굵기를
  연속적으로 보간한다. 단면은 양의 배율로 조절하며 손끝의 원래 둥근 곡면은 보존한다.
  손목 연결부·몸체와 이전 사본의 60개 본 이름/부모/기준 위치는 유지했다.
- 손가락 관절에 낮고 완만한 돌출과 얕은 굴곡을 넣고, 손등 쪽 관절 위치에 가는 주름을 만들었다.
  관절 전체를 고리 모양으로 조이지 않으며 주름의 색/깊이도 손등 쪽으로 제한한다.
- 이전 베이크의 손끝 밝은 띠를 제거하고 손 피부를 같은 색상 계열로 정리했다.
  손톱은 별도 오브젝트 없이 같은 표면의 재질/색으로 표현한다. 피부 경계 정점을 당기지 않는다.
- 손 전용 **2048×2048 Base Color 텍스처와 `NaturalHandsUV`**를 작성했다. 옷은 기존 `UVMap`을
  계속 사용한다. 손 피부/손톱 Roughness는 0.64/0.42이며 재질 3개를 유지한다.
  주름은 모델의 관절 좌표를 기준으로 작성한 표면색이다. 사진에서 피부결을 추출한 결과는 아니다.

편집 메시 28,996정점·29,066면과 게임용 본 60개를 유지했다. 손 또는 손톱의 분리 복제는 없다.
중간 굽힘 촬영에서는 손톱 경계에 작은 면 겹침이 보여, 정점 이동 없는 준비 사본에서 다시 작성했다.
최신 결과는 정면·비스듬한 방향·35도 굽힘 촬영으로 확인했다. 이 확인은 자기 교차 전수 검사가 아니다.

## 21. 손 리깅 구조 표시와 밑마디 포함 굽힘 확인 — 2026-10-12

사용자가 외형을 확인한 뒤 리깅이 망가지지 않았는지, 본 구조를 보여 달라고 요청했다.
열려 있던 실제 모델을 조회해 전체60개 본과 `root`를 대상으로 한 Armature modifier,

`hand.l → c_middle1.l → c_middle2.l → c_middle3.l`

검지·약지·소지·엄지도 같은3개 본 체인이며 오른손은 `.r`이다.

손목 본의 기존 표시 길이를 줄이기 위해 실제 본 기준 행렬을 수정하지 않고
검사용 관절 표식을 custom shape로 사용했다. `RigReview_WristMarker`는 표시용 보조 메시다.
전체60개 본은 보존하고 손 검사에 불필요한 본만 화면에서 숨겼다.

## 23. 서버 몸체·현재 캐릭터 갱신과 실제 등장 — 2026-10-13

사용자가 체험 시작에서도 새 몸체가 나오도록 서버 제작용 몸체 교체와 현재 인물 재결합을 요청했다.
Unity의 열린 Scene_2가 서버 현재 인물을 따르며 로컬 GLB·시험 프로필·강제 세션을 사용하지 않음을 확인했다.
서버에는 현재 인물의 완료된 제작 작업과 `head_trim.glb`가 남아 있어 이를 그대로 재사용했다.
다른 등록 인물이나 새 유료 생성 작업으로 대체하지 않았다.

### 서버 적용

- `Web/.env`의 `HEAD_BODY_GLB`가 가리키는 기존 파일 경로에 새 몸체 GLB를 원자적으로 교체했다.
- `Survey/blender/head_body_merge.py`를 공유 accessor 설정이 있는 로컬 수정본으로 배포했다.
- 기존 `head.x`·`neck.x`·머리 비율0.125·yaw−90°·출력 배율0.7을 유지해 현재 인물의 머리를 결합했다.
- 등록 API의 모델 업로드 경로로 새 GLB를 전달하고 다시 내려받은 SHA256을 후보 파일과 대조했다.
- Survey의 현재 인물 `model.glb`, 작업 DB의 artifact SHA256·바이트 수와 모델 갱신 시각을 함께 갱신했다.
  이전 모델 해시와 새 몸체 해시를 해당 작업의 `body_update` 기록에 남겼다.
- 작업 DB 잠금에서 새 queued/running 작업이 없는지 재확인하고, 준비 전후 파일 해시·현재 선택이 같을 때만 반영했다.

## 25. Unity Inspector 체형 조절과 현재 캐릭터 반영 — 2026-10-13

사용자 요청으로 앞24장의 체형 키6개를 Unity와 실제 Scene_2 캐릭터에 연결했다.

6개 키의 초기 값은0이며 기존 본60개와 FBX GUID를 유지한다. 새로운 얼굴 생성·재등록은 하지 않았다.

### 사용법·저장 범위

1. Scene_2에서 Play하고 체험을 시작해 캐릭터를 표시한다.
2. **Tools > 다시봄 > 캐릭터 > 체형 조절 열기**를 실행한다.
3. Inspector에서 **상체 폭·상체 두께·허리 폭·배 볼륨·팔 굵기·다리 굵기**를 조절한다.
   −1은 가늘게,0은 기본,+1은 굵게 적용하며 여러 값을 조합할 수 있다.
4. **체형 설정 저장**으로 설정 자산을 저장한다. **기본 체형으로 되돌리기**는6개 값을0으로 만든다.

기본 자산은 `Assets/Resources/PersonaBodyShape.asset`이며 Play 종료 후에도 설정을 유지한다.
Inspector 아래에는 캐릭터가 연결됐는지, 현재 모델에 키6개가 있는지 표시한다.
`PersonaSpawner.bodyShapeProfile`을 비우면 기본 자산을 사용하므로 열린 Scene_2를 저장하거나 다시 구성할 필요가 없다.
다른 설정을 만들 때는 `Create > 다시봄 > 체형 설정`으로 생성한 자산을 이 필드에 연결한다.
이 설정은 해당 로더가 불러오는 인물에 적용된다. 등록 세션 ID를 키로 한 체형 자동 저장은 구현하지 않았다.
여러 캐릭터가 같은 설정 자산을 쓰면 함께 바뀐다. 사진에서 체형을 추정하거나 서버 설문에 체형 값을 넣는 기능은 없다.

직접 배치한 FBX의 루트에 `PersonaBodyShapeController`를 추가해 같은 자산을 연결하면 Edit Mode에서도 조절한다.
현재6개 키는 키·팔다리 길이·어깨 관절 간격을 바꾸지 않는다. 목·옷깃·손·소매 안감·신발은 유지한다.

### 구현·출력

- `PersonaBodyShapeProfile`은6개 정규화 값을 저장하고 Inspector는 UI Toolkit의 자산 바인딩으로 Undo/Redo를 지원한다.
- `PersonaBodyShapeController`는 연결 때만 렌더러와 키 인덱스를 찾는다. 이후 값이 바뀔 때 가중치를 적용한다.
  공유 메시·정점 데이터·본·바인드 행렬·스킨 웨이트를 수정하지 않는다. 기존 표정 키가 있다면 대상 이름 이외의 키는 건드리지 않는다.

  각 프레임 단위를 곱해야 한다. 서버 모델을 FBX의100 단위로 적용해 과도하게 늘리는 오류를 피한다.
- `PersonaSpawner`가 모델을 로드하고 기존 키 정규화를 마친 뒤 컨트롤러를 연결한다. 아직 숨겨진 모델에도 등장 전에 적용한다.
  캐릭터를 교체하면 새 인스턴스에 다시 연결한다. 도착 연출·시선·호흡의 본 제어 경로는 유지했다.
