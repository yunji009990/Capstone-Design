# 머리·목 결합 보정 — 2026-10-24

사용자가 체형 미리보기의 옆모습에서 목과 얼굴 결합이 부자연스럽다고 지적했다.
10월23일의 체형 연결·리깅 검사는 통과했지만, 그 검사만으로 외관 품질이 확인된 것은 아니었다.
이번에는 보정 전 GLB·원본 FBX·현재 보정을 같은 카메라로 대조했다.

## 확인한 원인

- 기존 결합 GLB는 목에서 수평으로 몸체를 잘라 원래의 경사진 둥근 옷깃 상단을 잃었다.
  머리를 올려도 아래에서 받아 줄 옷깃이 없어 목의 절단면과 생성 이미지의 의상 흔적이 드러났다.
- 10월23일 추가한 높이 보정·목 원통·별도 피부색 재질은 턱 아래를 늘리고 표면 차이를 만들었다.
  이 처리는 제거했다.
- 미리보기 범위 계산도 `BakeMesh` 결과에 렌더러 배율을 다시 곱하고 있었다.
  실제 본 행렬로 계산한 정점과 대조해 위치·회전만 적용하도록 수정했다. 이는 미리보기 바닥·구도 수정이다.

## 현재 처리

`PersonaCollarTemplateBuilder`가 참여자 자료가 없는 기본 `Human.fbx`의 옷깃만 추출해
`Assets/Resources/PersonaCollarTemplate.asset`에 저장한다. 원본 의상의 UV·법선·본 가중치를 포함하며,
원본 FBX와 다른 제작 자산을 쓰거나 변경하지 않는다. 기본 FBX를 교체하면 이 템플릿도 다시 만들어야 한다.

`PersonaCollarTemplate.Restore`는 로드한 몸체의 잘린 높이 위쪽에 해당하는 옷깃만 복원한다.
템플릿의 목·머리 본과 파일의 본을 기준으로 좌표를 맞추고 이름으로 가중치를 연결한다.
몸체 원래 정점·재질 슬롯·6개 형태 키는 유지하며, 추가된 옷깃은 같은 의상 재질을 쓴다.
이미 온전한 옷깃은 중복 복원하지 않는다.

`PersonaModelProportions`는 생성 머리의 실제 목 절단면을 머리 본의 접합점에 맞추고 머리 전체를 이동한다.
얼굴·턱을 부분적으로 늘리지 않으며 머리의 정점 수·UV·법선·삼각형·가중치·재질 구성을 유지한다.
크기·높이·앞뒤3개 조절 키와 전체 배율은 계속 사용할 수 있다.

복원은 Unity가 소유한 인스턴스 복사본에만 적용한다. 원본 FBX·Avatar 기준 자산·등록 GLB·서버 결합 코드와
사용자의 미리보기·공용 체형 설정은 보존한다. 이 변경에 서버 배포나 재등록은 없다.

### 새 몸체의 착석 부유 보정

첫 입장·착석 재생 확인 뒤 사용자가 측면에서 엉덩이가 좌판 위로 떠 있는 것을 확인했다.
동작 재생과 Avatar 생성 성공만으로 좌판 접촉 높이가 검증되지는 않았다.
기존 착석 기준점의 Y는 약0.163m였고 새 몸체와 이전 몸체의 원점·착석 자세가 달랐다.
실제 스킨과 의자 MeshCollider를 비교한 좌판 높이는 약0.445m, 보정 전 골반 아래 옷 표면은 약0.531m로,
약8.6cm의 틈이 있었다. 앞으로 뻗은 발도 바닥 위로 떠 있었다.

- 개인 로컬 시험 설정의 `seatedHeightOffset=-0.083`을 사용한다.
  `PersonaSpawner`가 모델을 불러올 때 `PersonaArrival.ModelSeatHeightOffset`에 절대값으로 전달한다.
  사용자 `seatOffset`·SpawnPoint·의자·테이블은 바꾸지 않으며 기존 서버 몸체는0으로 초기화한다.
  이 값은 앉는 전환부터 적용하고 걷기의 바닥 경로에는 적용하지 않는다.
- 새 시험 몸체에만 `PersonaSeatedFootPlacement`를 붙인다. 의자에 앉는 혼합 비율에 따라
  양쪽 다리 두 관절의 회전으로 신발 바닥을 경로 끝의 바닥 높이에 맞춘다.
  발 회전·본 길이·스킨 가중치는 유지하며, 이 착석용 두 관절 보정은 서기·걷기와 기존 몸체에는 적용하지 않는다.
  현재 평평한 카페 바닥용 보정이며 계단·임의 지형 대응 기능은 아니다.
- 상태 기록은 좌판 충돌면·골반 아래 표면·접촉 간격·발의 최저점을 함께 남긴다.
  수정 후 측면 촬영에서 좌판 접촉과 내려놓은 발을 확인했고 좌판 틈은 사라졌다.
  옷의 측정 표면은 좌판에 약3mm 들어가는 수준이다. 입장·착석2회에서 같은 접촉 높이를 확인했고 보정은 누적되지 않았다.

전후 수치·측면 촬영은 Git 제외 `tools/_work/body_candidates/rocketbox/private/unity_validation/`에 있다.

### 걷기 지지발의 바닥 접촉

아래는10월24일 초기 보정 기록이다. 골반 진동 문제가 확인돼10월25일 다음 절의 방식으로 대체했다.

사용자는 SpawnPoint의 Y가 아닌 앞뒤 위치만 조절했다고 정정했다. 걷기 높이 문제를 SpawnPoint 이동 탓으로 보지 않았다.
좌판 접촉 보정과 별도로, 새 몸체에 걷기 클립을 적용하면 지지발이 바닥 대비 약-4.3~+6.4cm 어긋나는 것을
Editor 보행27개 시점에서 확인했다. 서서 대기할 때는 바닥에 맞았으며 경로 루트의 Y는 일정했다.

`PersonaSeatedFootPlacement`가 서기·걷기·인사의 실제 신발 스킨을 캐시한 정점·가중치·본 행렬로 평가한다.
낮은 지지발이 바닥3mm 위에 오도록 골반 자세의 Y만 보정한다. 이동 경로·모델 루트 Y·본 길이·가중치는 바꾸지 않는다.
들어 올린 반대 발의 상대 높이는 유지한다. 착석 전환에서는 이 보정을 줄이고 앞 절의 착석용 다리 보정으로 이어간다.
기존 서버 몸체와 다른 인물에는 로컬 시험본 연결 조건 없이 이 컴포넌트를 추가하지 않는다.

수정 후 보행27개 시점에서 지지발과 바닥의 간격은 약3mm로 유지됐고, 인사·착석과 유효한 Humanoid를 확인했다.
전후 기록은 `private/unity_validation/walk_floor_before.json`·`walk_floor_after.json`이다.
사용자가 조절한 Scene_2·체형 미리보기 설정·폰트 파일은 작업 전 해시와 동일했다.
반복 입장에서도 보행 지지발 높이와 착석 접촉을 확인했다.

### 보행 골반 진동·전환 끊김 수정 — 2026-10-25

사용자가 보행 중 몸 전체의 큰 상하 진동과 동작 전환의 끊김을 보고했다.
이전 지지발 보정은 매 프레임 가장 낮은 발바닥을 따라 골반을 이동했다. 발의 접촉 높이만 맞췄고 상체 움직임은 충분히 검증하지 못했다.
현재 로컬 시험 몸체와 `Catwalk Walk Forward 03`을2초·121개 자세로 평가하니,
원래 골반 높이 변화는 약1.22cm인데 보정 뒤 약13.00cm였으며 한 단계에서 최대3.28cm가 변했다.
걷기→회전에서도 이전 슬롯의 걷기 비율이 한 번에1에서0으로 바뀌어 혼합 중 자세가 끊겼다.

처음에는 골반을 일정하게6cm 내리고 지지발을 다리 IK로 고정하도록 바꿨다.
골반 변화1.22cm·발바닥 간격4~11mm라는 수치에 집중했고, 사용자가 무릎이 굽은 채 걷는 회귀를 지적했다.
같은 몸체와 같은 클립의121개 시점을 보정 유무로 다시 비교하니 무릎 굽힘 평균이
원본 약16도에서 보정 후 약35도로 증가했다. 이 중간 수정은 폐기했다.
Git 제외 `after.json`, `frame_*.png`는 이 폐기된 수정의 기록이며 최종 결과로 사용하지 않는다.

다음은 보행 보정 제거 시점의 변경이다. 걷기 클립의 최종 선택은 다음 절을 따른다.

- `PersonaSeatedFootPlacement`는 서기·걷기에서 골반이나 다리를 변경하지 않는다. 기존 착석 양발 보정만 유지한다.
- Scene_2의 걷기는 기존 프로젝트의 일반 `Walking` 클립으로 교체했다.
  두 클립을 같은 몸체에서 정면·측면으로 촬영해 팔 흔들림과 다리 궤적을 비교했다.
  `Catwalk Walk Forward 03` 자체의 손상으로 판단한 것은 아니며, 과도한 무릎 굽힘의 직접 원인은 추가 보정이었다.
- `PersonaArrival`은 이전 걷기 슬롯의 자세를 유지한 채 바깥 혼합에서 서서히 제거한다.
  바닥 경로가 없는 기존 경유지 이동도 걷기 비율을 사용한다.

원본·회귀 비교는 Git 제외 `tools/_work/persona_motion_20261025/clip_comparison.json`과
`corrected_catwalk_*.png`, `raw_catwalk_*.png`, `raw_walking_*.png`에 있다.
이 검사는 고정 시각의 Editor 자세 검사이며 HMD 프레임 시간·성능 측정이 아니다.
최종 보행은 발을 강제로 바닥에 고정하지 않으므로 리타게팅한 신발과 바닥 사이의 접촉 오차는 별도 과제다.
자세를 다시 굽히는 방식으로 이를 감추지 않는다.

`final_comparison.json`의121개 시점에서 착석 전용 보정을 호출한 `Walking`과 보정을 호출하지 않은 원본은
