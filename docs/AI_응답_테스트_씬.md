현재는 **마이크 질문 → STT·LLM → Qwen3-TTS → 음성·자막 답변**으로 동작한다.
TTS 재연결과 실제 검사 결과는 [재연결 검사](TTS_재연결_검증.md)를 참고한다.
현재 음성 전송은 [TTS 생성 스트리밍](TTS_실시간_스트리밍.md), 추론 대기 중 짧은 음성은

텍스트를 직접 넣는 자동 검사와 분류 결과는 [판정기 텍스트 검사](판정기_텍스트_검사.md)를 참고한다.

1. Unity에서 `Tools > Dialogue > Open AI test scene`을 연다.
2. Play 후 처음 사용하는 PC라면 아래 접속 설정을 입력한다. `음성 대화 서버 준비 완료 · Qwen3-TTS` 표시를 확인한다.
3. `참조 목소리 · 억양 설정`에서 WAV를 선택하고 미리 듣기·전사를 확인한다. 생략하면 현재 등록 음성을 사용한다.
4. 마이크를 선택하고 `테스트 시작`을 누른다. 연결이 준비되면 마이크가 열리며, `종료`로 닫는다.

새 인물·목소리는 참조 음성에 이어 리액션 준비 안내가 표시된다. 공개 WAV 실측 준비 시간은 약 3~5초였으며,
같은 설정으로 재접속하면 캐시를 재사용한다. 준비에 실패한 경우에도 리액션 없이 대화는 시작된다.

기본 서버는 `http://220.69.208.201:8002`. 주소·토큰은 AI 테스트 화면에서 직접 설정하며,
`확인` 또는 `테스트 시작`을 누르면 이 PC·프로젝트의 AI 전용 EditorPrefs에 저장한다.
기존에 저장한 설정은 그대로 사용한다. 씬을 열거나 만들 때 `Scene_1`·`Scene_2`를 읽지 않는다.
토큰은 화면에서 가리고 새 씬에는 저장하지 않는다.

처음 설정하는 PC에서는 Play 후 왼쪽 `대화 서버` 주소와 `접속 토큰`을 입력하고 `확인`을 누른다.
접속 토큰은 대화 서버의 `~/capstone-server/dialogue.env`에 있는 `DIALOGUE_TOKEN`과 같아야 한다.
토큰이 비어 있으면 입력 안내를 표시하며 대화를 시작하지 않는다. Play를 종료해도 입력한 접속 설정은 유지된다.
마이크가 없으면 시작 버튼을 비활성화한다. 헤드폰을 사용해 재생 음성이 마이크로 들어오는 것을 줄인다.

## 화면과 조작

일반 화면에서는 마이크로 입력하며, 서버의 TTS 설정에 맞춰 텍스트/음성 답변을 처리한다.
Editor의 `Run text response check`는 마이크·STT를 거치지 않는 자동 검사다.
인물 등록·3D 모델·VR 헤드셋 없이 기본 테스트 인물로 동작한다. 참조 음성은 TTS를 켰을 때만 필요하다.
참조를 따로 선택하지 않으면 현재 서버 등록 음성을 자동으로 사용한다. 등록 음성도 없으면 WAV 선택을 안내한다.
Unity Editor에서는 파일 선택 창을 쓰며 빌드에서는 파일 전체 경로를 입력해 불러온다.

| 표시·조작 | 내용 |
|---|---|
| 음성 인식 결과 | 인식 문장, 중간/최종 결과, 소리 종류, 언어 |
| 음성 측정값 | 발화 길이, RMS dBFS |
| 처리·시간 | 일반/추론 경로, 본답변 첫 글자·첫 음성·생성 완료까지의 서버 시간. 리액션 지연은 별도 |
| 테스트 시작·종료 | 연속 마이크 송신과 연결 시작·종료 |
| 다음 마이크 선택 | 테스트를 멈춘 상태에서 입력 장치 변경 |
| 참조 목소리 · 억양 설정 | WAV 선택·실제 사용 구간 미리 듣기·자동 전사 수정 |
| AI 발화 중 말하기 | 재생 위치·음성을 보존해 잠시 멈추고, 새 발화의 의도에 따라 재개·수정·전환·대기 |
| 끼어들기 판정 | 선택한 방향, 이유, 판정 요청에 걸린 시간 표시 |
| 답변 중단 | 생성 중이거나 재생 중인 답변을 즉시 중단 |
| 새 대화 | 재생 중단, 서버 기록·상황과 화면 기록 초기화 |
| 사진 집기 행동 전달 | 15초 동안 질문과 함께 전달할 Unity 행동 생성 |
| 대화 기록 복사 | 표시된 대화를 클립보드로 복사 |

예를 들어 `사진 집기 행동 전달` 후 마이크로 “내가 지금 들고 있는 게 뭐야?”라고 묻는다.
말을 하지 않고 버튼만 누르면 STT 결과가 생기지 않는다.

AI가 답변을 생성하는 중 “응, 계속 말해 줘”는 기존 생성을 재개하고, “아니, 더 쉽게 설명해 줘”는
새 답변으로 수정한다. “그건 됐고 고양이에 대해 알려 줘”는 주제를 바꾸며, “잠깐 기다려 줘”는
대기한다. 대기 중 “계속 말해 줘”라고 하면 재개한다. 보류가 120초를 넘으면 자동으로 해제된다.
VAD 감지 때 먼저 소리를 멈추고, 발화 종료·전사 후에 의도를 판단한다. 판정이 불확실하면 확인 질문을 한다.
화면에 최신 STT 결과를 표시하면서 보류한 답변 자막과 끼어든 발화를 함께 보존한다.
`답변 중단` 버튼은 판정 없이 남은 답변을 취소한다.
TTS 사용 시 생성된 음성의 재생 도중에도 같은 판정이 적용된다.
텍스트 모드에서 이미 완료된 답변은 다시 재생할 대상이 없으며 다음 발화는 새로운 대화로 처리한다.

TTS를 켜면 Qwen3-TTS 1.7B Base의 ICL 모드로 음성을 만든다. 참조의 화자 임베딩·오디오 코드·전사를 함께
사용해 음색과 말투를 반영한다. 음색만 추출하는 `x_vector_only_mode`는 꺼 두었다.
문장이 달라지므로 원본의 높낮이·길이가 그대로 복사되는 것은 아니며 실제 닮음은 청취로 확인한다.
참조는 3초 이상 16-bit PCM WAV(8–96kHz, 모노/스테레오)이며 6–12초를 권장한다.
긴 파일은 최대 12초의 연속 구간을 사용하고 그 구간만 전사한다. 원래 파일과 내부 쉼은 보존한다.
업로드는 서버 메모리에만 최대 8개 보관하며 30분 미사용 또는 서버 재시작 뒤에는 다시 불러온다.
참조 준비는 대화 시작 때 한 번 수행하고 모든 답변 구절에 재사용한다. 대화 종료 시 GPU 프롬프트를 해제한다.
현재는 첫 구절이 준비되면 TTS를 호출하고, 합성 도중 받은 PCM부터 재생한다.
추론 중에는 미리 만든 리액션이 먼저 나올 수 있다. 화면의 '첫 음성' 시간은 본답변 기준이며 리액션 시간으로 바꾸지 않았다.

## 기억과 대기 리액션 확인

같은 연결에서 일정·취향을 말하고 다른 대화를 이어간 뒤 다시 물어본다. 정정·삭제는 말로 요청할 수 있다.
AI가 모르는 내용을 되물었을 때 알려 준 답도 기억 정리 대상이다. 연결 종료·재접속·새 대화는 사용자 기억을 비운다.
구체적인 대본과 저장 범위는 [대화 메모리](대화_메모리.md)를 따른다.

리액션은 “두 코스의 시간과 비용을 비교해서 골라 줘”처럼 추론으로 분류될 질문으로 확인한다.
일반 모드나 본답변 글자가 0.3초 안에 나온 경우에는 생략한다. 리액션 도중에도 기존 끼어들기 조작을 사용할 수 있다.
인물·목소리 설정 변경은 다음 연결부터 반영한다. 자막에는 리액션이 보이지만 대화 기억에는 본답변만 남긴다.

## 멈춤 경계 확인 (2026-09-17)

끼어들 때 캐릭터가 **구절 끝에서** 멈추는지, 새 답변이 말 중간을 자르고 들어오지 않는지 사람이 듣고 본다.
계약은 [서버 음성 대화 구조](서버_음성대화_구조.md)의 "멈춤 경계 합의"를 따른다. 씬 에셋은 바꾸지 않는다.

1. `AI_Response_Test`에서 Play → `테스트 시작` → 설명이 길어질 질문을 한다(예: 산책 준비 과정).
2. 답변 재생 중에 다음을 하나씩 확인한다. 헤드폰을 쓴다.
   - “아니, 비 오는 날 기준으로 설명해 줘”(수정) · “그건 됐고 고양이 얘기해 줘”(전환):
     1.2초 안에 남은 구절 경계가 있으면 거기서 멈추고 새 답변이 시작되는지.
     경계가 멀면 짧은 페이드로 전환하는지.
   - “응, 계속 말해 줘”(재개): 정지 전 판정이 끝나면 계속 재생하고,
     이미 정지했다면 같은 답변의 남은 소리부터 이어지는지.
   - “아니, 내가 말하려던 건…”(불완전 발화): 진행/수정 선택지를 읊지 않고
     인물 말투로 짧게 듣는 반응이나 빠진 내용에 대한 질문을 하는지.
   - “잠깐 기다려 줘”(대기): 구절을 마저 말하지 않고 그 자리에서 멈추는지.
   - `답변 중단`·`새 대화`: 판정 없이 즉시 멈추는지.
3. Scene_2(체험 씬)에서도 같은 네 가지를 Play로 반복한다. 접속 설정은 각 씬의 것을 그대로 쓴다.
4. 기록 대조: `.dialogue-work/logs/dialogue-*.jsonl`에서 `response.paused` → `playback.paused`
   (필요하면 `playback.pause_forced`)의 `pause_id`가 같은 회차인지 본다.
   `python tools/analyze_dialogue_trace.py --ssh raon`로 보고서를 만들면 서버의
   `playback.ack reason=paused`와 같은 `pause_id`, 연결 계수
   `pause_boundary`/`pause_cut`/`pause_stale`/`pause_timeout`을 함께 볼 수 있다.

`reason=boundary`는 구절 경계 정지다. `grace_expired`·`immediate`는 경계 보장이 없는 정지,
`no_audio`는 아직 PCM을 받기 전의 정지다. `already_paused`는 이미 멈춘 상태의 새 요청이다.
`pause_expected_sample=-1`은 예약한 경계가 없었다는 뜻이고 0이 아니다.
**낱말 단위로 정확히 멈춘다고 설명하지 않는다.** 정지 지점은 서버가 보낸 구절 경계뿐이다.

자동 검사에서는 전체 하네스 492개와 연결된 Unity의 경계 정지 28개·재생 파형 38개가 통과했다.
위 마이크·VR 청취 절차는 사용자가 새 체험에서 확인해야 한다. 자세한 결과와 범위는
[서버 음성 대화 구조](서버_음성대화_구조.md)의 같은 날짜 검증 기록을 따른다.

- Play 중 `Tools > Dialogue > Run reference upload voice check`: 공개 WAV 업로드 후 그 참조로 합성·재생 검사.
- Play 중 `Tools > Dialogue > Run reference preview check`: WAV 업로드·미리 듣기·설정 화면 검사.
- 기본 결과: `.dialogue-work/ai-voice-scene-smoke.json`.
- 텍스트 입력 결과: `.dialogue-work/ai-text-scene-smoke.json`, `ai-text-scene-tested.png`.
- 끼어들기 결과: `.dialogue-work/semantic-interruption-check.json`, 각 경우의 `semantic-*.png`.
- 참조 업로드 결과: `.dialogue-work/ai-reference-upload.json`. 결과의 `voiceMode=reference_icl`을 확인한다.
- 설정 화면: `.dialogue-work/ai-reference-settings.png`, 미리 듣기 결과: `ai-reference-preview.json`.

끼어들기 검사는 `.dialogue-work/semantic-fixtures/`에 모노 PCM16·16kHz WAV 다섯 개가 필요하다.
현재 파일은 공개 참조 음성으로 Qwen3-TTS가 합성한 검사 입력이며 실제 사용자의 마이크 녹음은 아니다.
다른 PC에서는 아래 문장을 녹음해 같은 파일명으로 준비할 수도 있다.

| 파일 | 입력 문장 |
|---|---|
| `ask.wav` | 산책 준비 과정을 차례대로 설명해 줘. |
| `resume.wav` | 응, 계속 말해 줘. |
| `revise.wav` | 아니, 비가 오는 날이라고 생각하고 설명해 줘. |
| `switch.wav` | 그건 됐고, 고양이에 대해서 설명해 줘. |
| `hold.wav` | 잠깐 기다려 줘. |

이 검사는 일시정지 중 PCM 소비 커서가 고정되는지, 재개 시 응답 ID와 버퍼가 유지되는지,
수정·전환 때 기존 응답을 정확히 한 번 취소하는지, 대기 후 자동 재생하지 않는지를 확인한다.
예전 `ai-voice-interruption.json`은 즉시 취소 방식의 과거 결과이므로 새 판정기의 증거로 사용하지 않는다.
2026-09-10 네 경우 모두 통과했다. 재개와 대기 후 재개는 같은 응답 ID·PCM 커서를 유지했고,
수정·주제 전환은 각각 이전 응답을 한 번 취소하고 새로운 답변을 끝까지 재생했다.
음성 검사에서 판정 요청은 0.41–0.48초였으며 입력 발화 길이·종료 무음·STT·TTS 시간은 포함하지 않는다.

참조 업로드 왕복 검사에서 `speech / ko`와 `reference_icl`을 확인했고,
첫 글자 0.21초·첫 음성 2.75초·전체 생성 3.45초였다(4.608초 공개 WAV 참조, 준비 시간 제외).
1회 기능 검사 수치다. 서버의 발화 종료 판정 이후를 재며 종료 무음·네트워크·오디오 장치 지연은 제외한다.
실제 PC/VR 마이크·방의 소음에서 인식 정확도와 음색·억양 품질은 따로 확인해야 한다.

공개 WAV 참조로 “안녕하세요. 오늘은 어떤 이야기를 나눠 볼까요?”를 합성하고
음성 인식으로 다시 읽은 검사에서 공백·문장부호를 제외한 문장이 일치했다.
음성은 `.dialogue-work/reference-clone-sample.wav`, 결과는 `reference-clone-output.json`이다.
이 검사는 발음 내용 확인이며 화자 닮음이나 억양 정확도 점수는 아니다.

구현은 `Assets/Scripts/Dialogue/`의 `DialogueVoiceClient`, `DialogueTransport`, `DialogueAudioPlayer`,
`DialogueTestPanel`이다. 기존 씬의 스크립트 GUID를 유지해 참조를 옮겼다.
