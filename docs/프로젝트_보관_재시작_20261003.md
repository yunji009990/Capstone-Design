# 프로젝트 보관과 재시작

기준일: 2026-10-03. 발표 이후 프로젝트 서비스를 내려 두고, 필요할 때 **같은 서버에서 같은 구성으로 다시 실행**하는 안내다.
등록 자료·생성 결과·모델·가상환경은 보존한다. 기능 구성은 [프로젝트 기술 개요](프로젝트_기술_개요.md),
구현 범위와 이전 검사는 [현재 구현 현황](현재_구현_현황.md)에 있다.

## 1. 다음에 다시 켜는 방법

이 PC의 PowerShell에서 실행한다. `raon`은 기존 SSH 별칭이며 같은 계정으로 접속한다.

```powershell
ssh raon python3 /home/crc_unity/capstone-runtime/project_runtime.py start
```

등록 → LLM → TTS → 대화 → Tripo 작업자 → 웹 순서로 실행하고 준비 상태를 기다린다.
GPU 모델을 읽으므로 완료까지 몇 분 걸릴 수 있다. 마지막에 6개 서비스의 `ready`와 상태 JSON이 나오면 준비된 것이다.
이미 같은 설정으로 실행 중인 서비스는 재사용한다. SSH 연결을 닫아도 서비스는 유지된다.
웹 주소·Unity의 기존 접속 설정·세션 코드와 자료는 그대로 사용한다.

상태 조회와 사용 후 종료:

```powershell
ssh raon python3 /home/crc_unity/capstone-runtime/project_runtime.py status
ssh raon python3 /home/crc_unity/capstone-runtime/project_runtime.py stop
```

`status`의 `pid`와 `listening`은 실행 여부다. Tripo는 HTTP 포트가 없으므로 정상 실행 중에도 `listening=false`다.
`start`는 별도로 API 준비 상태와 웹의 작업자 연결까지 검사한다.
종료는 웹 → 작업자 → 대화 → TTS → LLM → 등록 순서다. 진행 중인 대화·음성 합성·모델 작업·LLM 요청이 있으면 중단한다.
현재 작업이 끝난 뒤 `stop`을 다시 실행한다. 다른 계정의 GPU 작업이나 서버 전원은 제어하지 않는다.

## 2. 무엇을 보관했는가

| 구분 | 서버 위치 | 보관 방식 |
|---|---|---|
| 웹·등록·머리 생성 코드, 고정 몸체 등 제작 준비물 | `~/webapp` | 원본 유지 + 파일 백업 |
| 대화·STT·TTS 실행 코드와 설정 | `~/capstone-server` | 원본 유지 + 파일 백업 |
| 등록 설문·참조 음성·사진·등록된 모델 | `~/server/sessions` | 원본 유지 + 파일 백업 |
| 모델 작업 DB·생성 중간 자료·GLB | `~/webapp/Survey/data` | 원본 유지 + 파일 백업 |
| 미리 만든 대기 리액션 음성 | `~/capstone-server/reaction-cache` | 원본 유지 + 파일 백업 |
| Python 가상환경 | `~/venv/{web,registration,tripo,dialogue,qwentts,vllm}` | 현재 설치 그대로 유지 |
| LLM·STT·TTS 가중치 | `~/models`, `~/dialogue-models`, Hugging Face 캐시 | 현재 파일 그대로 유지 |
| 실제 실행 명령·환경변수 | `~/capstone-runtime/profile.json` | 실행 중인 6개 프로세스에서 직접 캡처 |
| 운영 설정 사본 | `~/capstone-runtime/config` | 설정 파일 사본과 SHA-256 보관 |
| 서버 파일 백업 | `~/capstone-runtime/archives/server-files-20261003.tar.gz` | 파일별 SHA-256 대조 후 보관 |

토큰이 포함될 수 있는 프로필과 자료는 서버의 해당 계정 전용 폴더에만 둔다. 폴더는 `700`, 비공개 파일은 `600`이다.
Git에는 실행 도구·모의 검사·이 안내만 넣으며 실제 토큰·설문·사진·음성·GLB는 넣지 않는다.
실행 로그는 `~/capstone-runtime/logs/{registration,llm,tts,dialogue,tripo,web}.log`에 쌓인다.
백업 파일 목록과 해시는 같은 폴더의 `archive_manifest.json`, 전체 결과는 `archive_report.json`이다.

가상환경과 대형 모델은 서버에 그대로 남겼으며 백업 압축파일에 중복 복사하지 않았다.
이 보관은 **현재 서버의 일시 중지·재개용**이다. 서버 디스크 반납·계정 삭제·다른 서버 이관을 하려면
모델·가상환경을 포함한 별도 이전 작업이 필요하다. 현재 서버의 파일을 정리하거나 삭제하지 않는다.

## 3. 재시작 도구가 확인하는 것

소스는 [tools/project_runtime.py](../tools/project_runtime.py)다. 기존 개별 서비스 실행기는 그대로 남겨 두었다.
이번 전체 재개에는 위의 통합 명령을 사용한다.

- 종료 전 실제 Python 경로·작업 폴더·실행 인자·환경을 저장했으므로 LLM의 GPU·추론 옵션도 보존한다.
- 설정 파일의 해시가 바뀌었으면 시작하지 않는다. 현재 파일을 예전 설정으로 자동 덮어쓰지 않는다.
- 다른 프로세스가 포트를 사용하거나 같은 서비스가 여러 개 발견되면 시작하지 않는다.
- 프로세스 소유자·가상환경·모듈·포트·시작 시각을 확인하고 Linux `pidfd`로 신호를 전달한다.
  PID 재사용이나 다른 GPU 사용자의 작업을 대상으로 종료하지 않는다. 강제 종료(`SIGKILL`)는 쓰지 않는다.
- 동시에 두 개의 시작·종료 작업을 실행하지 못하도록 잠근다. 시작에 실패하면 이번 호출이 새로 띄운 서비스만 정리한다.
- 서비스 시작 시 기존 실행기의 PID 파일도 갱신한다. 재부팅·로그인에 맞춰 자동 실행하는 설정은 추가하지 않았다.

설정과 실행 파일만 검사하려면 다음을 쓴다. 서비스는 시작하지 않는다.

```powershell
ssh raon python3 /home/crc_unity/capstone-runtime/project_runtime.py check
```

기존 설정을 바꿔야 하는 후속 개발에서는 원인과 변경 범위를 먼저 확인한다. 저장 프로필은 과거 환경을 그대로 사용하므로
`.env`만 바꾸거나 `capture`로 기존 프로필을 덮어써서는 안 된다. 새 설정을 적용한 서비스를 검증한 뒤
별도 보관 폴더에 새 프로필을 만들고 재시작 기준을 갱신한다.
