## 1. 판단과 추천 범위

현재 프로젝트에는 등록, 머리 생성·고정 몸체 결합, 캐릭터 입장·착석, 시선·호흡,
음성 대화, 끼어들기·재개, 연결별 기억과 체형 조절이 이미 있다.
가장 효과적인 다음 작업은 **준비가 끝난 뒤 시작하고, 인물이 듣고 반응하며, 자연스럽게 만남을 마치는 흐름**이다.
새 AI 모델이나 큰 시스템을 추가하기보다 기존 기능을 Scene_2의 체험에 연결하는 편이 남은 일정에 맞는다.

## 3. 우선 수정·개선 항목

### F01 — 시작 조건과 캐릭터 준비·입장 상태가 분리됨

**10월24일 후속:** 준비 상태·실패 안내·수동 재확인과 착석 후 입력을 연결했다.
아래는 최초 분석이며 현재 구현·검사는 [시작 준비 기록](체험_시작_준비_20261024.md)을 따른다.

- **중요도 높음 / 코드·설정 확인, 실제 실패 장면 미재현.**
- [ExperienceControl](../Assets/Scripts/Dialogue/ExperienceControl.cs) 75~83·122~141행은 인물 등록·서버 준비·대기 여부로 시작을 판단한다.
  캐릭터 로딩 완료·Humanoid 입장 가능 여부·마이크 장치 상태를 준비 조건에 포함하지 않는다.
- [PersonaSpawner](../Assets/Scripts/Persona/PersonaSpawner.cs) 326~368·763~881행은 로딩 중 시작 요청을 보관하는 구조다.
  로딩이 늦어도 T포즈 대신 나중에 입장하는 처리는 이미 있으므로, 이를 “로더가 고장났다”는 뜻으로 해석하면 안 된다.
  다만 Scene_2의 `loadingIndicator`는 비어 있고 모델 요청 제한은 120초여서 운영자가 어느 단계인지 알기 어렵다.
- [DialogueVoiceClient.Realtime](../Assets/Scripts/Dialogue/DialogueVoiceClient.Realtime.cs) 443~460행은 서버 ready 직후 마이크를 연다.
  착석 완료와 대화 입력 시작을 조정하는 연결은 없다. 인물이 오는 동안 먼저 답변할 가능성이 있다.
- **수정 방향:** 준비 상태를 등록 확인·모델 로딩·음성 연결·마이크·입장·대화 가능으로 구분한다.
  모델 없는 음성 전용 체험은 별도 선택으로 유지하고, 캐릭터 체험에서는 모델 준비를 기다린다.
  음성 준비는 입장과 겹쳐 진행하되 대화 시작 시점을 명시적으로 정한다.
- **완료 기준:** 준비된 모델, 다운로드 지연·실패, 모델 없는 등록, 마이크 없음의 각 상태에서 다음 행동이 화면에 보인다.
  입장 중 발화를 언제 받는지 정하고 3회 반복 시작·종료에서 같은 순서로 동작한다.
- **규모:** 작음~중간. feature-implementation으로 구현 후 bug-investigation·build-validation으로 확인.

관련 소규모 수정도 같이 처리하기 좋다.

### F02 — 분석 당시 듣는 반응 비활성, 같은 날 후속 구현

**후속 상태:** Scene_2의 자동 반응을 켜고 확정 발화·입력 턴을 기준으로 절차적 끄덕임을 연결했다.
현재는 클립 없이1.2초 이상 발화에 최대4.5도·0.9초로 반응한다. 자막 숨김·자기 발화 차단·시선/호흡 동시 검사는 통과했고 HMD 판정은 남아 있다.
아래는 수정 전 분석 근거다.

- **중요도 중간 / 설정 확인. 결함보다 체감 개선 기회.**
- 분석 당시 Scene_2의 PersonaArrival은 `autoNodWhileListening=0`, `nodClip=null`, `shakeClip=null`이었다.
  반면 말할 때의 Sitting Talking과 시선·호흡은 이미 켜져 있다.
- [PersonaArrival](../Assets/Scripts/Persona/PersonaArrival.cs) 455~519행에 말하기·듣기 제스처 코드가 있다.
  [PersonaSpawner](../Assets/Scripts/Persona/PersonaSpawner.cs) 417~439·543~576행에는 머리·목의 시선 제어가 있다.
- **수정 방향:** 작고 드문 끄덕임 또는 듣는 자세를 기존 상체 제스처에 연결한다.
  단순한 소리 크기는 분석 당시 끄덕임 코드의 기준이었으므로, 가능한 경우 서버가 검증한 발화 상태와 함께 사용한다.
  모든 말에 동의하는 과한 반응이나 감정 추정 기능으로 설명하지 않는다.
- **완료 기준:** 사용자가 말할 때만 가끔 반응하고, 인물이 말할 때·잡음만 있을 때·입장 중에는 끼어들지 않는다.
  시선·호흡·대화 제스처와 동시에 재생해 목·어깨가 튀지 않는지 확인한다.
- **규모:** 작음~중간. 새 얼굴 리그보다 범위가 작고 영상에서 차이를 보여주기 쉽다.

### F03 — 분석 당시 목소리 2D 고정, 같은 날 공간 음향 구현

**후속 상태:** 2D 강제 지정을 제거하고 머리 위치 추종·PCM 이후 Meta XR 공간화를 연결했다.
실제 AudioListener의 좌우 출력에서 왼쪽/오른쪽 방향 차이와 정면 좌우 일치를 확인했다. 등록 목소리·HMD 청취는 남아 있다.
아래는 수정 전 분석 근거다.

- **중요도 중간 / 코드 확인. 기능 개선 항목.**
- 분석 당시 [DialogueAudioPlayer](../Assets/Scripts/Dialogue/DialogueAudioPlayer.cs) 120~147행은 생성 시 `spatialBlend=0`으로 고정했다.
  Inspector의 AudioSource 값만 바꿔서는 시작할 때 덮어써지는 구조였다.
- [DialogueAudioRenderer](../Assets/Scripts/Dialogue/DialogueAudioRenderer.cs) 363~436행은 커스텀 오디오 콜백으로 모든 출력 채널에 같은 샘플을 기록한다.
  따라서 위치만 옮기면 원하는 공간화가 된다고 단정하지 말고 실제 오디오 처리 순서를 검증해야 한다.
