# 웹 등록 흐름 개선

2026-09-15. 사용자가 요청한 설문 재작성, 기본 인물 예시 제거, 무작위 세션 ID 발급을 구현하고 서버에 적용했다.
[설문 항목 조사](웹_설문_항목_사용현황.md)에서 확인한 관계별 말투·사용자 이름 예문 문제는 이번에 변경하지 않았다.

> 같은 날 이후의 **설문 v2 개편**이 이 문서의 화면·모듈·API 일부를 대체했다.
> 관계별 말투·이름 문제도 v2에서 해결했다. 현재 형식과 사용 방법은
> [웹 설문 v2 사용법](웹_설문_v2_사용법.md)을 따르고, 이 문서는 그 직전 상태의 기록으로 읽는다.
> `Web/persona.py`·`Web/registration_input.py`는 `Web/survey_v2.py`로 대체되어 삭제했다.

## 사용 방법

1. 서버 등록 웹을 새로 고침한다. 기존에 열어 둔 화면이라면 `Ctrl+F5`로 새 화면을 받는다.
2. 동의·참조 음성·인물 정보·추억 등을 작성한다. 실제 화자 분리 환경이 없는 서버에서는 ‘한 명 (분리 안 함)’을 선택한다.
3. ‘인물 확인’에 도착하면 현재 설문으로 인물 설정과 사전지식을 자동 작성한다. 필요하면 직접 편집한다.
4. 앞 단계로 돌아가 설문 답변을 변경하면 기존 작성 결과를 비우고, 인물 확인에 다시 도착할 때 새로 작성한다.
5. 내용 확인 후 ‘세션 시작’을 누른다. 서버가 고유한 세션 코드를 자동 발급하며 완료 화면에서 확인할 수 있다.
6. Scene_2에서 Play 후 ‘체험 시작’으로 등록 인물과 대화한다. 씬·Unity 대화 코드는 이번에 변경하지 않았다.

설문이 그대로라면 인물 확인에서 직접 편집한 내용을 보존한다. **설문을 바꾸면 그 편집 내용도 새로 작성**된다.
작성에 실패하면 인물 설정은 빈 상태로 남고 다음 단계·등록을 막는다. ‘설문으로 다시 작성’으로 재시도한다.
작성 중 설문이 바뀌면 이전 요청을 취소하고, 취소 후 늦게 도착한 응답도 반영하지 않는다.
작성 요청의 대기 제한은 15초다.

기본 친구 설정·기본 추억·테스트 자동 채우기 버튼·세션 ID 직접 입력란은 제거했다.
이미 등록한 인물의 자료는 보관하며 새 등록이 현재 체험 인물을 바꾼다. 등록되지 않은 예전 자료 폴더를
현재 인물로 자동 선택하던 호환 경로도 제거했다. `AI_Response_Test`의 독립 테스트 모드는 유지했다.

## 구현과 연결 계약

| 영역 | 변경 |
|---|---|
| `Web/static/index.html` | 현재 설문과 작성 시점의 설문을 비교. 변경 시 작성 결과 무효화, 실패·빈 설정·중복 클릭 차단 |
| `Web/registration_input.py` | 설문 형식·필수 관계 검사, 설문 내용 해시인 `survey_revision` 계산·비교 |
| `Web/app.py` | 작성 버전과 설문이 일치하는 등록만 처리. 직접 세션 ID를 전달하지 않고 저장·모델 접수 부분 실패를 응답 |
| `Server/registration/app.py` | UUID4 생성·독점 폴더 생성으로 기존 인물 덮어쓰기 방지. 클라이언트 ID 지정 거부 |
| 검사·인계 | `Web/tests`를 `platform`/`all` 검사에 포함. 플랫폼 배포 묶음·팀원 인계에도 새 모듈·검사·문서를 포함 |

웹의 `/persona` 응답은 `persona`, `knowledge`, `survey_revision`을 제공한다.
`/publish`와 `/publish_direct`는 최종 `persona`, `knowledge`, `survey`, `survey_revision` 및 해당 참조 음성을 받는다.
설문 변경 후 이전 버전으로 등록하거나, 작성 버전 없이 등록하거나, 인물이 비어 있으면 400으로 거부한다.
설문 버전은 입력 일치 검사이며 별도의 인증 토큰은 아니다. 인물 텍스트의 수동 편집은 허용한다.

등록 API `/session/start`는 `session`을 보내지 않거나 비워 두면 32자리 UUID4 hex ID를 발급한다.
비어 있지 않은 `session`은 400으로 거부한다. 호출자는 응답의 `session`을 저장하여 이후 조회·모델 업로드·종료에 사용한다.
기존 ID의 조회와 이미 선택한 현재 인물은 유지한다. 인물 조회 API의 `schema_version`, `revision`, 참조 음성 해시 계약은 유지한다.

인물 등록 후 설문 DB 저장이나 모델 접수가 실패하면 `survey_saved`, `model_queued`, `registration_warning`으로 구분한다.
완료 화면에 부분 실패를 알리고, 접수하지 못한 모델을 생성 중이라고 안내하지 않는다.
이 처리는 두 서비스의 저장을 하나의 트랜잭션으로 만드는 것은 아니다. 새 등록을 기존 인물 수정에 사용하는 경로는 제공하지 않는다.

## 후속 논의로 남긴 항목

사용자가 요청한 1~3번은 적용했고, 4번의 관계별 말투·이름 예문은 아직 수정하지 않았다.
`Web/persona.py`는 모든 관계에 반말 지시를 넣으며 미분류 관계는 또래로 처리한다.
또한 사용자 이름이 캐릭터의 자기소개처럼 읽힐 수 있는 예문에 들어간다.
관계에 따른 말투와 실제 호칭을 어떻게 입력받을지 정한 뒤 별도 변경·답변 평가를 진행한다.
이번 검사는 이 두 문제의 실제 Gemma 답변 발생 빈도를 측정한 결과가 아니다.
