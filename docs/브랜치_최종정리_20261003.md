# hj·jw 비교와 main 반영 검증

기준일: 2026-10-03. 사용자 요청에 따라 로컬 변경을 정리하고 `hj`를 원격에 올린 뒤,
`jw`와 `main`의 기존 작업을 모두 포함하는지 확인한 버전을 `main`에 반영한다.
서버는 [보관 상태](프로젝트_보관_재시작_20261003.md)를 유지한다.

## 1. 원격을 갱신한 뒤 비교한 기준

| 대상 | 비교 시점 커밋 | 로컬 hj와의 관계 |
|---|---|---|
| 로컬 `hj` | `35790c65` | 문서 최신화·서버 보관 도구까지 포함 |
| `origin/hj` | `0d41f937` | 로컬에 미푸시 커밋 2개 |
| `origin/jw` | `b9151359` | hj가 모든 커밋을 포함하고 13개 앞섬. jw에만 있는 커밋 0개 |
| `origin/main` | `9b4215f5` | hj가 모든 커밋을 포함하고 319개 앞섬. main에만 있는 커밋 0개 |

`git fetch origin` 후 `git rev-list --left-right --count origin/jw...hj`는 `0 13`,
`origin/main...hj`는 `0 319`였다. 이 수치는 이번 설정 정리 커밋을 추가하기 전 기준이다.
커밋 날짜만 비교하지 않고 실제 조상 관계와 코드 차이를 확인했다.

현재 `hj`에는 `jw`의 Scene_2 입장·경로·인사·고정 몸체 애니메이션 변경이 모두 있다.
여기에 머리 생성 전용 경로 정리, Blender 결합 수정, Tripo 일시 오류 재시도,
밝은 피부 절단 보정, 최신 문서와 서버 보관·재시작 도구가 더해져 있다.
`jw` 이후 Unity 기능 소스·씬·패키지가 추가로 달라진 부분은 없으며, 이번에는 미커밋 애니메이션 메타데이터를 확정한다.

## 2. 정리한 로컬 변경

`Assets/Models/use_animation/`의 `Idle.fbx.meta`, `Standing Greeting.fbx.meta`, `Walking.fbx.meta`에
비어 있던 `humanDescription.human`과 `skeleton` 배열이 채워져 있었다.
이전에 보관 작업에서 제외했던 변경이며, 이번 요청에서 검증한 뒤 커밋한다.

- 3개 파일의 기존 GUID, 애니메이션 형식, 클립 설정은 유지했다.
- 각 파일의 Humanoid 본 52개, 스켈레톤 항목 61개, Humanoid 클립 1개를 Unity에서 확인했다.
- 3개 Avatar 모두 `isValid=true`, `isHuman=true`다.
- 빈 `parentName` 뒤 공백만 정리했다. 새 동작이나 리깅 방식을 추가하지 않았다.
- 검증용 임시 Editor 스크립트와 `.meta`는 실행 후 제거했다. 검사 산출물은 Git 제외 경로에 보관한다.

## 3. 검증 결과와 범위

Unity MCP에 열린 Editor가 없어 설치된 **Unity 2022.3.62f2**를 배치 모드로 실행했다.
검사 프로젝트 경로는 `Capstone-Design`, 활성 대상은 `StandaloneWindows64`였다.

| 검사 | 결과 |
|---|---|
| Unity 스크립트 컴파일 | 성공, 컴파일 오류 0개 |
| 변경 애니메이션 3개 임포트 | 유효한 Humanoid Avatar·클립 확인 |
| 고정 몸체 FBX·GLB | 동작 14개 검사 통과, 재시도·복구·초기 Idle 검사 통과 |

| Build Settings | 활성 Scene_1·Scene_2 파일 존재 확인 |

전체 모의 검사 이후 Python·웹 제품 코드는 바뀌지 않았다. 같은 검사를 중복 실행하지 않았으며,
이번에는 새로 커밋할 Unity 메타데이터에 맞춰 실제 Unity 검사를 실행했다.

기존 경고: `HeadPreviewWindow.cs:201`의 `Focus()`가 `EditorWindow.Focus()`를 가린다는 `CS0108` 1종.
해당 파일은 이번에 수정하지 않았고 이 경고는 컴파일을 막지 않는다.

## 4. 반영 방식

검증한 설정·기록을 `hj`에 커밋하고 기존 미푸시 커밋과 함께 원격에 보낸다.
그 `hj`의 커밋을 `main`에 **fast-forward**로 반영한다. `main`의 기존 이력은 모두 보존하며 강제 푸시는 쓰지 않는다.
마지막으로 원격 `hj`와 `main`의 커밋이 같은지 확인한다. `jw`는 비교 기준으로 유지한다.
서버 비공개 프로필·자료·백업과 로컬 검사 결과는 푸시 대상에 포함하지 않는다.
