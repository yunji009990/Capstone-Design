# 전이중 대화 타당성 조사 (2026-08-02)

**결론: 지금 가진 모델로는 못 한다.** 21B 는 오디오 인코더가 실시간용으로 학습되지
않았고, 크래프톤이 낸 전이중 전용 모델은 **한국어를 알아듣고 한국어 텍스트도 쓰지만,
음성으로 대화할 때만 영어로 답한다.**

다만 두 가지를 확인했다.

1. **전이중 스택 자체가 이 서버에서 돌아간다.** 턴 넘기기, 침묵/발화 전환, 맞장구
   토큰, 화자 조건부까지 실제로 동작했다.
2. **크래프톤 코드베이스는 한국어 전이중을 설계에 넣어뒀다** — 한국어 시스템 프롬프트
   4개가 실재하고 타입 힌트가 `Literal["eng", "kor"]` 이다(§3). 공개된 이 체크포인트에
   학습이 안 들어갔을 뿐이다.

**한국어판이 나오면 그날 붙일 수 있다.** §4 의 함정 넷만 다시 밟으면 된다.

## 재조사 (2026-09-09) — 판이 바뀌었다

**이 문서의 결론 하나가 틀렸다.** 「S2S 는 임의 화자 복제가 설계상 막힌다」는
`voice_clone_studio/음성대화_아키텍처_비교.md` 의 판단인데, **지금은 아니다.**

### 뒤집힌 것 — S2S 도 목소리를 복제한다

**Qwen3.5-Omni** 가 한다. 기술보고서 기준 29개 언어에 화자 특성을 옮기고
**한국어 WER 1.309** 다. 「프리셋 목소리만 된다」는 전제가 깨졌다.

**다만 우리가 못 쓴다 — 공개 가중치가 없다.**

| | 목소리 복제 | 로컬 | 한국어 |
|---|---|---|---|
| `Qwen/Qwen3-Omni-30B-A3B-Instruct` (공개) | ❌ **프리셋 셋뿐** (Aiden·Chelsie·Ethan) | ⭕ | ⭕ |
| `qwen3.5-omni-plus` / `-flash` | ⭕ | ❌ **알리바바 클라우드 API 전용** | ⭕ |

공개판은 `model.generate(..., speaker="Chelsie")` 로 **이름을 고르는 방식**이고
참조 음성을 넣을 자리가 없다. 우리 제품의 전부가 「고인의 목소리」라 그대로는 못 쓴다.
되는 판은 **등록된 실존 인물의 음성을 남의 서버로 보내야 한다.** `sessions/` 를
커밋조차 안 하는 프로젝트에서 택할 수 없다.

**그러니 「불가」가 아니라 「공개판 대기」다.** 알리바바가 3.5-Omni 가중치를 열면
그날 다시 본다. Qwen 은 지금까지 계속 열어 왔다.

### 맥락을 보는 TTS 도 시험했다 — MOSS-TTS-Realtime, 기각

S2S 로 못 가는 대신 **중간 길**을 재봤다. 생각은 LLM 이 하되, 읽어주는 모델이
앞 대화(글+소리)를 보고 억양을 정하는 것.

`OpenMOSS-Team/MOSS-TTS-Realtime` — Apache 2.0, 1.7B, 4.4GB, 한국어 포함,
대화 음성 100만 시간 학습. **방향은 정확히 맞았는데 한국어가 무너진다.**

```
기대   "밥은 먹었어? 굶지 말고 챙겨 먹어."
받음   "밥은 먹었어?  그것은 씨발이 없고요.  개껴먹어."      (조혜정 통짜)
       "밥은 먹었어?  결혼식 받았고요.  치켜버거."          (조혜정 자른것)
       "밥은 먹었어.  그 후식 바로 끄요.  그 후식"          (사용자)
```

**CER 0.77, 참조 셋 공통.** 설정 문제가 아니다. 여섯 자 문장이 27.44초로
늘어난 칸도 있었고(글자는 맞음), 청취 판정은 「음높이가 이상하게 변한다,
합성음 티가 난다」였다. **욕설이 나온 것이 결정적이다** — 고인의 목소리로
말하는 제품에서 이건 품질 문제가 아니다.

속도·크기는 좋았다(RTF 0.26, 4.4GB). 한국어 판이 나아지면 다시 볼 것.

### 이 갈래에서 실제로 쓸 수 있는 API

MOSS 를 붙이며 알아낸 것. 다시 시도할 때 여기서 시작한다.

```python
session.reset_turn(user_text=..., user_audio_tokens=...,
                   include_system_prompt=(i==0), reset_cache=(i==0))
```

- **맥락 없이는 아예 못 돈다.** `user_text` 와 `user_audio_tokens` 가 **필수**다.
  빼면 `ValueError`. 문장만 주고 읽어달라는 호출이 안 된다
- 턴을 넘길 때 KV 캐시를 유지해 앞 대화가 쌓인다
- 우리 제품은 마이크 소리를 이미 갖고 있으므로 이 요구가 오히려 잘 맞는다
- `transformers==5.0.0` 이어야 한다. 5.16 은 `safetensors` 판이 어긋난다
- 첫 호출 36초는 **예열**이다. 이후 1초대

### 시험 설계에서 두 번 실패했다 — 되풀이하지 말 것

**① 사람 쪽 글과 소리를 짝 안 맞춤.** 사람 발화 소리를 아무거나 빌려 써서
「예전에 뭐 했는지 기억나?」라는 글에 「응, 나도 방금 일어났어」 소리를 넣었다.
하필 그 자리가 맥락을 읽는 자리라 시험 전체가 무효였다.

**② 사람 목소리를 할머니 목소리로 넣음.** 혼자 자문자답하는 꼴이 됐다.
화자 임베딩으로 재니 고친 뒤는 코사인 0.07~0.19(다른 사람)로 갈렸다.

**맥락형 모델을 시험할 때는 사람 쪽 입력부터 검증할 것.** Whisper 로 받아적어
글과 대조하고, 화자 임베딩으로 두 목소리가 갈리는지 본다. `tools/` 에 없으면
이 문서의 절차를 다시 짜야 한다.

### 그래서 다음은

전이중·S2S 를 더 팔 때 **여기서 시작한다.**

| 볼 것 | 지금 상태 |
|---|---|
| Qwen3.5-Omni 공개 가중치 | **없음.** 나오면 1순위 |
| MOSS 한국어 개선판 | CER 0.77 로 기각. 갱신되면 다시 |
| 바지인 (§6 B안) | 아직 안 함. S2S 없이도 되는 체감 개선 |
| 문장 단위 TTS 의 어색함 | **못 고침**(아래) |

## 1. 왜 하려 했나

지금은 **무전기**다. 사용자가 말하고 → 0.5초 조용하면 → 전송 → 답이 오고 → 그동안
사용자는 말을 못 한다. 반이중이다.

전이중은 **전화**다. 동시에 말할 수 있고, 상대 말 중간에 끊고 들어갈 수 있고,
"응", "그렇구나" 같은 맞장구가 들어간다.

현재 구조에서 전이중을 막는 것은 넷이었다.

| | 위치 |
|---|---|
| HTTP 단발 요청/응답 — 양방향 동시 스트림 불가 | `RaonVoiceClient.cs:390` |
| 서버 `LOCK` 이 모든 추론을 직렬화 | `Server/app.py:34` |
| 모델이 순차 파이프라인 (STT→LLM→TTS) | `Server/app.py:339-346` |
| **재생 중 마이크 판정을 의도적으로 끔** (에코 방지) | `RaonVoiceClient.cs:213` |

## 2. 21B (`A.X-K2-Raon-Speech`) — 코드는 있는데 귀가 안 맞는다

### 있는 것

`modeling_raon.py` 에 전이중 추론 스택이 통째로 들어 있다.

```
 588~714  DuplexInputs · DuplexPhase · DuplexMachineState · DuplexStateManager
 6779     compile_audio_modules(duplex: bool = True, ...)
 7065     duplex_decoding_step        ← 프레임 단위 디코딩
 7232     init_duplex_decoding_state
 9357     class RaonDuplexModel(RaonModel)
10821     RaonPipeline.duplex(...)
11426     run_duplex_inference(...)
```

**`RaonDuplexModel` 은 순수 별칭이다** — 본문이 `config_class = RaonDuplexConfig` 한 줄
뿐이고 새 모듈이 없다. 즉 duplex 메서드는 전부 `RaonModel` 에 있고, 별도 가중치가
필요 없다.

**음성 복제도 배선돼 있다.** `duplex(speaker_audio=...)` 에 참조 wav 경로만 주면
`_compute_speaker_embeds` 가 ECAPA-TDNN 임베딩을 뽑아 디코딩 초기 상태에 넣는다.

### 뚫은 순서

1. **`spawn` 재귀** — `init_duplex_decoding_state` 가 오디오 디코더를 별도 프로세스로
   띄운다. 자식이 스크립트를 다시 import 하므로 본문을 `if __name__ == "__main__":`
   안에 넣어야 한다.
2. **`pidfd_getfd: Operation not permitted`** — 자식이 부모의 CUDA 메모리에 붙으려다
   `ptrace_scope=1` 에 막힌다. **`PYTORCH_CUDA_ALLOC_CONF=expandable_segments:False`**
   로 옛 CUDA IPC 경로를 쓰면 우회된다. sudo 불필요.
3. **`NotImplementedError: requires a causal audio encoder`** — `aut_is_causal` 이
   `false`. 원본을 안 건드리려고 심볼릭 링크 변형 디렉터리(`~/models/raon-causal`,
   92KB)를 만들어 `config.json` 만 `true` 로 바꿨다.
4. **`assert isinstance(updated_state, AuTStreamingState)`** — **배포 코드의 버그.**
   `AuTWrapper.forward` 의 스트리밍 경로가 상태를 새로 만들어놓고 **반환문 두 곳에서
   `streaming_state=` 를 빼먹었다.** 독스트링은 반환한다고 적혀 있다. 두 줄 추가로 수정.

### 그래서 돌았지만

139프레임 완주, 9.18 프레임/초, 사용자 오디오와 **겹치는** 답변 생성. 구조는 동작했다.
그런데 내용이 `'a'`, `'2'`, `' and'`, `'는'` 같은 무작위 토큰이었고, 사용자 청취 판정은
"이상한 언어"였다.

### 원인 — 인과 인코더가 학습되지 않았다

전이중과 무관한 **단순 음성 인식**으로 단일 변수 시험을 했다.

| 설정 | 같은 오디오 전사 결과 |
|---|---|
| `aut_is_causal=False` (원본) | `앞머리를 자르고 뒷머리도 자를까 기장을 조금만 자를까 하다가 이제 딱 레슨 가기 전에...` |
| `aut_is_causal=True` | `아 진짜?` (3스텝 만에 종료) |

인과 마스크를 씌우는 순간 **모델이 소리를 못 알아듣는다.** 전이중이 깨진 게 아니라
그 앞단에서 이미 귀가 멀어 있었다. 설정이나 코드로 못 고친다 — 학습 시점에 정해진 것이다.

## 3. `Raon-SpeechChat-9B` — 전이중은 완벽, 한국어는 애초에 영어 전용이다

크래프톤이 낸 전이중 전용 체크포인트. 19.5GB, 파일 20개.
**모델 카드가 영어 전용이라고 명시한다**(2026-08-26 확인). 우리 실측과 같다.
[HF](https://huggingface.co/KRAFTON/Raon-SpeechChat-9B) ·
[기술보고서](https://arxiv.org/abs/2605.23912)

### 21B 와 뒤집힌 것들

| 항목 | 21B | SpeechChat-9B |
|---|---|---|
| `model_type` | `raon` | **`raon_duplex`** |
| `architectures` | `RaonModel` | **`RaonDuplexModel`** |
| `aut_is_causal` | `false` | **`true`** |
| `use_duplex_end_pad` / `use_sil_token` | `false` / — | **`true` / `true`** |
| `duplex_sil_token_id` | `-1` (꺼짐) | **151672** |
| `duplex_bc_token_id` (맞장구) | `-1` (꺼짐) | **151673** |
| 오디오 인코더 | `qwen3_omni_moe_audio_encoder` (AuT) | **`voxtral_realtime_encoder`** |

인코더가 아예 다르다. 처음부터 실시간용으로 만든 것을 쓴다. 그래서 §2 의 `AuTWrapper`
버그는 이 모델에 해당 없다 — 다른 경로를 탄다.

### 실제 동작

```
Duplex Generation: 100%|██████████| 239/239 [00:23<00:00, 10.27it/s]
[상태] 침묵 141프레임 / 발화 98프레임
[말한 것] '<|audio_output_backchannel|> yeah B option better! ...
           <|audio_output_backchannel|> mmhmm It was wild though ...'
```

- 사용자가 말하는 동안 **침묵**, 끝나자 **발화** — 턴 넘기기가 된다
- **맞장구 토큰이 실제로 발동한다** ("yeah", "mmhmm")
- `speaker_audio` 통과 — 음성 복제 배선 정상

### 한국어 — 알아듣지만 말하지 못한다

**이해는 완벽하다.** 같은 한국어 오디오를 전사시켰더니 내용이 정확히 대응했다.

| 원문 | 9B 출력 |
|---|---|
| 앞머리 / 자를까 / 조금만 / 레슨 끝나고 / 미용실 | bangs / will you cut / a little / after the last class / hair salon |

**출력은 영어로 고정이다. 일곱 번 시도해 한글 0자다.**

**공식 문서에도 영어라고 명시돼 있다** — 모델 카드가
`enables real-time, simultaneous listen-and-speak conversation in English` 라고 적는다.
2026-08-26 확인 시점까지 한국어판은 없고 계획 언급도 없다. **즉 우리가 설정을 잘못
준 것이 아니다.** 아래 일곱 번은 그 사실을 실측으로 확인한 기록이지, 설정을 더
뒤져 볼 여지가 남았다는 뜻이 아니다.

| 시도 | 경로 | 결과 |
|---|---|---|
| 기본 영어 프롬프트 | 전이중 | 한글 0 / 영문 125자 |
| 임의로 만든 한국어 강제 프롬프트 | 전이중 | 한글 0 / 영문 156자 |
| **`kor:full_duplex:listen-first`** (학습 때 쓴 문장) | 전이중 | 한글 0 / 영문 159자 |
| **`kor:duplex_instruct:listen-first`** (학습 때 쓴 문장) | 전이중 | 한글 0 / 영문 125자 |
| 기본 | STT | 영어 |
| "한국어로 그대로 받아써" | STT | 영어 + 반복 루프 (`Will I cut my hair short?` ×8) |
| "원어 그대로, 번역 금지" | STT | 영어 + 반복 루프 (`Okay?` ×26) |

### 대조군 — 영어로는 완벽하게 동작한다

한국어가 안 된 것이 **우리 설정 탓이 아님**을 증명해야 했다. 크래프톤이 저장소에 올린
공식 평가 샘플(`data/duplex/eval/audio/duplex_00.wav`, 메타데이터 `{"speak_first": false,
"language": "eng"}`)을 그대로 넣었다. 오디오·참조·프롬프트 전부 크래프톤 것이다.

```
' Yeah? What's up?  oh  Really? Like what?  right  Thanks
  Just got back from the mall today  mmhmm  You're making me blush over here
  Let's go out sometime  The new dress? Yeah! I was nervous about wearing it to work.'
```

침묵 179 / 발화 278 프레임. **자연스러운 영어 대화에 맞장구까지 정상**이고, 청취로
텍스트와 소리가 일치함을 확인했다. 입력은 1채널 모노라 채널 혼합 문제도 없다.

**즉 모델도 우리 절차도 정상이다.** 아래의 한국어 실패는 전부 유효한 측정이다.

(첫 실행에서 `���야, �� 오늘 ���— 어? 그—` 같은 깨진 한글이 잠깐 섞여 나왔다. 프레임
단위로 디코딩하는 로그 특성상 3바이트짜리 한글이 프레임에 걸쳐 잘려 그렇게 보인 것이고,
토크나이저는 정상이다 — 한국어 왕복 13토큰 정확 복원, `fix_mistral_regex` 유무 무관.
다만 **모델의 출력 분포에 한국어가 남아 있다**는 방증이기는 하다.)

### 어느 경로가 막혔나 — 모달리티별로 갈린다

"한국어를 못 한다"가 아니다. **텍스트는 되고 음성이 안 된다.**

| 경로 | 한국어 | 근거 |
|---|---|---|
| 이해 (음성 → 내용) | **된다** | 전사 내용이 원문과 정확히 대응 (앞머리→bangs, 레슨 끝나고→after the last class) |
| **텍스트 → 텍스트** | **된다** | `"안녕? 오늘 뭐 했어?"` → `"안녕! 오늘은 그냥 집에서 책 읽고, 저녁에 친구들과 커피 마시며 시간 보냈어."` |
| 텍스트 → 음성 (`tts()`) | **측정 못 함** | 영어·한국어 × 참조 유무 4조건 모두 깨진 소리. **`tts()` 는 21B 에서도 원래 고장나 있다**(`Raon모델_분석.md` §5, "계측기로 쓰지 말 것"). 제품이 쓰는 것은 `tts_continuation` 이다. 이 함수로는 한국어 합성 여부를 잴 수 없다 |
| **음성 → 응답** | **안 된다** | 7회 전부 영어. 시스템 프롬프트·사용자 메시지 양쪽에 한국어를 밀어도 영어 |

**LLM 의 한국어 생성 능력은 멀쩡하다.** 텍스트로 물으면 자연스러운 한국어 반말로 답한다.
잠긴 것은 **음성을 입력으로 받았을 때의 응답 언어** 하나다. 음성 대화 학습이 영어로만
된 결과다. 전이중은 입력이 항상 음성이므로 이 벽을 그대로 맞는다.

### 그런데 코드베이스는 한국어를 지원한다

**이 구분이 중요하다.** 모델 폴더만 보면 언어 설정이 없다 — README 에 언어 인자 없음,
`config.json` 에 언어 키 0개, 내장 페르소나 17개 전부 영어. 그래서 처음에 "한국어 지원
자체가 없다"고 결론냈는데 **틀렸다.** 패키지 저장소를 보면 다르다.

`src/raon/utils/duplex_data.py` —

```python
CHANNEL_DUPLEX_TO_SYSTEM_MESSAGE: dict[str, str] = {
    "eng:full_duplex:listen-first":  "You are engaging in real-time conversation.",
    ...
    "kor:full_duplex:speak-first":   "당신은 실시간 대화에 참여하고 있습니다. 먼저 말씀하세요.",
    "kor:full_duplex:listen-first":  "당신은 실시간 대화에 참여하고 있습니다. 먼저 말하지 마세요.",
    "kor:duplex_instruct:speak-first":  "당신은 실시간 대화에 참여하고 있습니다. 먼저 말씀하세요.",
    "kor:duplex_instruct:listen-first": "당신은 사용자와 실시간 대화에 참여하는 어시스턴트입니다. 먼저 말하지 마세요.",
}

def get_duplex_system_message_key(language: Literal["eng", "kor"], ...)
```

한국어 시스템 프롬프트 4개가 실재하고 타입 힌트가 `Literal["eng", "kor"]` 이다.
학습 데이터 형식에도 `language` 필드가 있다(`"Language code (for prompt selection),
e.g. eng, kor."`). 데모의 `prompt_language` 파라미터도 `언어:채널:모드` 키를 받는데,
`if language != "eng": return prompt_text` 로 **영어만 통과시킨다.**

**즉 크래프톤은 한국어 전이중을 설계에 넣어뒀고, 공개한 이 체크포인트에만 학습이
안 들어갔다.** 한국어판이 나올 가능성이 실재한다는 뜻이다.

한국어 전이중 체크포인트는 현재 **없다.** KRAFTON 공개 모델 10개 중 전이중은 이 하나뿐이다.

## 4. 다시 시도할 때 — 함정 넷

한국어판이 나오거나 파인튜닝을 하게 되면 이것들이 그대로 필요하다. **전부 하루치
삽질을 치른 것들이다.**

### ① `transformers` 는 반드시 5.0 미만

**이게 가장 컸다.** 모델 요구는 `>=4.57.1,<5.0` 인데 서버 기본 환경은 **5.14.1** 이었다.
그 상태에서는 Voxtral 스트리밍 상태가 안 넘어가 `Short audio: 6 mel frames < 8 required`
경고와 함께 배치 경로로 빠지고 `encoder_cache is None` 으로 죽는다.
버전을 맞추자 **한 번에 완주했다.**

전용 venv 를 따로 팠다. 서버가 쓰는 `~/venv/raon` 은 건드리지 않았다.

```bash
python3.12 -m venv ~/venv/duplex && source ~/venv/duplex/bin/activate
pip install 'transformers>=4.57.1,<5.0' torch torchaudio soundfile accelerate speechbrain
# 설치 결과: transformers 4.57.6, torch 2.13.0+cu130
```

4.57 에서는 `from_pretrained(dtype=...)` 이 아니라 **`torch_dtype=`** 다. `dtype` 을
쓰면 조용히 무시되어 float32 로 올라간다.

### ② `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:False`

`ptrace_scope=1`(우분투 기본값) 환경에서 필수. 안 주면 오디오 디코더 자식 프로세스가
부모의 CUDA 메모리에 못 붙는다. sudo 없이 해결된다.

### ③ `AutoModel` 로 로드할 것

`RaonPipeline.__init__` 이 `RaonModel.from_pretrained` 를 **하드코딩**한다. duplex
체크포인트를 그걸로 올리면 설정이 어긋나 첫 프레임에서 확률값이 `inf`/`nan` 이 되고
CUDA 가 죽는다. README 도 `AutoModel` 을 안내한다.

`RaonPipeline.__new__` 로 껍데기만 만들고 채우면 된다. `task_params` 는 반드시
`_DEFAULT_TASK_PARAMS` 를 넣을 것 — `{}` 로 두면 생성 설정이 통째로 빠진다.

### ④ 입력 뒤에 무음 꼬리를 붙일 것

`run_duplex_inference` 는 **입력 길이만큼만** 돈다. 사용자 발화만 넣으면 모델이 예의
바르게 기다리다 프레임이 소진돼 끝난다. 대답을 들으려면 뒤에 무음 8초쯤을 붙여야 한다.
(실시간 서버에서는 마이크가 계속 흐르므로 해당 없음.)

### 속도

| | |
|---|---|
| 필요 | **12.5 프레임/초** (프레임당 80ms) |
| 실측 (9B, SDPA) | 9.2~10.3 프레임/초 |
| 문서값 (RTX 6000 Pro) | **RTF 0.27** — 실시간의 3.7배 |

서버 GPU 가 문서와 같은 기종(**RTX PRO 6000 Blackwell, 97887 MiB**)인데 문서값에 크게
못 미친다. **`flash-attn` 미설치**가 유력하다 — 로그에 계속 경고가 떴고 README 도
권장 목록에 넣어뒀다. 다시 시도할 때 먼저 볼 것.

## 5. 서버에 남긴 것

| 경로 | 무엇 | 지워도 되나 |
|---|---|---|
| `~/venv/duplex` | transformers 4.57 전용 환경 | 예 |
| `~/models/Raon-SpeechChat-9B` | 19.5GB. 한국어판 나오면 참고용 | 예 |
| `~/models/raon-causal` | 21B 의 `aut_is_causal=true` 심링크 변형, 92KB | 예 |
| `~/server/duplex_probe.py` | 탐침 스크립트 | 예 |
| `~/server/duplex_out*`, `duplex_out_ko` | 탐침 출력 | 예 |
| **`modeling_raon.py` 2줄 패치** | `AuTWrapper.forward` 반환값 수정 | **§2-4 참고** |

**패치는 무해하다.** `if streaming_state is not None:` 안에 있고 현재 서버는 그 인자를
넘기지 않는다(`causal=`, `audio_lengths=` 만 넘긴다). 실행 경로가 닿지 않는다.
기존 기능 동작은 실측으로 확인했다.

되돌리려면:

```bash
cp ~/models/AX-K2-Raon-Speech/modeling_raon.py.bak_duplex \
   ~/models/AX-K2-Raon-Speech/modeling_raon.py
rm -rf ~/models/raon-causal ~/server/duplex_out* ~/server/duplex_probe.py ~/venv/duplex
```

백업은 두 겹이다 — `~/backup/pre-duplex-modeling_raon.py` 와
`바탕화면\capstone_backup\`(git 번들 + 서버 tgz + 패치 전 모델 파일).
