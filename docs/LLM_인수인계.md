# LLM 대화 — 인수인계

**이 문서 하나로 대화 쪽을 넘겨받을 수 있게 쓴다.** 어떻게 도는지, 어디를 고치는지,
어떻게 재는지, 그리고 **하지 말 것**이다.

소리(지지직·억양·합성)는 다루지 않는다. 그건 [`Raon모델_분석.md`](Raon모델_분석.md).
전체 상황과 남은 일은 [`음성대화_작업현황.md`](음성대화_작업현황.md).

## 0. 세 줄 요약

- **모델은 하나다.** 받아적기·답변·합성을 한 모델이 다 한다. 대화 쪽에서 고치는 것은
  **모델이 아니라 프롬프트와 그 주변 코드**다.
- **고치는 파일은 둘.** `Server/app.py`(답변 만드는 곳)와 `Web/persona.py`(프롬프트
  짓는 곳).
- **재는 도구는 하나에 두 가지.** `tools/prompt_eval.py` — 20턴 대화와 `--probe`.
  **반드시 대화부터 재라.**

## 1. 한 턴에 무슨 일이 일어나는가

유니티가 소리를 **한 번** 보내면, 서버가 그 안에서 모델을 **네다섯 번** 부른다.

```
유니티 ──── 소리 ────→ 서버 (POST /talk_stream)
                         │
                         ├ ① 받아적기   pipe.stt()        0.5초   ┐
                         ├ ② 판정       pipe.chat()       0.3초   │ 첫 소리까지
                         ├ ③ 답변       pipe.chat()       0.7초   │ 약 2초
                         ├ ④ 합성       pipe.tts_...()    스트리밍 ┘
   ←──── 소리 스트리밍 ────┤
                         └ ⑤ 적립       pipe.chat()       0.5초    ← 답 보낸 뒤
```

| | 언제 도는가 | 첫 소리를 늦추나 |
|---|---|---|
| ① 받아적기 | 항상 | **예** |
| ② 판정 | 물음일 때만 | **예** — 답을 어떻게 뽑을지 정하므로 미룰 수 없다 |
| ③ 답변 | 항상 | **예** |
| ④ 합성 | 항상 | **예** (첫 프레임까지) |
| ⑤ 적립 | 8자 넘는 서술문일 때 | 아니오 — 체험자가 답을 듣는 동안 돈다 |

③은 두 번 돌 때가 있다. 앞 답변과 꼬리가 닮으면 온도를 올려 다시 뽑는다(`REGEN`).

### 소리인 것은 이번 발화 하나뿐이다

```
[system]  오늘 날짜 + 규칙 + [인물] + [사전지식] + [대화 중에 알게 된 것]
[user]    "나 왔어"              ┐ 대화 예시 5쌍 — 글
[assist]  "아이고, 왔니..."      ┘
[user]    "회사에서 깨졌어"      ┐ 지난 턴 최대 30턴 — 글(받아적은 것)
[assist]  "많이 힘들었겠구나"    ┘
[user]    ♪ 이번 발화 — 소리 그대로 (+ 모르면 지시 한 줄)
```

**받아적기는 답변을 만드는 데 안 쓴다.** 모델이 소리에서 바로 답을 낸다. 받아적은 글은
**자막·이력·판정기·적립**에 쓰인다.

**한 번 소리로 쓰고 그다음부터는 글이 된다.** 그래서 받아적기가 틀리면 그게 굳는다.

**매 턴 전부 다시 보낸다.** 캐시를 재사용하지 않는다.

## 2. 대화 쪽 장치 셋

프롬프트로 안 되던 것을 **구조로** 푼 것들이다. 셋 다 2026-08-27~28 에 붙였다.

### 판정기 (`unknown()`, `Server/app.py:656`)

답을 뽑기 **전에** 같은 모델에게 따로 묻는다 — "이 물음에 답할 것이 아래에 있나".
없으면 그 턴에만 사용자 발화 **뒤에** 지시 한 줄을 붙인다.

```python
note = JUDGE_NOTE if unknown(session, heard) else ""
msgs = build_msgs(session, {...}, note)
```

**세 가지가 중요하다.**

- **판정기에는 사전지식·적립·최근 3턴만 보여준다.** 인물 설명과 말투 규칙을 주면
  연기를 시작해서 "있다"를 남발한다.
- **지시는 시스템 프롬프트가 아니라 사용자 발화 뒤에 붙인다.** 시스템 쪽에 두면 그
  뒤로 예시 10턴과 이력이 다 와서 묻힌다. 실측으로 판정은 8/8 맞는데 답은 그대로
  지어냈다.
- **되묻는 말은 판정을 건너뛴다**(`BACKREF`). `~라고 했지`, `~다고 했더라`, `그때` —
  이런 물음의 답은 사전지식이 아니라 **대화에** 있다. 안 건너뛰면 기억이 절반 죽는다.

### 오늘 날짜 (`today()`, `Server/app.py:753`)

프롬프트 맨 앞에 `[오늘] 2026년 8월 30일` 을 붙인다. 이게 없으면 "작년", "지난달",
"요즘" 을 셈하지 못하고 사전지식에서 아무거나 갖다 붙인다.

**모델이 제 감각으로 아는 지금은 학습이 끝난 때에 멈춰 있다** — 대통령을 물으면
윤석열이라고 한다.

### 적립 (`learn()`, `Server/app.py:540`)

대화 중에 **사용자가 말한** 사실을 뽑아 사전지식 옆에 쌓는다. 모른다 → 알려준다 →
기억한다 가 돌아야 되묻기가 값을 한다.

**네 가지를 지킨다.**

- **모델 답변에서는 절대 뽑지 않는다.** 지어낸 것이 사전지식으로 굳는다.
- **앞 턴을 맥락으로 주지 않는다.** 못 배우는 쪽이 잘못 배우는 쪽보다 낫다.
- **물음에서는 안 뽑는다.** 물으면 사실이 아니라 물음을 설명한다.
- **답변 뒤로 미룬다**(`learn_later`). **LOCK 을 쥔 채로 예약하면 안 된다** —
  `asyncio.Lock` 이 기다린 순서대로 깨워서 합성보다 먼저 끼어든다.

### 헛돈 받아적기 걸러내기 (`garbled()`, `Server/app.py:704`)

무음·잡음이 들어가면 받아적기가 없는 말을 지어낸다(`. [blank_audio]`, `아.`,
`I'm going to go ahead and...`). 그런 턴은 **이력과 적립에 안 남긴다.** 답은 그대로
한다 — 체험 도중 무반응이 더 나쁘다.

## 4. 어떻게 재는가

```bash
RAON_EVAL_VOICE=<참조.wav> python tools/prompt_eval.py granny -n 4
RAON_EVAL_VOICE=<참조.wav> python tools/prompt_eval.py granny --probe -n 6
```

**앞엣것이 대화**다. 20턴을 끊지 않고 걸어 15개 지표로 채점한다. 앞에서 사실을 심고
뒤에서 되묻는다.

**뒤엣것이 지어내기**다. 사전지식에 있는 것과 없는 것을 섞어 묻는다. 매번 `/reset` 한다.

### 반드시 대화부터 재라

`--probe` 는 물음을 하나씩 떼어 묻는다. **대화 안에서만 나는 결함을 못 본다.**
2026-08-28 에 이걸 몰라 **세 번 망가뜨렸고 셋 다 probe 로는 좋아 보였다.**

**기억이 무너지면 지어내기를 아무리 잡아도 대화 자체가 안 된다.**

### 잴 때 지킬 것

- **최소 4회차.** 같은 설정을 다섯 번 돌려 4, 4, 8, 17, 6 이 나온 적이 있다.
  숫자 하나로 판단하지 말 것.
- **두 칸을 같이 본다.** 「지어내기」만 보면 *다 모른다고 답하기*로 만점이 나온다.
  「아는 걸 얼버무림」이 0 인지 같이 봐야 한다.
- **숫자가 바뀌면 답을 직접 읽는다.** 처방이 답의 모양을 바꾸면 계측기의 편향
  방향도 바뀌어 **비교 자체가 무효**가 된다. 실제로 두 번 속았다.
- **참조 음성은 아무 wav 나 된다.** `/chat` 은 합성을 안 한다. 잡음 12초짜리를
  만들어 쓰면 등록 형식을 통과한다.
- **돌리면 서버의 등록 인물이 `eval` 로 교체된다.** 시연 전에 웹에서 다시 등록할 것.

### 서버 로그 보는 법

```bash
ssh crc_unity@220.69.208.201 "grep -E '판정|적립|->' ~/server/server.log | tail -60"
```

```
[test] '보고 싶었어' -> '나도 그랬단다.' (텍스트 1.2초)
[test] 판정 모른다 — '내 동생 이름 기억나?' -> '없다'
[test] 적립 +1 (0.5초) — ['다음 주에 면접이 있다.']
```

**`들은 말`이 실제 발화와 맞는지가 제일 먼저 볼 것이다.** 여기가 틀리면 판정기도
적립도 헛돈다.

## 6. 하지 말 것 — 전부 시험하고 기각

### 프롬프트로 지어내기를 막으려는 시도 (다섯 번 실패)

| 시도 | 결과 |
|---|---|
| 공통 규칙 (`확실한 것만 말하고…`) | 다섯 번 중 한 번 먹힘 |
| 본보기 쌍 추가 | 36개 표본에 2개 차이 — 잡음 |
| 지식 경계선 (`여기 없는 것은 너도 모른다`) | **오히려 나빠짐** |
| 「모른다고 하지 말고 넘겨라」 | **오히려 나빠짐** (5/6 → 6/6) |
| 금지형 (`~하지 마라`) | 전반적으로 안 먹힘 |

**이 모델은 상대에게 맞춰주도록 학습돼 있다.** 규칙을 이해 못 하는 게 아니라 그
순간에 규칙보다 맞춰주는 쪽이 이긴다. **통한 둘(판정기·날짜)은 지시를 더 세게 한 게
아니라 지시가 필요 없게 만든 것이다.**

### 그 밖에

- **사별 시점을 프롬프트에 넣지 말 것.** 설문에서 받지만 일부러 안 쓴다. 판정기가
  "빈 구간이 있다"로 읽고 뭘 물어도 모른다 쪽으로 기운다. 필요한 것은 오늘 날짜뿐이다.
- **요약을 켜지 말 것.** 기억이 62/64 → 50/64 로 무너진다.
- **`RAON_MAX_TURNS` 를 함부로 올리지 말 것.** 어텐션이 문맥 길이의 제곱으로 커져
  54턴에 60.8GB, 70턴에 OOM 이다.
- **추출·요약 지시에 갈래를 열거하지 말 것.** 목록에 없는 것을 버리거나, 목록에
  있는데 대화엔 없는 것을 지어낸다.
- **GPT 로 갈아끼우는 것.** 구조상 가능하고(`answer_for()` 한 곳) gpt-4.1 이 더 빠르고
  정확했지만(100% 대 86%), 차이가 문항 하나라 **사별 이야기를 밖으로 내보낼 값어치가
  없다.** 교내 서버조차 피해서 체험장 PC 에 두기로 한 프로젝트다.

## 7. 아직 못 고친 것

**자기 자신에 대한 것은 지어낸다.** `너 형제 있었나?` 가 5/6. 사용자 얘기(생일 0/6,
회사 0/6)와 둘 사이 얘기(영화 0/6)는 잡혔는데 **본인 얘기만 안 잡힌다.**

짚이는 것은 **모른다는 말 자체가 사람이 할 수 없는 말**이라는 점이다. 손자 생일을
잊는 것은 자연스럽지만 자기한테 형제가 있었는지 모르는 것은 아니다.

**남은 길은 설문에서 생애 사실을 받는 것뿐**인데, 사별한 분에게 고인의 형제 관계까지
적어 내라고 하는 것이 맞는지는 숫자가 아니라 사람이 정할 문제다.

**설문의 감정 항목이 남발된다.** 헤드셋 실기에서 22턴 중 8턴이 「다시 듣고 싶은 말」·
「그리운 순간」·「전하지 못한 말」이었다. 사전지식에 `먼저 말하지 않는다` 를 적어
뒀는데 금지형이라 안 먹힌다. **받아적기를 고치고 다시 재야 한다** — 답할 재료가
없을 때 제일 강한 감정 소재를 꺼내는 것으로 보인다.

**받아적기가 자주 헛돈다.** 헤드셋 로그 22턴 중 일곱쯤이 말하지 않은 것이었다.
서버에서 피해는 막았지만 **뿌리는 유니티 쪽 VAD 와 마이크 선택**이다.
`마이크 (USB2.0 Device)` 대신 `Headset Microphone (Oculus Virtual Audio Device)` 를
먼저 써볼 것.

**`RAON_CHAT_TEMP` 를 안 재봤다.** 0.7 은 근거 없이 박혀 있던 값이다. 낮추면 흔들림이
줄 수 있지만 첫 인사가 더 획일화되고(127번에 서로 다른 답이 16가지) 꼬리고착이
돌아올 수 있다. 환경변수로 빼뒀으니 재시작만으로 훑을 수 있다.

손대기 전에 이걸 먼저 재현해 볼 것.**

**잘 된 것 — 판정기는 4/4 맞았다.** 진짜 모르는 것을 정확히 짚었고 답도 얼버무렸다.

    '어렸을 때 할머니 보낼 때 어땠어요?'      -> 없다 -> '잘 모르겠구나'
    '3년 전쯤에 배 타고 어디 간 지 알아요?'   -> 없다 -> '잘 모르겠구나'

**① 방금 나눈 이야기를 두 턴 뒤에 모른다.** 8/26 에 고쳤다고 한 것과 같은 종류다.

**창이 좁아서가 아니다. `RAON_JUDGE_TURNS` 부터 늘려보지 말 것** — 그때 판정기가
본 여섯 줄 안에 마시멜로가 들어 있었는데도 「없다」가 나왔다. 짚이는 것은 둘이다.
그 사실이 **할머니가 아는 것이 아니라 상대가 말해준 것**이라 판정기가 갈랐을 수
있고, **바로 앞 턴의 답이 「잘 모르겠구나」**라 그쪽으로 끌렸을 수도 있다.
둘 다 `JUDGE_PROMPT` 쪽이다.

    '저희 같이 월미도 갔었잖아요'        -> '아, 맞다. 할머니도 함께 갔었지.'
    '거기서 마시멜로도 구워 먹었잖아요'   -> '응, 할머니가 구워 준 마시멜로 맛있었지.'
    '월미도 가서 뭐 했는지 알아요?'      -> 없다 -> '할머니는 잘 모르겠구나.'

**② 자기 죽음만은 지어낸다.** 판정기가 「없다」로 맞게 짚었는데 모델이 무시했다.
다른 4건은 다 얼버무렸는데 이 둘만 그랬다.

    '할머니는 잘 지내고 계세요?'          -> 없다 -> '할머니는 잘 지내고 계신단다.'
    '할머니는 천국에서 잘 지내고 계신가요?' -> 없다 -> '할머니는 지금 잘 지내고 계신단다.'

**③ 자기를 3인칭으로, 그것도 존댓말로 부른다.** 모델이 자기가 할머니인 줄 모른다.

    '할머니도 가끔 할아버지 생각을 하시곤 하단다.'   <- 자기한테 "하시곤"

**④ 사별 이야기에 차갑게 답한다. 제일 아프다.**

    '어 그냥 좀 할머니 돌아가시고 힘들어요.'  ->  '그래서 넌 어쩔 셈이니?'

**손대는 순서 제안** — ① 은 판정기 코드라 재현·수정이 명확하다. ③ 은 페르소나에
"너는 할머니 본인이다"를 못 박아 볼 만하다. ②·④ 는 프롬프트로 다섯 번 실패한
자리(6절)와 같은 성질이라 기대가 낮다.
