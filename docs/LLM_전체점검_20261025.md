# 서버 대화·LLM 전체 점검 — 2026-10-25

## 점검 범위와 운영 상태

사용자 요청으로 LLM을 중심으로 회귀 검사, 실제 모델의 의도 판정·여러 턴 답변·재회 전제·기억,
WebSocket 연결과 STT→LLM→TTS 음성 왕복을 확인했다. Unity·실제 마이크·HMD를 사용하지 않았다.
검사 전 작업 트리는 `main`의 `c2c11f55`였으며 로컬 커밋2개가 원격 추적 브랜치보다 앞서 있었다.

- 실제 모델: `gemma-4-31B-qat`, vLLM의 API 호환 이름은 `exaone`.
- 일반 답변: thinking 끔·최대256토큰. 추론 답변: 같은 모델에서 thinking 켬·최대2,048토큰.
- 문맥 한도:8,192토큰. 공통 프롬프트는 `gemma4_dialogue_v3`, 기억은 `session_memory_v1`·연결 범위다.
- 핵심 서버 소스8개의 LF 정규화 해시가 로컬과 운영에서 일치했다. CRLF 차이를 코드 차이로 세지 않았다.
- 운영 서비스·모델·설정·등록 인물·참조 음성은 교체하거나 재시작하지 않았다.
  실제 LLM 요청과 테스트 전용 임시 참조 업로드만 수행했고, 해당 참조는 종료 후 삭제했다.
- 자동 기억 검사는 동일 소스로 만든 별도 loopback 텍스트 API `127.0.0.1:18012`에서 수행했다.
  이 API에는 STT·TTS 모델을 추가 적재하지 않았으며 종료 후 포트 닫힘을 확인했다.

## 검사 도구에서 수정한 오류와 초기 실패의 해석

- `tools/eval_dialogue_memory.py`의 `TextDetector`에 현재 `Dialogue.close()`가 정리하는 `recent` 버퍼가 없었다.
  종료 때 `AttributeError`가 발생해 완료 기록을 쓰지 못했다. 해당 버퍼의 생성·초기화2줄을 추가했다.
- `tools/tests/test_eval_dialogue_memory.py`는 가짜 감지기를 실제 `Dialogue.close()`로 종료하고
  입력·보류·최근 버퍼와 기록이 비워지는지 확인한다. 새 회귀1건이 통과해 총 검사 수가582→583이 됐다.
- 임시 텍스트 API도 같은 버퍼를 갖추도록 고쳤다. 수정 전 종료 오류가 있던 결과는 보존하고
  실제 모델의 기억·WebSocket 검사만 새 파일로 다시 실행했다. 운영 서버 코드는 바꾸지 않았다.
- 첫60턴 실행에서는 음료 취향이 잡담 답변에 반복 등장해, 모든 기준 정보가 최근 기록 밖이어야 한다는 조건을
  충족하지 못했다. 기억 손실로 단정하지 않았으며 수정 후 별도 실행에서는9개 조건을 모두 충족했다.
  첫 실행에서 최근 정보를 다시 꺼내던 과한 개인화·반복 경향은 답변 품질 관측으로 남긴다.
- 첫 음성 입력은 두 문장이어서 STT가 두 발화로 나눴다. 검사 클라이언트가 두 번째 응답을 다음 요청의 응답으로
  읽어 취소 확인을 마치지 못했다. 한 문장 입력을 쓰고 전사 턴·응답 ID를 맞춰 수신하도록 검사 클라이언트를 고쳤다.
  최초 실패 기록을 남겼고, 올바른 입력·응답 대응으로 왕복·취소·복구를 다시 확인했다.

## 음성 검사의 실제 범위와 남은 확인

Windows SAPI `Microsoft Heami Desktop` 한국어 합성 녹음을 사용했다. 참조는5.77초·16kHz mono PCM16이며
Whisper가 참조를 전사했다. 최종 입력은 `오늘 기분이 좋아서 함께 이야기를 나누고 싶어요.` 한 문장이고
같은 문장으로 전사됐다. 출력은24kHz mono PCM16이며 첫 답변 약4.15초, 취소 뒤 새 답변 약2.24초의 음성을 수신했다.

재생 완료 알림은 클라이언트에서 모의로 보냈다. 실제 스피커·Unity AudioSource·HMD 청취를 검사한 것이 아니다.
합성 참조의 화자 유사도·음질·실제 사용자 마이크 정확도·잡음 환경·VR 장치 지연을 평가하지 않았다.
`response.done.timing`은 서버 생성 구간이며, STT 말끝 대기·실제 HMD 출력까지 포함한 지연으로 설명하지 않는다.

최종 운영 상태: `ready`, LLM·추론·TTS 준비 정상, 운영 연결0개. 임시 텍스트 포트: `18012` 닫힘 확인.
