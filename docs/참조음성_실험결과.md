## 확인된 것

- **참조가 지지직을 결정한다** — 직접 녹음 30/30 없음, 유튜버 녹음 40/40 있음
- **대역 분포가 원인이다** — 양방향으로 확인. bad→good 스펙트럼은 크게 개선,
  good→bad 스펙트럼은 발생(참조 자체는 깨끗했다). 보정량에 따라 단조롭게 변한다.
- **그런데 되돌릴 수 없다.** 안전 구간으로 옮기려면 1~4kHz 를 46.1% → 3.6% 로
  깎아야 하는데, 그게 말의 또렷함을 담당하는 대역이다. **지지직과 먹먹함의 맞바꿈**
  이상이 안 된다. STFT 든 FIR 이든 같다 — 구현이 아니라 목표 곡선의 문제다.
- **목소리·마이크 거리·음높이는 무관하다** — 같은 화자의 104·133·149·179·263Hz
  다섯 표본이 전부 깨끗하다. 음높이 교란은 통제 실험으로 갈랐다:
  104Hz 에 낮은 저역을 씌우면 발생, 263Hz 에 정상 저역이면 깨끗.
- **생성 파라미터로는 못 바꾼다** — RAS·temperature·top_k 셋 다 변화 없음
- **→ 실용적 답: 직접 녹음을 받을 것.** 영상·방송에서 딴 소리는 현재 방법으로 못 쓴다.

### 꼬리 무음은 해결됐다

- **참조의 쉼 비율이 출력의 꼬리를 결정한다.** 같은 참조에서 쉼만 잘라
  인과를 확인했다 — 유튜브 클립 22%→0% 는 꼬리 7.4초→0.5초에 정상 1/5→5/5,
  직접 녹음 27.6%→6% 는 8.4초→0.6초에 0/5→5/5. 전사는 원본과 같았다.
- 말하는 속도 자체는 0.103~0.128초/글자로 일정하다. **모델이 느린 게 아니라
  쉼이 아무 데나 들어가는 것**이다
- **필요할 때만 자를 것.** 쉼 18% 짜리를 잘랐더니 꼬리는 원래 좋았는데
  지지직만 0.24→0.76 으로 올랐다. 22%·28% 는 자르니 지지직도 같이 내려갔다.
  `Web/app.py` 는 **20% 초과일 때만** 자른다.

### 유튜브 클립도 쓸 수 있다 — 채널 나름이다

| 채널 | 저역 | 지지직 |
|---|---|---|
| 남자 채널 | 38.2% | 없음 |
| 여자 채널B | 59.1% | 없음 |
| 문제 채널 (2개 클립) | 5.8% / 4.0% | **심함** |

"영상에서 딴 소리는 못 쓴다"는 틀렸다. 4개 중 2개가 문제없다. 문제 채널은
**두 클립 모두 저역 4~6%** 로 재현되므로, 그 채널의 후처리 특성이다.

### 계측기 구멍 (고침)

판정 기준이 상대값(95분위의 6%)이라 **잡음 바닥만 있는 파일을 정상으로 쟀다.**
사용자가 "아예 무음"이라고 한 13초짜리를 '쉼과다'로 판정했다. 절대 음량을
먼저 보게 고쳤다 — 정상은 말 대역 RMS 0.054~0.096, 무음은 0.0002 이하다.
전체 135개를 다시 훑어 2개(둘 다 문제 채널 조건)를 찾았다.

### 지표에 대해

- **쉼 계열 지표는 청취와 5/5 일치** — 블라인드에서도 재현
- **지지직 지표는 참조를 스펙트럼 가공한 조건에 무효** — lp7k(0.23)와 d75(0.21)가
  깨끗하다고 나왔지만 실제로는 들렸다. 출력의 6kHz 대역은 참조의 그 대역을
  따라가므로 측정 대상을 손댄 셈이 된다. **원본 참조끼리 비교할 때만 쓸 것.**
- 기준을 0.5 → 1.2 로 올렸다. 새 녹음 4개가 0.02~0.78 인데 전부 깨끗하게 들렸다.
