# Tripo 얼굴 품질 조사 — 생성 쪽 손잡이 소진

기준: 2026-09-27. 앞선 기록은 [T포즈 전처리 실험](Tripo_T포즈_전처리_실험.md)이다.
이 문서는 **무엇을 시도했고 왜 기각했는지**를 남겨 같은 길을 다시 파지 않게 하는 것이 목적이다.
실제로 측정한 값과 사람의 눈 판정을 구분해 적는다.

## 0. 한 줄 결론

**얼굴이 원본과 다른 원인은 `image_to_model` 의 텍스처 생성 단계이며, 입력을 어떻게 바꿔도
결과가 움직이지 않는다.** 생성 쪽에서 건드릴 수 있는 손잡이는 전부 소진했다.
남은 길은 **다른 생성 서비스·등급으로 바꾸는 것**이고, 조명은 원인 해결이 아니라 증상 완화다.

## 1. 손실이 어디서 나는가

같은 사진(`e4fd7ec6`)으로 측정한 동일인 점수(ArcFace 코사인, `tools/face_similarity.py`).

| 단계 | 점수 |
|---|---|
| 원본 사진 | 1.00 (기준) |
| → T포즈 이미지 | 0.55 ~ 0.65 |
| → **얼굴 이식본** | **0.98** |
| → 완성된 3D 모델 | 0.13 ~ 0.35 |

렌더 방식을 나누면 형상만 −0.05~0.06, 텍스처만 0.18~0.36이다.
**정체성은 텍스처가 들고 있고, 형상은 담지 않는다.**

즉 **Tripo 에 넘기는 그림은 이미 거의 완벽한데(0.98) 굽고 나면 무너진다.**

## 2. 얼굴 크기는 입력과 무관하게 고정이다

`generate_image(t_pose)` 는 출력이 항상 1024×1024 전신이다. 전신을 그 화폭에 넣으면
머리에 배정되는 몫이 정해진다.

| | 캔버스 | 얼굴 | 얼굴 면적 비율 |
|---|---|---|---|
| 원본 사진 | 298×456 | 132×176 | 17.1% |
| T포즈 결과 | 1024×1024 | **69~74 × 96~100** | **0.67%** |
| 얼굴 이식본 | 3072×3072 | 221×303 | **0.71%** |
| 얼굴 크롭 | 184×242 | 128×178 | 51% |

원본을 크게 넣어도 T포즈 얼굴은 늘 70px 언저리다(실험 11건 전수, 본 조사 3건 재확인).
**이식본은 캔버스를 3배 키운 것이라 절대 픽셀만 늘고 비율은 그대로다.**

## 3. 기각 목록

모두 같은 사진·같은 씨앗으로 한 번에 한 변수만 바꿨다.

| 시도 | 비용 | 결과 |
|---|---|---|
| 원본 해상도 올리기 | — | 무효. T포즈 얼굴 크기가 고정이라 반영되지 않는다 |
| 멀티뷰(`--multiview`) | 90 | 사용자 판정 "아닌 것 같다" |
| 로컬 vs 서버 차이 | 75 | **차이 없음.** 같은 입력·같은 요청에서 삼각형 1.4% 변동뿐 |
| 브랜치 차이(hj/jw) | 0 | 도구·`TPOSE_MODEL`·`TPOSE_PROMPT` 전부 동일 |
| 색 정합(`_match_colour`) 끄기 | 0 | +0.001~0.003. 노이즈 바닥 0.045 미만이라 무의미 |
| 이식 확대 3배 / 5배 | 0 | 차이 없음. 원본 얼굴이 132×176 이라 더 늘려도 정보가 안 는다 |
| 텍스처 재굽기(이식본) | 20 | 아틀라스 834KB→2,621KB. **눈 판정 "거의 비슷"** |
| 형상 `detailed` + `face_limit=250000` | 100 | 삼각형 47k→237k. **"부드럽지만 원본과 차이가 더 심함"** |
| 이식 + 형상 `detailed` | 95 | 퀄리티는 낫지만 이마·뺨에 줄무늬 |
| 이식 블렌딩 4종 | 0 | **2D 이식본에는 경계가 없다.** 줄무늬는 Tripo 가 만든 것이라 블렌딩은 무관 |
| `texture_prompt.images` 2장 | 0 | Tripo 가 400(code 1004)로 **거절**. 문서에는 "파일 목록"이나 실제로는 안 받는다 |
| `style_image` 에 얼굴 크롭 | 20 | 수락되지만 **결과 차이 없음** |

2026-09-27 소모 **235 크레딧**. 거절된 요청은 작업이 생성되지 않아 비용이 없다.

## 4. 왜 "입력을 바꿔도 안 된다"가 결론인가

입력 쪽 값을 크게 흔들었는데 결과가 따라오지 않았다.

- 얼굴 픽셀 3배(74 → 221)
- 얼굴 화면 비율 70배(0.7% → 51%, 크롭)
- 텍스처 데이터 3배(834KB → 2,621KB)
- 형상 5배(47k → 237k 삼각형)

**입력에 반응하지 않는다는 것은 그 단계가 입력을 참고만 하고 스스로 그린다는 뜻이다.**
이 해석은 직접 관측이 아니라 무반응성에서 역추론한 것이므로 추정으로 남긴다.

## 5. 측정 도구와 한계

- 동일인 점수: `tools/face_similarity.py` (ArcFace `buffalo_l`, 코사인). 노이즈 바닥 0.045.
- 얼굴 이식: `Survey/core/face_paste.py`. 5점 닮음변환이라 정면 사진일수록 맞는다.
- **UV 아틀라스에서는 얼굴 검출이 안 된다.** 텍스처만 뽑아 재려 했으나 실패했고,
  점수를 내려면 모델을 렌더해야 한다(`tools/faceshot/`, 브라우저 필요).
- 그래서 3D 결과 판정은 사람 눈으로 했다. 기능 통과와 품질 판정을 구분한다.
- Tripo 는 씨앗을 고정해도 완전히 결정적이지 않다(같은 입력·요청에서 삼각형 1.4% 변동).
  **한 회차 비교로 우열을 판정하지 않는다.**

## 6. 조명에 대하여

팀원 측정에 `Scene_2` 환경광을 올리면 +0.084 (크레딧 0)로, 본 조사의 어떤 시도보다 크다.
다만 이것은 **텍스처에 이미 있는 정보를 보이게 하는 것**이지 닮음을 만드는 것이 아니다.

| 증상 | 조명으로 |
|---|---|
| 뭉개져 보인다 · 칙칙하다 | 개선 가능 |
| 안 닮았다 | **해결 안 됨** |

점수 상승분도 정체성이 좋아져서인지 측정 조건이 좋아져서인지 아직 안 갈렸다.
**원인 해결로 적지 않는다.**

## 7. 남은 선택지

1. **다른 생성 서비스** — Meshy, Rodin 등. 같은 사진으로 비교해 본 적 없다. 가장 직접적이다.
2. **Tripo 상위 등급** — P1.0 등. image-to-3D 지원 여부부터 확인이 필요하다.
3. **얼굴만 다른 방법으로** — 몸은 Tripo, 얼굴은 별도 경로로 붙이기.

공식 문서 기준 `image_to_model` 의 최신은 **v3.1-20260211** 이고 v3.2 는 없다.
`texture_quality` 는 `standard`/`detailed` 뿐이며 이미 최고값을 쓰고 있다.

## 8. 현재 서버 상태 (중요)

**임시 우회가 켜져 있다.** `~/webapp/Web/.env` 의 `MODEL_FIXTURE_GLB` 가 살아 있어
등록하면 Tripo 를 부르지 않고 준비된 모델(`~/webapp/fixtures/portrait_good.glb`)이 그대로 나간다.

- 사진과 무관하게 **모든 등록자가 같은 모델**을 받는다. 시연·배선 확인용이다.
- 끄려면 그 한 줄을 지우고 모델 워커만 재시작한다. 코드 배포는 필요 없다.
- 구현은 `Survey/core/model_pipeline.fixture_glb()`. 작업 기록에 `fixture` 단계가 남아
  나중에 Tripo 로 만든 것과 구분된다.
- 백업: `~/webapp/backups/fixture_20260918T092722/`

실제 체험을 할 때는 **반드시 끄고 확인한다.**
