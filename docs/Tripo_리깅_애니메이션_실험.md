# Tripo 생성 → 리깅 → Unity 애니메이션 실험

최초 실험: 2026-09-09 · 문서 갱신: 2026-09-10 · Unity 2022.3.62f2 / glTFast 6.14.1

이 문서는 **팔짱 입력을 사용한 최초 실험 기록**이다. 현재는 T포즈로 전처리한 인물 두 명에
각각 9개 동작을 적용하고 [전용 테스트 씬](Tripo_모델_테스트_씬.md)에서 확인한다.
최신 결과·사용량·한계는 [T포즈 전처리 실험](Tripo_T포즈_전처리_실험.md)의 현재 상태를 참고한다.

**Tripo에서 만든 앉기 애니메이션이 Unity Play Mode에서 실제로 재생됐다.**
프로젝트의 `PersonaSpawner.SpawnAsync()`를 호출해 GLB를 읽었고, 뼈대 회전뿐 아니라
스킨 메쉬의 정점 변형도 확인했다. 자동 검증 통과는 동작 여부에 대한 결과이며,
얼굴 유사도나 관절 변형의 자연스러움까지 보장하는 평가는 아니다.
**이 최초 결과는 정면에서 팔·손이 띠처럼 길게 늘어나는 심한 변형이 보여 시각 품질이 미달이었다.**

2026-09-10 후속 실험에서는 T포즈 전처리로 팔·손 변형이 크게 개선됐다.
아래 내용은 최초 팔짱 입력 실험이며, 새 결과는 [T포즈 전처리 실험](Tripo_T포즈_전처리_실험.md)에 정리했다.

## 시험 조건과 결과

기존 시험에 사용한 209 × 577px 전신 사진을 그대로 사용했다. 인물은 팔짱을 끼고 있다.
별도 사진 보정이나 추가 이미지 생성은 하지 않았다.

| 항목 | 이번 시험 |
|---|---|
| 모델 생성 | `v3.1-20260211`, `face_limit=50000` |
| 텍스처 | PBR, `texture_quality=detailed`, 원본 사진 정렬 |
| 형상 | `geometry_quality=standard`, 이미지 자동 보정 끔 |
| 시드 | 형상·텍스처 모두 `20260909` |
| 리깅 | 가능 여부 검사 통과, `v1.0-20240301`, biped |
| 애니메이션 | `preset:sit`, baked GLB |
| 실제 결과 | 삼각형 47,856개, 뼈대 41개, SkinnedMeshRenderer 1개 |
| 클립 | Legacy Animation 1개, 7.208초 |
| 파일 크기 | 3,502,720바이트, 약 3.34 MiB |
| 실제 사용량 | 75크레딧: 생성 40 + 검사 0 + 리깅 25 + 애니메이션 10 |

현재 보관된 비교용 GLB는 삼각형 100,408개이며 뼈대와 애니메이션이 없다.
이번 결과는 삼각형 수가 약 52% 적으면서 리깅과 애니메이션을 포함한다.
두 파일은 생성 시점과 조건이 달라, 이 차이만으로 모델 버전의 품질 우열을 단정하지 않는다.

## Unity에서 확인한 것

최초 실험 당시 `Assets/Editor/TripoAnimationTrial.cs`는 임시 씬에서 동일 GLB 두 개를 로드했다.
현재 코드는 저장된 `Tripo_Model_Test` 씬을 재사용한다.
당시 캡처한 정면 비교 화면은 왼쪽이 `freezePose=false`, 오른쪽이 `freezePose=true`다.
현재 비교 도구의 배치는 왼쪽 `Frozen`, 오른쪽 `Animated`다. 서버 폴링은 실행하지 않고
로컬 파일의 바이트를 실제 `PersonaSpawner` 로딩 함수에 전달한다.

- 시작과 중간 프레임을 비교했을 때 15개 뼈대의 회전이 달라졌다.
- BakeMesh로 확인한 최대 정점 이동은 메쉬 좌표계 기준 약 0.259였다.
- 실제 시간 경과에 따라 클립 시간이 증가하고 15개 관절이 움직였다.
- 자세 고정 모델에서는 움직인 관절이 0개였다.
- PBR 셰이더가 지원되고, 피부·옷 텍스처와 앉은 자세가 화면에 나타났다.

비교 화면은 모델을 보기 쉽게 같은 배율로 확대하고, 같은 방향으로 회전해 배치한다.
카페 의자에 정확히 맞춘 결과가 아니다. `Scene_2`의 원본 설정은 저장하거나 변경하지 않았다.

## 확인된 개선 지점

| 지점 | 확인 내용 | 다음 적용 방향 |
|---|---|---|
| 재생 설정 | `Scene_2`는 `freezePose=true`, `freezeTimeSec=0` | 계속 움직이게 하려면 `freezePose=false`로 새로 로드. 실행 중 체크만 바꿔서는 이미 적용한 포즈를 다시 처리하지 않음 |
| 팔과 손 | 자세 고정·재생 양쪽에서 팔·손이 띠처럼 길게 늘어남. 팔짱 사진과 자동 스킨 가중치의 조합이 원인으로 의심됨 | 팔이 몸에서 떨어진, 선명한 전신 사진으로 같은 조건을 다시 비교해 원인 확인 |
| 크기·방향 | 새 GLB의 자세 높이는 원본 배율에서 약 0.84, 씬의 배율은 0.3 | 고정 배율에 의존하지 않고 크기·바닥 기준·정면 방향을 맞춘 뒤 의자와 접촉 확인 |
| 텍스처 | 4096 × 4096 텍스처 3개, mip level은 모두 1 | mipmap 적용과 2K/4K 비교 후 Quest 실기에서 메모리·원거리 떨림·프레임 확인 |
| 얼굴 동작 | 이 GLB의 morph target은 0개 | 앉기 재생과 별도로 표정·눈 깜빡임·립싱크 구성을 준비 |

당시 다음 실험의 우선순위는 입력 사진의 팔 분리 → Unity 재생 설정 → 의자 배치 → VR 최적화였다.
이후 T포즈 입력과 전용 테스트 씬의 재생까지 확인했고, 실제 의자 배치와 VR 최적화는 남아 있다.
이번 검증 범위는 로컬 GLB의 Unity 로딩과 신체 애니메이션이다. 웹에서 서버로 업로드한 뒤
Unity가 내려받는 전체 전달 흐름, Quest 실기 성능, 립싱크는 이번에 검증하지 않았다.

## 다시 실행하기

실제 생성 시험 도구는 `tools/tripo_trial.py`다. `--image`에 사진 경로,
`--out`에 `tools/_work/tripo_trial_날짜` 형식의 출력 폴더를 지정한다.
`--dry-run`은 API를 호출하지 않는다. 실제 실행은 크레딧을 사용한다.
동일 출력 폴더로 다시 실행하면 저장된 task ID를 사용해 이어서 진행한다.

Unity에서 `Tools > Tripo > Trial > Run latest local model`을 실행하면
저장된 `Tripo_Model_Test` 씬에서 Play Mode로 실제 로더를 비교한다.
가장 최근 `animated.glb`를 선택하며 추가 Tripo 호출이나 과금은 없다.
`Sample start`, `Sample middle`, `Play animation` 메뉴로 비교하고,
`Stop playback` 또는 Unity Stop으로 멈추면 같은 테스트 씬에서 모델 검사로 돌아간다.

### 뼈대를 직접 검사하기 (2026-09-10)

`Assets/Scenes/Tripo_Model_Test.unity` 또는 `Tools > Tripo > Inspect local rig`를 열면
모델과 `Tripo 리깅 검사` 창이 자동으로 표시된다. 편집 모드에서도 재생할 수 있고 추가 API 호출은 없다.

- `생성 원본 / 리깅 원본 / 애니메이션`으로 각 단계의 결과를 전환한다.
- Scene 탭에 뼈대가 주황색으로 겹쳐 표시된다. 점을 클릭하거나 뼈 목록에서 선택한다.
- `선택한 뼈 회전 도구 (E)`로 관절을 돌려 어느 피부 부분이 따라오는지 확인한다.
- `수동 회전 되돌리기`로 초기 자세를 복원한다. 애니메이션 화면에는 동작 선택·재생·시간 조절도 있다.
- `재생 정지 · 시작 자세`로 멈추거나 다른 작업 씬을 연다.

임시 씬 생성과 원래 씬으로 자동 복원하는 방식은 전용 테스트 씬으로 대체했다.
Unity 상단의 Play/Stop을 눌러도 같은 테스트 씬에 남는다.
다른 씬에 편집한 내용이 있으면 Unity의 저장 확인을 거친 뒤 테스트 씬을 연다.
모델 추가와 선택 방법은 [모델 테스트 씬](Tripo_모델_테스트_씬.md)을 참고한다.

`영향받는 정점`은 선택한 뼈의 가중치가 0.01을 초과하는 정점 수다.
수치가 크거나 작다는 것만으로 리깅 품질을 판정하지 않는다.
자동 시험 상태도 품질 통과와 구별하도록 `playback_verified`로 표시한다.

이후 T포즈 입력으로 만든 두 캐릭터에는 각각 9개 동작을 추가했다.
최신 결과와 사용법은 [T포즈 전처리 실험의 9개 동작 적용](Tripo_T포즈_전처리_실험.md)을 참고한다.

Unity에서 세 파일을 각각 불러와 전환과 뼈대 표시를 확인했다. 생성 원본은 뼈가 0개,
리깅 원본과 앉기 적용 모델은 각각 41개다. 생성 원본과 리깅 원본의 정지 자세에서는
팔 형태가 유지되지만, 앉기 클립의 첫 프레임부터 팔·손의 심한 늘어짐이 나타난다.
따라서 리깅 원본에서 팔꿈치를 조금씩 돌려 스킨 변형을 확인하는 것이 다음 점검 순서다.
이 비교만으로 스킨 가중치와 리타게팅 중 어느 쪽이 주원인인지 확정하지는 않는다.

실제 사진·GLB·API 응답·검증 JSON·스크린샷은 git에서 제외된
`tools/_work/tripo_trial_20260909/`에 있다. 핵심 증거는 `unity_validation.json`과
`unity_front_comparison.png`다. 기존 정면 비교 화면은 왼쪽이 루프 재생, 오른쪽이 자세 고정이다.
이전 모델 폴더에는 `.exclude-from-model-test` 표식을 두어 테스트 목록에서 제외했다.
실제 GLB 파일 삭제는 도구의 자동 승인 검토에서 정책상 차단되어 실행되지 않았다.

## 공식 문서

이번 생성 파라미터는 [Tripo Image to Model v3.0/v3.1](https://docs.tripo3d.ai/model-generation/image-to-model-v3-0-v3-1.html)을 기준으로 정했다.
앉기 프리셋을 위해 리깅 v1.0을 사용했다. v2.5의 지원 프리셋과 차이는
[공식 애니메이션 리타겟 문서](https://developers.tripo3d.ai/en/docs/animations-retarget)에서 확인할 수 있다.
mipmap 설정은 [glTFast ImportSettings](https://docs.unity3d.com/Packages/com.unity.cloud.gltfast@6.14/api/GLTFast.ImportSettings.html)의 `GenerateMipMaps`에 해당한다.
Tripo도 [공식 리깅 안내](https://www.tripo3d.ai/blog/apply-preset-animations-to-3d-character)에서
몸에 붙은 팔과 합쳐진 신체 부위가 관절 인식을 방해할 수 있고, T/A 포즈가 유리하다고 설명한다.
이번 모델의 팔짱 자세가 원인이라는 판단은 팔이 분리된 입력과 추가 비교가 필요한 가설이다.
