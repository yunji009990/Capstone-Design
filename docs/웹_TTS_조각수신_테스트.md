# 웹에서 같은 음원의 재생 경로 비교

2026-09-17 최신 상태: 200ms→50ms 고정 길이 전송 실험에서도 잘림이 개선되지 않아
사용자 요청으로 **누적 버퍼와 마지막 무음 패딩을 제거하고 가변 조각 전송으로 복구**했다.
조각은 최대 200ms이고 짧은 조각도 실제 길이대로 즉시 전달한다. Unity의 스트리밍 재생은 유지한다.
아래 도구와 보관 음원은 이전 비교 자료다. 이미 생성한 파일에는 이번 변경이 반영되지 않는다.
현재 상태는 [고정 길이 전송 되돌리기](말끝_오디오_진단.md#27-고정-길이-전송무음-패딩-되돌리기)를 따른다.

2026-09-17. 현재 서버의 Qwen3-TTS로 한 번 생성한 음원을 두 경로로 재생하는 개발용 도구다.
서버에서 완성한 WAV(A)와 브라우저가 PCM 조각으로 조립한 WAV(B)를 나란히 제공한다.
A/B를 별도로 합성하지 않으므로 생성 회차 차이 없이 조립·로딩 경로를 비교할 수 있다.
이전 끝음절 청취 페이지도 서버에서 PCM 조각을 모아 WAV로 저장했다. 이번 A 경로를
엔진의 비스트리밍 생성 방식으로 해석하지 않는다.

## 실행과 사용

프로젝트 루트에서 다음 명령을 실행한다. 이 PC의 `raon` SSH 접속 권한이 필요하다.

```powershell
python tools/tts_browser_check.py --open
```

주소는 <http://127.0.0.1:8772/>다. 서버 등록 웹 8500과 별도로 이 PC에서 실행한다.
서버의 웹·대화·TTS 서비스를 재시작하지 않으며 Unity 씬과 재생 모드도 변경하지 않는다.
터미널에서 직접 실행했다면 Ctrl+C로 로컬 도구를 종료할 수 있다.

1. Unity에서 **체험 종료**를 누른다. 운영 대화 연결이 있으면 테스트 요청을 거절한다.
2. 우선 기본 대사 **오늘 와 주셔서 정말 고맙습니다.**와 **전체 문장 한 번에 생성**을 유지한다.
3. **서버에서 새로 생성**을 한 번 누른다. 현재 등록된 목소리로 A/B 공통 음원을 생성한다.
4. **같은 음원 준비 완료**가 뜨면 A와 B를 번갈아 끝까지 듣는다. 한쪽을 재생하면 다른 쪽은 멈춘다.
5. 두 쪽 모두 잘림 / A만 잘림 / B만 잘림 / 모두 정상 중 청취 결과와 잘리는 단어를 기록한다.
6. 다음 단계에서 대사 또는 생성 방식 하나만 바꾼다. 같은 회차의 A/B부터 대조한 뒤 다음 생성으로 넘어간다.

생성 중에는 음원을 재생하지 않는다. 입력·수신 오류, 취소, 완료 이벤트가 없는 연결 종료,
샘플 수·해시 불일치는 실패로 처리한다. A WAV의 형식·길이·SHA-256과 A/B **전체 WAV 바이트**가
일치해야 두 플레이어가 준비된다. 각 **WAV 내려받기**는 해당 플레이어의 음원과 같다.
다운로드 전까지 음원은 메모리에만 있다. 로컬 도구는 A WAV 한 개를 최대 10분간 보관하고,
다음 생성 또는 시간 만료 때 지운다. 이전 A의 링크를 다시 사용하려면 만료 전에 내려받아 둔다.

## 비교 조건

| 항목 | 문장별 생성 | 전체 문장 한 번에 생성 |
|---|---|---|
| TTS 요청 | 운영 `PhraseBuffer` 규칙으로 나눈 문장·구절마다 요청 | 입력 텍스트 전체를 한 번 요청 |
| 문장 사이 추가 쉼 | 운영 `SENTENCE_GAP_PCM` 사용(현재 150ms) | 별도 추가 없음 |
| 네트워크 | 생성 중 PCM 조각 전송 | 생성 중 PCM 조각 전송 |
| 브라우저 재생 | 전체 수신 후 같은 음원의 A/B 재생 | 전체 수신 후 같은 음원의 A/B 재생 |

| 경로 | WAV를 만드는 곳 | HTML 오디오가 읽는 곳 |
|---|---|---|
| A | 원격 Python `wave`로 동일 PCM 조립 | 로컬 도구의 `/audio/<임시값>.wav` HTTP 완성 파일 |
| B | 브라우저 `pcmToWav`로 수신 PCM 조립 | 브라우저 메모리의 Blob URL |

두 플레이어는 같은 `preload=metadata`를 쓰고 자동 재생하지 않는다. 서버의 완성 WAV는
로컬 도구가 원격 정상 종료·형식·PCM 해시를 검사한 다음에만 공개한다. 중간 오류나 종료 코드
실패, 잘못된 완료 순서에서는 URL을 만들지 않는다. 브라우저는 취소·새 요청·페이지 종료 때
이전 결과를 지우고 늦게 도착한 수신·해시 검사 결과가 새 결과를 덮어쓰지 못하게 한다.

24kHz·mono·PCM16, 패킷당 최대 9,600바이트, 전체 최대 45초다. 현재 등록 음성은 대화 API의
참조 준비 기능으로 읽는다. 참조·TTS voice ID는 이 요청에서 만든 것만 정리한다.
등록 인물·원본 음성·모델 설정은 수정하지 않는다. 인증 토큰은 서버 프로세스의 환경에서
원격 작업자만 읽으며 브라우저에 전달하지 않는다.

이 도구는 입력한 대사를 직접 합성한다. 마이크·STT·LLM 답변 생성·끼어들기 판정은 실행하지 않는다.
Unity가 앞서 재생한 그 회차의 원음이 아니라 **새로 합성한 음원**이다. 새 생성 버튼을 다시 누르면
생성 결과가 달라질 수 있지만, 한 회차 안의 A/B는 같은 음원이다. 웹에서도 잘린다는 결과만으로
원인을 확정하지 않는다. 두 경로에서 동일하게 잘리면 브라우저의 조각 조립이 WAV를 훼손한다는
가설을 지지하지 않는다. 생성 자체와 공통 재생 환경 등 남은 조건은 후속 비교가 필요하다.

조각 수·샘플 수·SHA-256 검사는 원격 작업자가 보낸 PCM이 브라우저의 WAV에 그대로 들어갔는지를
검사한다. 원래 생성 음성의 발음, 끝 음절의 완전성, 스피커·이어폰 출력은 사람이 별도로 판단한다.
화면의 전체 대기 시간에는 SSH와 참조 준비가 포함된다. 운영 대화 응답 지연 측정값으로 사용하지 않는다.

## 코드와 검사

- `tools/tts_browser_check.py`: 로컬 HTTP와 SSH 중계, 완성 WAV 검증·메모리 캐시. 원격 작업자는 stdin 코드로 실행하며 서버에 설치하지 않는다.
