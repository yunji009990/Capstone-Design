# 체험 시작 준비·착석 후 입력·종료 페이드 — 2026-10-24

사용자가 기능 개선 1번을 선택해 Scene_2의 준비·입장·음성 입력 순서를 연결했다.
시작 전에는 등록·대화 서버·마이크 장치·캐릭터 모델과 입장 준비를 확인한다.
입장 중에는 음성 연결·참조 음성 준비를 진행하고, 착석과 음성 연결이 모두 끝나면 새 마이크 녹음을 시작한다.
LLM·STT·TTS 모델, 서버 설정·프로토콜, 등록 인물 자료는 변경하지 않았다.

## 사용 방법

1. Scene_2에서 Play를 시작한다. 운영자 화면의 현재 상태와 마이크 아래의 상세 안내를 확인한다.
2. 모델·대화 서버·마이크 장치 준비가 끝나면 **체험 시작**이 활성화된다.
3. 시작을 누르면 인물이 입장한다. **캐릭터 입장 중 · 마이크 대기** 동안의 말은 전송하지 않는다.
4. 착석과 음성 연결이 모두 끝나면 **대화 가능** 상태가 된다. 이후 기존 음성 대화를 사용한다.
5. 문제가 있으면 안내에 따라 연결·장치를 확인하고 **준비 다시 확인**을 누른다. 체험 중에는 이 버튼과 마이크 선택을 잠근다.

마이크 사전 확인은 장치 목록과 선택 상태 기준이다. 실제 16kHz 장치 열기와 권한은 착석 후 녹음을 시작할 때 확인하고,
실패하면 체험을 중단해 안내한다. 장치가 없던 상태에서 연결하면 목록을 다시 확인한다.

시작 전 모델이 없어도 음성만 사용하려면 `ExperienceControl.voiceOnlyExperience`를 켠다.
스포너가 없는 기존 AI 테스트 구성은 음성 전용으로 동작한다. Scene_2 기본값은 캐릭터 체험이며 자동으로 음성 전용으로 바뀌지 않는다.

## 구현

| 구성 | 동작 |
|---|---|
| `PersonaSpawner` | 인물 확인·모델 대기·다운로드·표시 준비·준비 완료·실패 상태와 안내 제공. 현재 인물과 로드된 모델이 일치해야 준비 완료 |
| 모델 사전 확인 | 연결된 입장·착석 클립과 Humanoid Avatar 생성 가능 여부를 검사하고 원래 자세로 복원 |
| `ExperienceControl` | 시작 버튼과 준비 상태를 통합. 입장·착석 상태에 따라 음성 입력 허용 |
| `DialogueVoiceClient` | 연결 준비와 마이크 캡처를 분리. 입장 중에는 마이크를 열지 않으며 착석 전 음성 버퍼를 재생성해 보내지 않음 |
| 운영자 UI | 기존 상태 줄에 짧은 상태, 새 상세 안내에 다음 행동 표시. 기존 서버 확인 버튼을 준비 재확인으로 재사용 |
| 재확인 | 마이크 목록 갱신·대화 health 확인·미완료 모델 다시 준비. 준비된 모델은 다시 다운로드하지 않음 |

서버 모델 업로드 대기(404)와 다운로드 연결 실패는 기존 자동 재시도를 유지한다.
빈 모델·해석/리깅 실패는 같은 자료를 계속 해석하지 않고 안내한 뒤 명시적인 재확인을 기다린다.
입장 중 종료·연결 실패·세션 변경에서는 입력을 열지 않고 인물 연출을 정리한다.
입장 준비에 실패했을 때 서있는 인물을 남긴 채 음성 대화로 넘어가지 않는다.

추가 상세 안내는 기존 SettingsCard의 빈 영역에 배치했다. 카페·테이블·담장·유리·몸체·체형 설정은 변경하지 않았다.
F01 작업 후 사용자 요청으로 아래 간단한 종료 페이드(F04)를 추가했다.

10월24일 후속 사용자 결정: 준비 재확인 UI의 필요성·중복 배치 검토는 보류한다.
당장은 캐릭터 위치·보행을 먼저 확인하고, 추후 hj 브랜치 병합 시 양쪽 UI 변경과 충돌을 함께 대조한다.
이 결정으로 UI 버튼을 추가·삭제하거나 지금 hj를 병합하지 않는다.

## 검사

실제 대화 서비스에 접속하지 않는 loopback HTTP/WebSocket 모의 서버와 임시 Unity Play 씬에서 검사했다.
실제 결합 GLB의 로딩·Humanoid 입장·착석을 사용하고, 음성 입력은 합성 무음 PCM으로 주입했다.

- 모델 없음/업로드 대기, 다운로드 503 실패, 다운로드 지연 중 시작 차단과 재시도.
- 마이크 장치 없음 안내·시작 차단과 준비 복구.
- 입장 중 음성/텍스트 검사 입력 차단과 취소.
- 음성 연결이 먼저 끝나는 경우와 착석이 먼저 끝나는 경우.
- 실제 시작 버튼으로 시작·종료 **3회**, 착석 뒤 실제 WebSocket PCM 전달.
- 모델 없는 명시적 음성 전용 체험과 연결 종료 시 입장 취소.
- Scene_2의 상태·상세 안내·재확인·마이크 선택 연결. 1280×720 운영자 UI 촬영 확인.

결과는 Git 제외 `tools/_work/experience_preparation/validation.json`, `scene_wiring.json`, `preparation_ui.png`다.
기본 전체 검사 **582개 통과·건너뜀0개**: `tools/_work/checks/20261024T055218Z-all-b74ec596/report.json`.
실제 등록 목소리·마이크 왕복·HMD 착용과 플레이어 빌드는 이번 검사에 포함하지 않았다.

다시 검사하려면 다음 로컬 도구를 켠 뒤 Scene_2 Edit Mode에서
**Tools > 다시봄 > 개발 도구 > 대화 검사 > 로컬 음성 검사 > 체험 준비·착석 입력 제어**를 실행한다.

```powershell
python tools/unity_preparation_fixture.py
```

기본 모델은 기존 로컬 미리보기 캐시다. 다른 결합 GLB는 `--model <로컬 GLB 경로>`로 지정한다.
검사 도구는 loopback 주소만 허용하고 운영 세션을 사용하지 않는다. 완료 후 임시 씬을 닫고 Scene_2로 돌아온다.
검사 서버는 종료 후 Ctrl+C로 닫는다. 서버 응답을 흉내 낸 결과를 실제 답변 품질·음성 품질 검사로 설명하지 않는다.

## 간단한 종료 페이드 추가

같은 날 사용자 선택에 따라 별도 인사말·마무리 동작·추가 대기 없이 종료하도록 수정했다.

1. **체험 종료**를 누르면 마이크 입력·음성 재생·연결을 즉시 정리한다.
2. 인물은 그대로 둔 채 **0.8초** 동안 부드럽게 화면을 어둡게 한다.
3. 화면이 완전히 어두워지면 인물을 숨긴다. 다음 체험 시작 전까지 검은 화면을 유지한다.
4. 다음 시작은 검은 화면에서 밝아지며 같은 모델을 경로 처음부터 사용한다.

종료 중에는 시작·재확인·마이크 선택을 잠그고 반복 종료 요청을 무시한다.
연결 실패·제어 컴포넌트 비활성화는 즉시 정리하며, 페이드 도중 연출 컴포넌트가 꺼져도 종료 상태가 남지 않는다.
페이드 대상이 없는 AI 테스트 구성은 즉시 종료한다. 일반 종료 페이드는 `timeScale=0`에서도 진행한다.

시간은 Scene_2의 **체험 연출 (ExperienceCues)** Inspector에서 `Finish Darken Sec`로 조절한다.
일반 종료에는 기존 Feel 종료 플레이어의 유지·밝아짐 단계를 사용하지 않는다.
`Begin Brighten Sec`는 검은 화면에서 다음 체험을 시작할 때 밝아지는 시간이다.

동일한 로컬 검사 메뉴에 종료 흐름 검사를 추가했다. 임시 Play 씬에서0.8초 페이드5회,
인물 숨김 순서·입력 즉시 차단·종료 중/종료 후 반복 요청·재시작 밝아짐·`timeScale=0`·연출 비활성화 복구를 확인한다.
확대 검사 결과는 `tools/_work/experience_preparation/validation.json`의 `success=true`, `completedCycles=3`, `completedFades=5`다.
전체 기본 검사582개 통과·건너뜀0개: `tools/_work/checks/20261024T064732Z-all-25ae21ce/report.json`.
Scene_2의 종료 시간 외 카페 배치·유리·체형·원본 몸체 설정은 변경하지 않는다.
씬 저장으로 상세 안내의 중복 Color32 값이 실제 색과 동기화됐고, UI 촬영에서 TMP 동적 폰트 글리프·아틀라스가 갱신됐다.
작업 전부터 있던 폰트 변경은 되돌리지 않았다. 보존 비교는 `tools/_work/experience_fade_20261024/preservation.json`이다.
HMD 양안에서의 화면 덮임·실제 음성 재생 중 종료·최종 시연 녹화는 아직 검사하지 않았다.
