# Scene_2에서 등록 인물과 대화하기

기준일: 2026-09-16. 웹 설문 v2로 인물을 등록하고 **Scene_2에서 그대로 체험**하는 순서다.
설문 자료 형식과 문항 설명은 [웹 설문 v2 사용법](웹_설문_v2_사용법.md)에 있다.

**실제 사용자가 Scene_2에서 대화하려면 웹 등록이 반드시 필요하다.**
[AI 응답 테스트 씬](AI_응답_테스트_씬.md)은 대화 AI 개발용 별도 씬이고 접속 설정도 따로 쓴다.
그 씬이 등록 없이 도는 것은 개발 전용 동작이며, Scene_2에는 해당하지 않는다.

이 문서는 두 부분이다. **1~3장은 사람이 직접 쓰는 방법**, 4~5장은 개발자용 자동 검사와 검증 결과다.

> **체험 중 문제가 보이면:** 로그를 열거나 어딘가에 올릴 필요 없다.
> **평소대로 테스트하고 "언제 어떤 게 이상했다"고 알려주면 된다.** 진단 로그는 자동으로 쌓이고
> Codex 가 그것을 직접 분석한다. 이상한 순간에 `Tools/Dialogue/Diagnostics/Mark issue` 를
> 눌러 두면 지점을 더 빨리 찾는다(선택). 자세한 순서는
> [테스트 디버그 사용법](테스트_디버그_사용법.md)에 있다.
>
> 현재 진단 스키마는 **Unity `v=2`, 서버 `dialogue_diag_v4`** 이고 서버 8002 에 배포했다.
> 검증 범위와 아직 아닌 것(실제 마이크·이어폰 청취, 말끝 원인 확정)은 같은 문서의
> 「현재 검증 상태」를 본다. 아래 4~5장의 과거 검사 결과는 그 시점 기록이며 그대로 둔다.

## 1. 웹에서 인물 등록

주소는 `http://220.69.208.201:8500`이다. 지금 이 PC의 운영 주소이며, 다른 PC·다른 배포에서는 주소가 다르다.
2026-09-15 배포로 이 주소에서 아래 설문 v2 화면이 돈다.

1. **테스트 → 할머니 또는 친구.** 설문 입력만 채워진다. 자동 등록·음성·사진은 없고
   "가상 예시 인물" 표시가 남는다. 1단계의 **동의 세 가지는 직접 읽고 확인**한다.
   인물을 바꾸거나 `설문 비우기`를 누르면 **앞서 고른 사진·음성 선택이 초기화**된다.
   이전 사람의 얼굴·목소리가 새 인물에 붙지 않게 하려는 것이므로 2~3단계에서 다시 고른다.
2. **2단계 음성.** 본인이 쓸 권한이 있는, 잡음이 적은 **한 사람만 녹음된** 파일을 고른다.
   8단계에서 참조로 쓸 구간은 **3초 이상**이어야 한다.
   이번 검증에는 공개 SenseVoice 한국어 예제 `ko.wav`(4.608초)를 썼다.
3. **3단계 사진은 선택.** 사진이 없으면 3D 생성·리깅 시험은 할 수 없고,
   **씬에 이미 있는 표현과 음성 대화만** 확인하게 된다.
4. **4~7단계**에서 채워진 설문을 읽고 고칠 곳을 고친다. **8단계**에서 참조 목소리를 직접 들어본다.
5. **9단계 `AI가 이렇게 알고 대화합니다`.** 문항 번호(`단계-문항`)별 요약과 AI 인물 설명을 읽고,
   고칠 곳은 `고치기`로 해당 문항에 돌아간다. 다 맞으면 아래 **확인란**을 누른다.
   설문을 고치면 인물 설정이 **다시 작성되고 확인란이 무효**가 된다. 다시 읽고 다시 눌러야 한다.
6. **10단계 `세션 시작`.** 서버가 **UUID4 세션을 자동 발급**한다. 화면에 세션 코드가 표시되고,
   등록한 인물이 **현재 체험 인물**로 선택된다. 세션 ID를 사람이 지정하거나 덮어쓸 수 없다.

## 2. Unity Scene_2에서 체험

Unity 2022.3.62f2에서 `Assets/Scenes/Scene_2.unity`를 **직접 열고** Play 한다.
테스트 씬용 메뉴(`Tools > Dialogue > Open AI test scene`)는 다른 씬을 여는 것이므로 쓰지 않는다.

1. Play 후 화면의 **체험 시작**을 누른다.
2. 마이크로 말한다. 단추를 누른 채 말할 필요가 없다 — 서버가 말이 끝난 지점을 판단한다.
3. 끝낼 때 같은 단추(**체험 종료**)를 누른다.

Scene_2의 대화 설정은 이렇게 되어 있다. **씬마다 접속 설정은 독립**이므로 AI 테스트 씬이나
Tripo 씬의 값을 Scene_2로 가져오지 않는다.

| 설정 | 값 | 뜻 |
|---|---|---|
| `useTestProfile` | `false` | 실제 등록 인물로 대화한다. 테스트 인물 설정이 아니다 |
| `followServerSession` | `true` | 웹에서 마지막으로 등록된 인물을 자동으로 따라간다 |
| 등록 서버 | 8000 | `/session/current`를 주기적으로 조회한다 |
| 대화 서버 | 8002 | 대화 주소를 비워 두면 등록 서버와 같은 호스트의 8002를 쓴다 |

### 화면 UI 변경 (2026-09-16)

운영자 화면(`OperatorHUD`)을 정리했다. **대화 동작과 서버 설정은 바뀌지 않았다.**

- **체험자 말 받아쓰기 설정과 표시를 없앴다.** 설정 토글과 안내 문구를 지우고
  `showHeardSubtitle` 을 꺼 둔 상태로 고정했다. 이제 기록·자막에 **체험자 줄이 나오지 않는다.**
  - **음성 인식 자체는 그대로 돈다.** 서버 STT·끼어들기 판정·진단 기록에는 영향이 없다.
  - **인물(AI) 자막과 대화 기록은 그대로 나온다.**
  - 이 변경은 Scene_2 의 표시에만 적용된다. [AI 응답 테스트 씬](AI_응답_테스트_씬.md)의
    진단 출력은 그대로 둔다.
- **자리 옮기기 7개 단추**(앞·뒤·좌·우·처음·위로·아래로)의 **동작은 전과 같다.**
  세로 행을 맞추고 간격을 넓혔으며, 앞뒤좌우는 화살표, `처음`과 높이 단추는 색으로 구분했다.
  글자 크기와 테두리를 키우고 `체험 시작`·`대화 초기화` 위치를 함께 조정했다.
  단추가 부르는 기능은 그대로이며 새로 만든 UI 오브젝트는 없다.

Scene_2 Play 화면에서 표시 제거·배치·화살표 글꼴을 확인했다. 기존 7개 버튼의 `onClick`을
실제로 호출해 앞뒤 ±0.2m, 좌우·위아래 ±0.1m 이동과 `처음`의 시작 위치 복귀를 확인했다.
검사 후 위치는 복구했다. 결과는 `tools/_work/sentence_tail_20260916/replay-integration.json`의
35개 통합 검사에 포함된다. Quest 컨트롤러로 버튼을 누르는 기기 시험은 별도다.

접속 토큰 같은 인증 값은 **각자 PC의 기존 안전한 관리 절차로** 설정한다.
실제 토큰과 실제 운영 세션 ID는 문서·보고서·Git에 적지 않는다.
빈 값이나 예시 세션 ID로 우회해서 "되는 것처럼" 만들지 않는다.

## 3. 안 될 때 확인할 것

| 화면·증상 | 확인 |

| 단추가 **`서버 연결 필요`** | 대화 서버 8002가 떠 있는지, 등록·대화 주소와 토큰이 맞는지 |
| 등록은 했는데 Unity가 모름 | 세션 조회는 몇 초 주기다. 잠시 기다리거나 Play를 다시 시작한다 |

| 3D 모델이 안 보임 | 사진 없이 등록하면 생성된 모델이 없다. 음성 대화는 그대로 된다 |
| **말소리가 중간에 끊김**, 몇 턴 뒤 마이크가 먹지 않음 | 진단 기록을 켜고 다시 시험한다. [음성 재생 끊김 진단](음성_재생_끊김_진단.md) |
| **문장 끝 음절이 빠진 것처럼 들림** | 그 답변을 끝까지 들은 뒤 아래 「같은 답변 다시 듣기」로 대조한다. [말끝 오디오 진단](말끝_오디오_진단.md) |
| 갑자기 체험이 멈춤 | 화면 상태 줄의 `중단됨 · <사유>` 를 **Play 종료 전에** 적어 둔다. 같은 문서의 재시험 절차를 따른다 |

Play를 누르지 않은 상태에서는 등록해도 아무 일도 일어나지 않는다. 등록과 Play는 별개다.

### 끊김·멈춤을 다시 재현할 때

[음성 재생 끊김 진단](음성_재생_끊김_진단.md)의 「다시 시험할 때」를 따른다. 요약하면
서버 진단 로그를 켜고 → Play → **5~10턴**(짧은 답·긴 문장·끼어들기·잡음 구간 포함) →
증상이 난 **시각과 턴 번호**를 적고 → Play 종료 전에 화면 문구를 확인한 뒤 →
편집기 `\.dialogue-work/logs/` 의 최신 `.jsonl` 과 서버 진단 로그를 함께 넘긴다.
말한 내용을 적을 필요는 없다. 로그에 발화 원문이 남지 않으므로 시각과 턴으로 대조한다.

### 같은 답변 다시 듣기 (개발용)

말끝이 빠진 것처럼 들린 답변을 **그때 받은 PCM 그대로** 다시 들어 보는 편집기 메뉴다.
같은 문장을 다시 합성하면 음성이 달라질 수 있어 이 대조가 필요하다.

1. 문제가 난 답변을 **끝까지** 듣는다.
2. **체험 종료**를 누른다. **Play 는 켜 둔 채**로 두고 **`대화 초기화`는 누르지 않는다.**
   종료 뒤 연결 정리에 잠시 걸릴 수 있으니, 메뉴가 거절하면 몇 초 기다렸다 다시 고른다.
3. `Tools/Dialogue/Compare last reply/Stream renderer` 와 `.../AudioClip` 을 **각각** 고른다.
4. 두 번 다 Console 의 `turn=`·`gen=` 이 같은지 확인하고 들어 비교한다.

두 경로 모두 잘려 들리면 수신 PCM·공유 출력 단·장치를, 한쪽만 다르면 그 경로와 그때의 조건을
조사한다. **원인 확정이 아니다.** 보관은 메모리뿐이며(60초 완료본 1개, 10분 뒤 삭제, 새 응답·
새 체험·대화 초기화·등록 인물 변경·Play 종료에도 삭제) 음성·원문·세션은 파일이나 Console 에
남지 않는다. 자동으로 소리가 나지 않고, 사람이 메뉴를 고를 때만 난다.
자세한 설명은 [말끝 오디오 진단](말끝_오디오_진단.md)에 있다.

## 4. 개발자용 자동 검사 메뉴

`Tools > Dialogue > Run Scene 2 registered survey check`는 **사람 없이 한 턴을 확인하는 자동 검사**다.
평소 체험에는 필요 없고, 이 메뉴를 쓰려고 임시 씬을 만들 필요도 없다.

- 재생 중인 **실제 Scene_2**에서만 돈다. 씬을 새로 만들거나 저장하지 않는다.
- Git에서 제외된 `.dialogue-work/scene2-survey-check-config.json`을 읽는다.
  등록·대화 주소는 **loopback(QA 서버)만** 허용하고, 기대하는 세션 UUID가 현재 인물일 때만 시작한다.
  운영 현재 인물을 바꾸지 않기 위한 제한이다. 토큰은 설정 파일에 넣지 않고 씬의 값을 그대로 쓴다.
- 사용자가 누르는 경로 그대로 **시작 단추의 `onClick`을 호출**한다. `useTestProfile`은 끝까지 `false`다.
- 마이크 대신 **파일 PCM을 마이크와 같은 전송 경로로** 넣는다(80 ms · 2560바이트 조각).
  이 상태는 에디터 전용이며 Player 빌드에는 분기 자체가 컴파일되지 않는다.
- 검사가 직접 시작한 체험만 검사가 끝낸다. 이미 체험 중이면 **중단시키지 않고 실행을 거부**한다.

구현은 `Assets/Editor/Scene2SurveyValidation.cs`, 구현 메모는
`tools/_work/survey_v2_20260915/claude-scene2-report.md`에 있다.

**이 메뉴는 파일 입력 검사다.** Quest Pro 헤드셋을 쓰고 실제 마이크로 말하는 기기 시험과는 다르며,
기기 시험은 이번 결과에 포함되지 않았다.

## 5. 2026-09-15 실제 검증 결과

`tools/_work/survey_v2_20260915/scene2-{grandmother,friend}.json` — **두 인물 모두 통과.**
격리된 QA 등록·대화 서버와 공개 `ko.wav`(4.608초)를 썼다.
두 회차 모두 실제 Scene_2의 등록 흐름(`useTestProfile=false`)·시작 단추 `onClick`·`reference_icl` 참조 4.608초로
음성 전사, 본답변, 자막 표시, 재생 완료까지 통과했다.

| 항목 | 할머니 | 친구 |
|---|---|---|
| 답변 음성 샘플 (수신 = 소비) | 149,760 | 138,240 |
| 출력 피크 | 0.382 | 0.497 |
| 파일 입력 끝 → 첫 오디오 **관측** | 1.372초 | 1.304초 |
| 서버가 보고한 **본답변** 첫 음성 | 0.943초 | 0.864초 |

두 시간은 기준이 다르다. 앞의 값은 마지막 WAV 조각을 보낸 뒤 에디터에서 관측한 시각이고
대기 리액션과 본답변을 구분하지 못한다. 뒤의 값은 서버가 본답변 기준으로 보고한 값이다.
**각 인물 1회만 측정했다. 평균이 아니고, 실제 Quest 마이크 검사도 아니다.**

친구 인물의 첫 시도는 Unity의 `Failed to present D3D11 swapchain due to device reset/removed`
치명 오류로 중단됐다. 로컬 에디터의 그래픽 오류 창을 닫고 Unity를 다시 띄워 위 결과를 받았다.
**원인은 확정하지 않았다.** 이 한 번의 재시도로 장시간 Unity·Quest 안정성이 보장되지는 않는다.
사진·3D 생성 검사는 이번 범위가 아니다.
