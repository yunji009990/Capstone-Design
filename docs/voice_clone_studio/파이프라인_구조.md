# Voice Clone Studio — 전체 파이프라인 구조

다화자 오디오에서 화자 목소리를 등록하고(**사전준비**), 그 목소리로 실시간 대화하는(**테스트**)
음성 대화 시스템의 전체 구조. 백엔드는 오디오를 받아 **STT → LLM → TTS** 로 처리해 답변 음성을 돌려준다.

---

## 1. 런타임 / 프로세스 구조

```
┌─────────────────────────────────────────────────────────────┐
│  브라우저 (frontend: 정적 HTML/JS/CSS)                        │
│   · 사전준비 탭   · 테스트(대화) 탭 + 실시간 마이크 시각화     │
└───────────────┬─────────────────────────────────────────────┘
                │ HTTP (폴링 + PCM 청크 스트림) · CORS
┌───────────────▼─────────────────────────────────────────────┐
│  backend/app.py  (Flask, 127.0.0.1:5001, threaded)           │
│   라우팅 · 세션 · GPU_LOCK · 타이밍 · 파이프라인 오케스트레이션 │
└──┬──────────────┬──────────────┬───────────────┬────────────┘
   │ subprocess   │ warm socket  │ warm socket   │ HTTP
   ▼              ▼              ▼               ▼
┌────────┐   ┌──────────┐   ┌──────────┐   ┌──────────────┐
│ NeMo   │   │ STT 워커 │   │ TTS 워커 │   │ LLM          │
│ 추출   │   │ whisper  │   │ Qwen3-TTS│   │ OpenAI       │
│(nemo_  │   │ large-v3 │   │ (상주)   │   │ gpt-4o-mini  │
│ env)   │   │(eval_env)│   │(qwen3 env)│  │ (원격)       │
└────────┘   └──────────┘   └──────────┘   └──────────────┘
 필요시 1회    서버시작 예열   서버시작 예열    provider 토글
              (상주, ~1s)     (상주, ~6s/문장)  (config.json)
```

- **멀티 venv 격리**: 무거운 ML 런타임을 각자 다른 파이썬 환경에서 실행(의존성 충돌 방지).
  ambient python(Flask) / `engine/extraction/nemo_env` / `engine/tts/eval_env`(whisper) /
  `engine/tts/adapters/qwen3tts/env`(TTS).
- **웜 워커(warm worker)**: 모델을 1회 로드해 상주시키고 localhost TCP 소켓으로 JSON 요청을 받는다.
  콜드 로드 비용 제거. 준비상태는 **status 파일**로 통지(파이프 데드락 회피). 코드: `warm.py`,
  `workers/stt_worker.py`, `workers/tts_worker.py`.
- **GPU_LOCK**: STT·TTS·추출 등 GPU 작업을 앱 레벨에서 직렬화(두 모델이 동시에 상주해도 연산 경합 없음).
- **LLM provider 토글**: `config.json` 의 `llm.provider` 로 `openai`(현재) ↔ `ollama`(로컬) 전환.
  OpenAI 키는 `OPENAI_API_KEY` 환경변수에서만 읽음(코드·로그에 값 없음).

## 2. 두 단계

```
① 사전준비 (탭 1)  ── 목소리 등록 ──►  세션 생성
② 테스트   (탭 2)  ── 그 목소리로 대화 (자동 루프)
```

## 3. 사전준비 파이프라인 (목소리 등록)

```
오디오 업로드
   │  POST /api/extract  (비동기 job, GET /api/extract/<job> 폴링)
   ▼
NeMo MSDD 화자 분리   (extract_runner.py, cwd=engine/extraction)
   │   → 화자별 reference clip + 시각화 데이터(파형 / 발화 타임라인 / overlap)
   ▼
화자 선택(라디오) + 캐릭터 프롬프트 입력(기본: '친구')
   │  POST /api/prepare
   ▼
선택 화자 ref 를 1회 STT → ref_text 확보  (zero-shot: 학습 없이 추론 시 ref 만 사용)
   ▼
SESSION 생성 { ref_path, ref_text, system_prompt, history[] }
   │  (선택) POST /api/preview → 그 목소리로 임의 문장 미리듣기
```

## 4. 대화 파이프라인 (테스트 탭, 핵심)

```
🎧 대화 모드 ON
   │  POST /api/listen/start → stream_id
   ▼
[상시 캡처]  브라우저: 마이크 → 16k mono PCM → 250ms 마다 push
   │            + AnalyserNode 로 실시간 레벨 미터(막대) 시각화
   │  POST /api/listen/<sid>/push   (raw int16 PCM)
   ▼
[스트리밍 엔드포인팅]  백엔드 _listen_loop
   │   · 청크 에너지(RMS)로 말/침묵 추적
   │   · 짧은 pause(0.35s) 후보 → 그 시점까지 STT (vad_filter=ON → 무음 환각 차단)
   │   · 문장 완결 → 즉시 종료 / 한국어 연결어미(…고/…서/…는데) → 긴 pause(1.0s)까지 대기
   │   · GET /api/listen/<sid>/state 로 프론트가 상태·부분전사 폴링
   ▼  (발화 종료 감지 → turn_id 발급)
┌──────────────── 답변 생성  _stream_reply ────────────────┐
│  user_text                                                │
│     │ run_llm_stream  (OpenAI SSE 스트리밍)               │
│     ▼                                                      │
│  문장 단위로 자름 ──► 문장1 ─► TTS ─► chunk0.wav          │
│  (LLM 스트림)         문장2 ─► TTS ─► chunk1.wav  …       │
│  history 에 turn 누적                                      │
└────────────────────────────┬─────────────────────────────┘
   │  GET /api/turn/<id> 폴링 (chunks 가 준비되는 대로 누적 반환)
   ▼
[재생]  프론트: 도착한 청크를 순서대로 큐 재생 (첫 소리 ~6s)
   │     · 재생 중엔 마이크 정지(에코 방지)
   ▼
재생 끝 → 자동으로 다시 listen/start  (대화 루프 반복)
```

### 엔드포인팅 임계값 (`app.py` 상단 상수)
| 상수 | 기본값 | 의미 |
|---|---|---|
| `VOICE_RMS` | 400 | 이 이상이면 '발화'로 간주 |
| `SHORT_PAUSE` | 0.35s | 문장 완결 시 이 pause 로 종료 |
| `LONG_PAUSE` | 1.0s | 연결어미(미완결)면 이만큼 더 대기 |
| `MIN_SPEECH` | 0.35s | 최소 발화 길이(오종료 방지) |
| `MAX_UTT` | 20s | 최대 발화 길이(안전장치) |

### 무음 환각(Whisper) 방어
- **VAD 필터**(`vad_filter=True`): 비음성 구간을 전사 전에 제거 → "자막을 켜고 시청해주세요" 류 환각 차단.
- **환각 블랙리스트**(`_is_noise_text`): 자막/구독/시청 등 유튜브 자막류 문구가 들어가면 발화로 치지 않음.
- **재무장(re-arm)**: 노이즈 블립이 잘못 트리거하면 긴 pause 후 다시 대기 상태로 리셋.

## 5. 성능 / 지연 (RTX 5060 Ti, 한 턴)

| 구간 | 시간 | 비고 |
|---|---|---|
| 발화 종료 감지 | 완결 ~0.35s / 미완결 ~1.0s | 스트리밍 엔드포인팅 |
| STT (웜) | ~1s | vad_filter 로 환각 차단 |
| LLM 첫 문장 | ~0.8–2s | OpenAI 스트리밍 |
| TTS 첫 문장 (웜) | ~수 초 | 문장 스트리밍 |
| **첫 소리까지** | **~6s** | 이후 문장은 재생 중 생성 |

- 서버 시작 시 STT·TTS(+Ollama 사용 시 LLM) 백그라운드 예열.
- Qwen3-TTS 는 실시간보다 느려(RTF~1.9) 답변이 아주 길면 문장 사이 공백이 생길 수 있음.
  기본 프롬프트가 한두 문장으로 유지 → 보통은 끊김 없음.

## 6. API 요약

| 단계 | 엔드포인트 |
|---|---|
| 화자 추출 | `POST /api/extract` · `GET /api/extract/<job>` |
| 목소리 준비 | `POST /api/prepare` · `GET /api/prepare/<id>` |
| 미리듣기 | `POST /api/preview` · `GET /api/preview/<id>` |
| 대화(엔드포인팅) | `POST /api/listen/start` · `POST /api/listen/<sid>/push` · `GET /api/listen/<sid>/state` · `POST /api/listen/<sid>/cancel` |
| 답변 폴링 | `GET /api/turn/<id>` → `{transcript, reply(누적), chunks:[{idx,text,audio_url}], timing}` |
| 기타 | `GET /` · `GET /static/<f>` · `GET /files/<path>` · `GET /config` |

## 8. 핵심 설계 결정 요약

- **STT·TTS 웜 워커**: 콜드 로드(수십 초) 제거 → 매 턴 즉시 처리.
- **문장 스트리밍**: 답변 전체를 다 만들지 않고 첫 문장부터 합성·재생 → 첫 소리 지연 대폭 감소.
- **스트리밍 엔드포인팅**: 긴 침묵을 기다리지 않고 "문장 완결 + 짧은 pause"로 발화 종료를 빨리 감지.
- **VAD + 블랙리스트**: Whisper 무음 환각 차단.
- **대화 모드 일원화**: 푸시투토크 제거, 버튼 조작 없이 자동 루프.
- **LLM provider 토글**: 로컬(Ollama) ↔ OpenAI 전환. 오디오는 항상 로컬, 텍스트만 provider 로 전송.
