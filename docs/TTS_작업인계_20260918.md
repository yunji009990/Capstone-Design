## 2. Qwen 꼬리 잘림 — 조사 종료 상태

**사용자가 Qwen 신규 진단 실험을 중단시켰다. 아래 항목을 다시 파지 않는다.**

기각되었거나 해결에 이르지 못한 것:

- 공식 `qwen_tts` `generate_voice_clone`로 **완결된 WAV를** 뽑아도 잘림이 보고되었다.
- 청크/전체, 현재/공식 디코더, CPU/GPU, 정상 오디오 코덱 왕복 — 모두 **전송·디코더 절단 가설에 불리**하다.
  단, 완전한 배제 증명은 아니다.
- EOS 지연: 견고한 해결책 없음. 구/신 baseline 바이트 동일, 이후 case6 한 건은 정상으로 들림.
- x-vector: 꼬리는 고쳐졌으나 **클론 정체성이 무너짐**.
- 참조 무음 추가 실패. sub-talker greedy 실패(여러 화자 공통).
- 새 참조: 일부 개선, 전부는 아님. 전사도 함께 바뀌어 **근본 원인 증명이 아니다**.

마지막 구간(모음 길이 가설):

- 등록 음성 "고맙지" round3: 원본/1.5x/2x/fade **전부 정상**으로 들림 → 실패 재현 대조군이 아니므로 개선 근거에서 제외.
- 새 참조 "고맙지" round1: 단어는 들리나 끝이 급함. **모음 누락은 입증되지 않음**.
- 사용자 요청으로 기존 **등록 음성 + 다른 문장** "오늘 와 주셔서 정말 고맙습니다" 진행
  (`qwen-sentence-tail`): **4개 버전 모두 잘림으로 들림.** 회차 범위는 미지정.
- round1/2에서 후보는 **42ms뿐**(+21/+42ms stretch), fade-only 후보는 마지막 12ms를 남긴다.
  음소 경계가 불확실하고 rubberband 크롭 후 실제 음소 정렬도 확인하지 않아 **길이 가설을 배제하지 않는다.**

결론: **품질 수정은 달성하지 못했다.** 런타임은 원본 Qwen 가중치 + vLLM-Omni + 자체 전송·분절이며,
공식 예제 그대로가 아니다. **공통 참조 전처리·전사는 여전히 용의선상에 있다.**

## 4. VoxCPM2 전환 구성과 검사 기준

### 4.1 현재까지의 근거
- Vox는 이전에 **클론 스트리밍 + 취소 HTTP 테스트를 통과**했다. 단, **격리 실험**이며
  당시에는 운영·Unity 검증 전이었다. 이번 운영 적용 결과는 아래 완료 기록을 따른다.
- 후보 코드: `tools/_work/tts_replacement_20260917/` 의 `vox_candidate.py`, `vox_http_trial.py`,
  `vox_http_remote.py`, `http_vox_eval.py`를 확인한다. `bridge.py` 파일은 없다.
- 사용자 평가: **Qwen보다 자연스럽지는 않지만 끝맺음이 좋다.** 참조 전용(reference-only) 우선 후보.
- venv·환경·정확한 경로는 **기존 스크립트를 읽어서 확인**한다. 맹목적으로 재설치하지 않는다.

### 4.2 반드시 지켜야 할 공개 계약 (8003 그대로)
- 엔드포인트: `/health`, `/voices`, `/synthesize`
- `/synthesize`: NDJSON `started` / `audio` / `done` / `error`
- 24kHz mono PCM16, 청크 최대 9600바이트, 가변 청크
- `source_samples`, `padding_samples=0`
- 취소 시 **모델 생성 워커가 실제로 멈춘 뒤 API 직렬화 게이트를 해제**한다. 모델 가중치를 매번 내리는 의미는 아니다. 참조 정리도 보존한다.
- Vox 네이티브 48kHz → **flush 포함 리샘플**
- **voice mode를 거짓으로 `reference_icl` 이라 표기하지 않는다.** 참조 전용이면 그대로 표기한다.
- `Server/realtime_tts.py`에 `reference_audio`를 추가했고 TTS health/voices 및 대화 API health/voice.ready가 실제 모드를 전달하도록 수정했다. `reference_icl`은 Qwen 호환용이다.
- `TTSClient.reaction_identity()`에 URL·model·streaming·voice_mode가 이미 포함된다. Vox의 정확한 model/mode를 보고하여 새 키로 리액션을 준비하게 한다. 캐시·페르소나 자료를 임의 삭제하지 않는다.

### 4.3 검증 계획과 실제 수행 범위
1. 모의 계약 검사 → 확인: 위 4.2 항목 일치
2. 라이브 클론 소수 케이스 + 취소 1건 + 동시 요청 2건 → 확인: 스트림 정상 종료, 취소 시 해제
3. health·로그 확인 → 확인: 오류 없음
4. **사용자 청취** → 확인: 끝맺음 판정

불필요한 전수 검사는 하지 않는다. 기능 통과와 실제 음성 품질은 별개로 기록한다.
실제 전환에서는 합성 3건·취소 1건과 health를 확인했다. 라이브 동시 요청 2건 검사는 실행하지 않았다.
완료 검사는 아래 6장에 기록했으며 새 실패 근거 없이 반복하지 않는다.

### 4.4 전환 전 안전 조치
- 전환 **전에** TTS `.env`와 대상 파일의 백업·해시를 남기고 롤백 절차를 확보한다.
- Scene_2 사용자 테스트는 **백엔드만 바꾸면 되며 Unity 편집이 필요 없다.**

## 7. 모델 확정과 참조 음성 기준 (2026-09-18 추가)

### 7.1 확정 내용

사용자 결정으로 **운영 TTS는 VoxCPM2를 유지·확정**한다. 근거는 말끝 종료가 안정적이고
Qwen 꼬리 잘림 원인이 미해결이라는 점이다. 자연스러움이 Qwen보다 떨어지는 것은
확정 시점에 이미 알고 받아들인 트레이드오프다. 다음 세션은 모델 교체나 새 모델 비교를
먼저 제안하지 않는다. 기존 비교 자료는 `/prosody/`, `/vox-ending/` 청취 페이지에 남아 있다.

### 7.2 참조 음성 실측 (읽기 전용)

사용자가 "목소리가 그 사람 같지 않고 말투가 기계 같다"고 판정한 뒤, 참조 후보 3종을
같은 방식으로 측정했다. 측정은 서버 tmpfs에서만 하고 음성은 즉시 삭제했다.
원본 음성·전사는 저장소에 넣지 않았다.

| 항목 | 등록 참조(당시 사용자 본인 목소리) | 공개 한국어 | Vox 공식 예제 |
|---|---|---|---|
| F0 중위 | 107.6 Hz | 124.0 Hz | 320.0 Hz |
| F0 범위 | 5.1 반음 | 7.1 반음 | 9.7 반음 |
| 유효 대역(에너지 99%) | 1,748 Hz | 2,261 Hz | 6,507 Hz |
| 길이 | 9.75초 | 4.61초 | 12.8초 |
| 앞 무음 | 0.86초 | 0.78초 | 0.22초 |
| 끝 무음 | 0.44초 | 1.02초 | 0.24초 |
| 피크 / 클리핑 | 11431 / 없음 | 8570 / 없음 | 6967 / 없음 |

읽는 법과 한계를 구분한다.

- **F0 범위 5.1 반음**은 단조로운 낭독을 뜻한다. "말투가 기계 같다"에 가장 직접 대응하는 수치다.
  목소리 높낮이가 아니라 **읽은 방식**의 문제이므로 재녹음으로 바뀔 수 있다.
- **유효 대역 1,748 Hz**는 먹먹함이다. 샘플레이트는 24 kHz이므로 그릇의 한계가 아니다.
- 단, 이 대역 지표는 **음높이와 교란된다.** 낮은 목소리는 저역 에너지가 커서 수치가 내려간다.
  그래서 1,748 Hz를 전부 녹음 탓으로 단정하지 않는다.
- **F0 107.6 Hz 자체는 정상 남성 범위**다. "낮아서 안 된다"는 결론은 성립하지 않는다.
  낮은 음역·단조로움·먹먹함이 겹친 것으로 본다. 이것도 청취 판정과 함께 봐야 하며 확정 원인은 아니다.

측정기는 스크래치패드의 `ref_probe.py`(수치 측정)와 `ref_fetch.py`(tmpfs 내려받기)다.
저장소에 두지 않았으므로 다시 필요하면 같은 항목으로 새로 만든다.

### 7.3 시연용 참조를 고를 때의 기준

사용자 요청은 "괜찮게 나오는 참조 하나를 찾아 보여주기용으로 쓴다"다. 목표는 원인 규명이 아니라 선별이다.

- 녹음 조건: 마이크 20 cm 이내, 감정을 넣어 억양이 오르내리게, **끊지 말고 이어서 10–12초**,
  앞뒤 여백 0.2초 내외, 중간에 1초 넘는 쉼 없음, 안내 문구로 끝내지 않음.
- 수치 기준: F0 범위 8 반음 이상, 고역이 살아 있음, 앞뒤 무음 짧음.
- 절차: 수치로 먼저 걸러내고 → **참조만 바꿔** 같은 문장 3개를 합성 → 청취 페이지로 사람이 판정.
- **참조를 바꾸면 나오는 목소리가 그 참조 화자의 목소리가 된다.** 시연에서 음질을 보이는 목적이면
  괜찮지만 "이 분 목소리를 재현했다"는 맥락으로 쓰면 어긋난다. 이 구분을 보고에 유지한다.
- 선별은 `AI_Response_Test` 테스트 모드의 참조 업로드로 하여 **등록 인물 자료를 건드리지 않는다.**
  Scene_2 시연에 실제로 쓰려면 웹 등록으로 참조를 다시 등록해야 하며, 이는 사용자 승인 사항이다.

### 7.4 Scene_2에서 STT 전사가 안 보이는 이유

버그가 아니라 설정이다. Scene_2의 `DialogueVoiceClient`에 `showHeardSubtitle: 0`이 저장돼 있다.
서버 전사는 정상 수신되어 `lastHeard`와 진단 로그에 남지만, UI 전달에서만 빈 문자열로 바뀐다.
근거는 `Assets/Scripts/Dialogue/DialogueVoiceClient.Realtime.cs:504`다.

- 코드 기본값은 `true`(`DialogueVoiceClient.cs:17`). `AI_Response_Test`는 `DialogueTestPanel.cs:44`에서 항상 켠다.
  그래서 테스트 씬에서는 보이고 Scene_2에서는 안 보인다.
- 런타임 토글용 `SubtitleToggle` 컴포넌트는 있으나 **Scene_2에는 배치되어 있지 않다.**
- 디버깅 중에는 Play 중 인스펙터 체크로 켠다. 씬 저장이나 토글 배치는 Scene_2 수정이므로 승인 사항이다.
