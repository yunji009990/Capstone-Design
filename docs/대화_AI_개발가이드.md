# 대화 AI 개발 가이드

기준일: 2026-09-13. 사용자 결정: **우리 작업은 대화 AI, 팀원 작업은 T포즈·3D 모델 제작**이다.
공통 지침은 [AGENTS.md](../AGENTS.md), 검사 명령은 [AI 하네스](AI_하네스.md)를 따른다.

## 1. 목표와 현재 기준

`AI_Response_Test`에서 사용자의 말·Unity 상황을 이해하고 인물 설정과 대화 기록을 유지하며 자연스러운 텍스트 답변을 만든다.
말하는 도중 사용자가 끼어들면 의도에 따라 보류·재개·수정·주제 전환·대기를 처리한다.

현재 구현은 SenseVoiceSmall·VAD → 의미 판정 → Gemma 4 31B QAT → 텍스트 응답이다.
일반/추론 경로는 같은 Gemma의 thinking 설정 차이이며 TTS는 꺼져 있다.
새 모델 교체나 TTS 재활성화보다 현재 대화의 재현 가능한 품질 평가를 우선한다.
등록·테스트 인물은 `gemma4_dialogue_v1` 공통 프롬프트를 사용한다.
규칙·예시 배치·기존 인물 호환·실제 비교 결과는 [Gemma 4 대화 프롬프트](Gemma4_대화프롬프트.md)에 있다.

모델 생성, T포즈 편집, 리깅, 9개 동작 팩, 서버의 제작 목록·GLB 다운로드는 팀원이 담당한다.
대화 개발을 위해 팀원의 Tripo 제작 기능을 구현하거나 `Tripo_Model_Test`, `Scene_1`, `Scene_2`를 변경하지 않는다.
모델을 제작하지 않아도 임시 테스트 인물·텍스트 입력·모의 Unity 상황으로 개발할 수 있다.

## 2. 구현 위치

| 관심사 | 위치 | 보존할 계약 |
|---|---|---|
| 인증·접속·테스트 모드 | `Server/dialogue_server.py` | 등록 체험과 임시 테스트 연결의 분리 |
| 인물 조회 | `Server/persona_client.py` | 읽기 전용 API, revision·참조 음성 해시 |
| STT·감정·VAD | `Server/realtime_audio.py` | 16kHz PCM 입력, 발화 관측과 종료 판단 |
| 대화 기록·응답 상태 | `Server/realtime_dialogue.py` | 전달한 답변만 기록, 늦게 도착한 취소 응답 배제 |
| 의도·일반/추론 판정 | `Server/interruption_policy.py`, `realtime_llm.py` | 현재 정책과 출력 검증, 미전달 초안 제외 |
| 인물·지식·공통 규칙 | `Server/persona_context.py` | 인물과 실제 제공된 정보의 일관성 |
| Unity 대화 | `Assets/Scripts/Dialogue/` | response_id, 입력/재생 턴, 중단·초기화, 자막 |
| Unity 검사 | `Assets/Editor/DialogueTestScene*` | AI 전용 설정, 실제 검사 결과 기록 |

`Server/registration/`는 인물 정보의 제공자다. 인터페이스를 읽어 이해하되 대화 개발에서 웹·DB·제작 처리로 범위를 넓히지 않는다.
공통 API 변경이 필요한 요청에서는 제공자·소비자 코드를 함께 검토하고 `--area all`로 검사한다.

## 3. 작업 시작과 반복 절차

1. Git 상태와 관련 함수를 확인한다. 현재 문제를 재현할 입력·이전 대화·기대 결과를 기록한다.
2. `python tools/check.py --area dialogue`로 기본 검사를 실행한다. 최근 같은 코드의 통과 결과가 있으면 불필요하게 반복하지 않는다.
3. 한 동작이나 가설을 수정하고 필요한 회귀 검사를 보강한다.
4. 변경에 맞는 아래 실제 검사 단계를 선택한다.
5. 입력·실제 응답·기대 동작·시간 범위·판정 근거와 검사 버전을 결과에 남긴다.

## 4. 실제 검사 선택

| 단계 | 실행 방법 | 무엇을 확인하는가 |
|---|---|---|
| 모의 계약 | `python tools/check.py --area dialogue` | 대화·인물 API·취소·버퍼·참조 계약 |
| 실제 판정 모델 | `tools/eval_turn_judge.py`와 [판정기 검사 문서](판정기_텍스트_검사.md) | 일반/추론·끼어들기 사례의 기대값 일치 |
| 실제 답변 모델 | `tools/eval_dialogue_prompts.py`와 [프롬프트 문서](Gemma4_대화프롬프트.md) | 가상 인물의 여러 턴 기억·정정·말투·설명 비교. Unity 불필요 |
| Unity 텍스트 연결 | AI 씬 Play 후 `Tools > Dialogue > Run text response check` | 실제 서버 응답·Unity 상황 전달·연결 설정 |
| 공개 WAV 경로 | `Tools > Dialogue > Run AI test scene check` | STT 관측→실제 답변 경로. 현재 TTS 꺼짐 |
| 실제 여러 턴 대화 | AI 씬에서 같은 임시 인물로 대화 | 자연스러움·기억·지식 근거·수정 반영 |
| 실제 마이크·VR | 실제 입력 장치에서 같은 대본 비교 | 소음·발화 종료·인식·중단·장치 지연 |

Unity 설정과 결과 파일은 [AI 응답 테스트 씬](AI_응답_테스트_씬.md)에 있다.
MCP에서는 현재 프로젝트를 확인하고 사용자가 편집 중인 씬 상태를 보존한다. TTS 의존 검사 때문에 TTS를 자동으로 켜지 않는다.
실제 GPU 모델을 쓰는 평가는 모의 검사 명령에 포함하지 않는다. 현재 등록 인물을 평가 인물로 교체하지 않는다.

## 5. 다음 대화 개발의 우선순위

1. **여러 턴 품질 평가를 확장한다.** `eval_dialogue_prompts.py`의 기본·별도 대본에 더 다양한 가상 인물과 긴 대화를 추가한다.
   사실 지어내기, 불필요한 회피, 말투, 앞선 답변과의 모순을 전체 기록으로 평가한다. 현재 판정기 68개 사례와 별도의 평가다.
2. **실제 입력의 발화 종료와 인식을 확인한다.** 말 중간의 쉼·짧은 맞장구·정정·침묵을 구분해 기대 동작을 정한다.
   텍스트 입력, 공개 WAV, 실제 마이크를 구분해 STT와 대화 로직 중 어디서 실패했는지 확인한다.
3. **응답 지연과 끼어들기 경험을 개선한다.** 첫 글자, 보류 시간, 판정 시간, 재개·취소를 같은 조건에서 측정한다.
   발화 길이·VAD 종료 무음·STT·모델·네트워크·장치 지연 중 포함한 범위를 명시한다.
4. **Unity 대화 UI와 오류 복구를 다듬는다.** 연결 실패·재접속·취소·초기화 때 사용자에게 보이는 상태와 대화 기록을 검증한다.

위 순서는 다음 작업의 기준이다. 답변 비교 실행기는 구현됐으며 음성 입력·지연·Unity UI 개선 전체가 완료됐다는 뜻은 아니다.
얼굴·손가락·리깅·대화 동작 연결 및 TTS 품질 확장은 별도 통합 범위로 남긴다.

## 6. 운영과 완료 보고

대화 서버는 `~/capstone-server`, API는 8002다. 웹·등록·Tripo의 `~/webapp`과 독립 실행한다.
대화 API 제어는 `dialogue.sh api`, 배포 묶음은 `tools/service_bundle.py dialogue`다.
모의 검사나 문서 수정은 서버 재시작을 요구하지 않는다. 배포가 포함된 요청은 해시·health·로그까지 확인한다.

완료 보고에는 변경 이유, 수정 파일, 모의 검사 결과, 실제 모델·Unity·마이크 검사 여부,
남은 품질 한계와 서버 반영 여부를 포함한다. 과거 검사 기록을 이번 변경의 실제 실행 결과로 표시하지 않는다.
