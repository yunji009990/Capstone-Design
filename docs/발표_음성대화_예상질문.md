# 발표용 LLM·STT·TTS 예상 질문과 답변

기준일: 2026-11-05. 실제 구현과 기존 검사 기록을 바탕으로 정리한 발표 답변이다.
새 모델 실행이나 추가 성능 측정은 하지 않았다. 기존 서버와 현재 API 시연본의 모델·측정값을 구분한다.

| 구분 | 기존 GPU 서버 | 현재 API 시연본 |
|---|---|---|
| LLM · 답변 생성 | Gemma 4 31B QAT | OpenAI gpt-5.4-mini |
| STT · 음성 인식 | Whisper large-v3 | OpenAI gpt-transcribe |
| TTS · 음성 합성 | 서버 VoxCPM2 | PC VoxCPM2 |

현재 시연본도 기존 참조 목소리를 유지하기 위해 TTS를 직접 실행한다.
실행 구성은 [로컬 API 시연](로컬_API_시연.md), 공통 계약은 [서버 음성 대화 구조](서버_음성대화_구조.md)를 따른다.

## 1. AI 모델을 직접 개발하거나 학습한 건가요?

사전 학습된 모델을 활용했습니다. 저희가 구현한 부분은 인물 정보에 따른 대화 구성, 기억 관리,
사용자 끼어들기 처리, 음성 스트리밍과 VR 연결입니다. 이 기능들이 하나의 대화 경험으로 이어지도록 통합했습니다.

## 2. 왜 음성 인식·대화·음성 합성을 분리했나요?

각 단계의 품질과 오류를 따로 확인하고 개선하기 위해서입니다. 예를 들어 인식 결과는 맞는데 답변이 이상하면
대화 처리를 확인할 수 있고, 다른 기능을 유지하면서 특정 모델만 교체할 수도 있습니다.

## 3. 특정 인물처럼 말하게 만드는 방법은 무엇인가요?

등록 설문에서 관계, 호칭, 말투, 함께한 기억 등을 받아 프롬프트에 구성합니다. 여기에 최근 대화와 핵심 기억을
함께 제공해 같은 인물의 설정을 유지하도록 합니다. 인물마다 모델을 새로 학습하는 방식은 아닙니다.

## 4. 대화가 길어지면 앞에서 한 말을 잊지 않나요?

최근 대화 원문과 별도로 중요한 사실을 추려 관리합니다. 일정이나 취향을 정정하면 새 정보를 반영하고,
삭제 요청도 처리합니다. 현재 기억은 같은 대화 연결 안에서 유지되며 재접속 후 복원은 구현하지 않았습니다.

## 5. RAG나 벡터 데이터베이스를 사용했나요?

현재 벡터 데이터베이스는 사용하지 않습니다. 등록된 인물 자료와 사용자 발화에 근거한 핵심 기억을 선택해
답변 입력에 넣습니다. 기억에는 원문 출처를 연결해 어떤 말에서 나온 정보인지 확인할 수 있도록 했습니다.

기억 범위·출처·삭제 계약은 [대화 메모리](대화_메모리.md)를 따른다.

## 6. 실제로 없었던 추억을 AI가 만들어 내면 어떻게 하나요?

개인적인 사실과 추억은 등록 자료나 실제 대화에 근거하도록 하고, 모르는 내용은 확인하도록 지시합니다.
말투 예시도 실제 기억과 구분합니다. 다만 프롬프트만으로 오류를 완전히 막을 수는 없어
여러 턴의 대화로 설정 유지 여부를 점검하고 있습니다.

## 7. 일반 대화와 깊은 추론은 어떻게 구분하나요?

사용자 발화와 대화 맥락을 판정해 일반 응답과 추론 경로를 선택합니다. 같은 모델에서 추론 설정을 다르게
사용하는 구조입니다. 현재 API 시연본은 일반 응답에 `none`, 추론 경로에 `low`를 사용해 불필요한 대기 시간을 줄입니다.

## 8. 서버 버전에서 Whisper를 선택한 이유는 무엇인가요?

한국어 인식 정확도와 처리 지연의 균형을 고려했습니다. 공개 한국어 녹음30개 비교에서 Whisper는
깨끗한 음성의 문자 오류율이3.48%, 평균 인식 처리 시간이0.159초였습니다. 이는 파일 입력의 STT 단독 결과이며,
현재 API 시연본의 성능과는 구분합니다.

표본·정규화·인식 구간·제외 항목은 [STT 모델 비교](STT_모델_비교.md)를 따른다.

## 9. 잡음이나 기침에도 AI가 답하지 않나요?

먼저 발화 후보를 찾고, Silero VAD로 사람의 말이 포함됐는지 검증한 뒤 전사를 확인합니다.
잡음만으로 진행 중인 답변을 중단하지 않도록 구성했습니다. 다만 매우 작거나 짧은 발화가 누락될 수 있는 한계는 있습니다.

## 10. 사용자가 말을 끝냈다는 것은 어떻게 판단하나요?

현재는 발화 뒤 약700ms의 무음을 기준으로 입력을 확정합니다. 너무 짧게 잡으면 생각하면서 말하는 문장을 끊고,
너무 길면 응답이 늦어지는 관계가 있어 종료 대기와 인식 시간을 함께 고려합니다.

## 11. 실시간이면 말하는 도중에도 계속 인식하나요?

음성은 계속 받지만, 현재 STT는 확정된 발화 구간을 모아서 인식합니다. 이후 답변 텍스트와 합성 음성은
생성되는 순서대로 전달합니다. 따라서 입력부터 출력까지 모든 단계가 같은 방식의 스트리밍인 것은 아닙니다.

## 12. TTS로 VoxCPM2를 선택한 이유는 무엇인가요?

등록 음성을 참조한 목소리 합성과 생성 중 음성 전달이 가능하고, 프로젝트에서 중요했던 말끝 종료의 안정성을
고려했습니다. 이전 후보에서 말끝 잘림 문제가 남아 있어 VoxCPM2로 확정했습니다.
자연스러움과 화자 유사도는 참조 음성 품질까지 함께 확인해야 합니다.

## 13. 목소리를 재현하려면 많은 녹음이나 추가 학습이 필요한가요?

현재는 인물별 추가 학습 없이 참조 음성으로 목소리 특징을 준비합니다. 처리에 사용하는 참조는3~12초의 연속 구간이며,
준비된 특징을 답변 합성에 재사용합니다. 짧은 녹음도 사용할 수 있지만 잡음, 녹음 상태, 발화 방식에 따라 결과가 달라집니다.

모델 결정·참조 녹음 기준은 [TTS 작업 인계](TTS_작업인계_20260918.md)7장을 따른다.

## 14. 사용자의 감정을 인식해서 목소리도 바꾸나요?

대화 내용에 나타난 감정에 맞춰 LLM이 공감하는 표현을 생성합니다. 현재 목소리에서 감정을 분류하는 기능이나,
감정 강도를 수치로 지정해 합성하는 기능은 구현하지 않았습니다. 음성의 표현에는 참조 녹음과 합성 모델의 특성이 영향을 줍니다.

## 15. 응답을 빠르게 하기 위해 무엇을 했나요?

일반 대화에서는 추론을 줄이고 답변을 간결하게 구성합니다. 답변 전체가 끝나기 전에 완성된 구절부터 TTS에 보내고,
TTS도 만들어진 음성부터 전달합니다. 참조 음성 특징을 재사용하고, 추론 대기 중에는 미리 준비한 짧은 리액션을 활용합니다.

## 16. 실제 응답 시간은 몇 초인가요?

발화 종료 감지, STT, 의도 판정, 답변 생성, TTS, 재생까지 나눠 측정하고 있습니다.
기존 서버의 의도 판정은68개 사례에서 중앙값0.463초였고, 현재 배포본의 API STT는 단일 검사에서1.156초였습니다.
두 값 모두 전체 대화 응답 시간은 아니며, 현재 시연본의 발화 끝부터 HMD에서 첫 음성이 들릴 때까지의 평균 지연은
별도 측정이 필요합니다.

판정은 [LLM 전체 점검](LLM_전체점검_20261025.md), API 단일 표본은 Git 제외
`tools/_work/local_demo/validation/package/voice.json`의 `stt.seconds`가 근거다.
같은 파일의 `first_pcm_seconds`는 입력 파일 전송 시간까지 포함하므로 말끝 기준 응답 시간으로 인용하지 않는다.
리액션 첫 음성, 본답변 첫 음성, 전체 합성 완료도 서로 다른 지표다.

## 17. AI가 말하는 도중 사용자가 끼어들면 어떻게 되나요?

확인된 사용자 발화에 따라 답변을 이어갈지, 내용을 수정할지, 주제를 바꿀지, 기다릴지 판단합니다.
예를 들어 “응, 계속해”는 재개하고 “그건 됐고 다른 이야기하자”는 기존 답변을 취소합니다.
현재는 발화 종료와 인식 후 반영하므로 사용자가 입을 여는 순간 즉시 멈추는 방식은 아닙니다.

## 18. 중간에 끊긴 답변도 AI는 이미 말한 것으로 기억하나요?

Unity가 실제로 어디까지 재생했는지 서버에 알려 줍니다. 그 확인을 바탕으로 전달된 답변 부분을 대화 기록에 반영합니다.
사용자가 듣지 못한 내용을 이후 대화에서 이미 설명했다고 가정하는 문제를 줄이기 위한 처리입니다.

## 19. API 버전이면 GPU 없이, 인터넷 없이도 실행되나요?

현재 시연본은 LLM과 STT가 OpenAI API를 사용하므로 인터넷이 필요합니다. 기존 목소리를 유지하는 VoxCPM2는
PC에서 실행하므로 NVIDIA GPU도 필요합니다. 학교 GPU 서버에 접속하지 않고 실행할 수 있도록 분리한 구성입니다.

## 20. 개인정보는 어디로 전달되고, 현재 검증은 어디까지 됐나요?

API 모드에서는 대화·인물 설정이 LLM API로, 인식할 음성이 STT API로 전달되며 목소리 합성은 로컬에서 처리합니다.
대화 기억 초기화와 등록 사진·음성 삭제는 별도입니다. 현재 실제 음성 입력→전사→답변→목소리 합성,
취소 후 재응답을 확인했으며, 목소리 유사도와 실제 HMD 체감 품질은 기능 검사와 구분해 평가해야 합니다.

LLM 요청에는 `store=false`를 지정하지만 이를 모든 외부 처리·보관이 없다는 의미로 설명하지 않는다.
참조 음성의 전사 확인에도 STT API를 사용한다. 실제 개인정보·키·참조 녹음·세션 식별자는 이 문서에 포함하지 않는다.
