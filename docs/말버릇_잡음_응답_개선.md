# 말버릇·잡음 응답 개선

기준일 2026-09-17. 적용 버전은 공통 프롬프트 `gemma4_dialogue_v3`,
약한 전사 거절 `weak_transcript_v1`(0.75 / -0.35)이다. 운영 8002에 배포했다.
입력 검증 전체 구조는 [서버 음성 대화 구조](서버_음성대화_구조.md)의 「입력 검증」,
v1 당시의 프롬프트 변경 기록은 [Gemma 4 대화 프롬프트](Gemma4_대화프롬프트.md)에 있다.
생성을 거치지 않고 나가던 고정 안내 문장의 처리는 [캐릭터 확인·기억 삭제 안내](캐릭터_확인_안내.md)에 있다.

## 1. 왜 바꿨나

- 등록 설문이 만드는 `[말투]` 줄이 말버릇을 "자주 씁니다"라고 지시하고, 말투 예시에도 같은
  추임새가 들어 있어 **반복을 유도하는 구조**가 프롬프트 안에 있었다. 가상 인물 2명의 여러 턴
  비교에서 실제로 같은 말버릇이 답변마다 이어지는 것을 확인했다(아래 §3).
  실제 사용자 음성이나 답변 원문 로그로 확인한 것은 아니다.
- 주변 잡음이 Whisper에서 짧은 문자로 전사돼 입력으로 채택되면, 말하지 않았는데도 캐릭터
  답변이 보류되거나 새 답변이 시작될 수 있었다.

## 2. 무엇이 어떻게 동작하나

### 말버릇 반복 억제 (`Server/persona_context.py`, `realtime_dialogue.py`)

- `normalize_quirks()`는 생성된 인물 글의 `[말투]` 다음 **첫 목록 줄 하나**만 본다.
  `- "…", "…" 같은 말을 자주 씁니다.` 형식이 정확히 맞을 때만 선택적 표현 줄로 바꾼다.
  형식이 어긋나거나 다른 구역의 자유 입력이면 아무것도 바꾸지 않는다.
- 인물을 **불러올 때** 적용한다. 운영 등록 파일, 등록 API, 웹 설문 생성기는 수정하지 않는다.
  말버릇 표현 자체는 사라지지 않고 "필수가 아니다"라는 읽는 법만 붙는다.
- 전달이 확인된 **최근 답변 3개**에서 한 번이라도 쓴 말버릇은 다음 생성의 시스템 문구에
  `[표현 반복 주의]` 짧은 지시로 넣어 피하게 한다. 취소로 전달되지 않은 구간, 들려주지 않은 초안,
  대기 리액션은 그 기록에 들어 있지 않다.
- 사용자가 그 표현을 직접 꺼내거나 청한 턴에서는 막지 않는다.
  존댓말·반말, 호칭, 관계, 인물의 사실은 그대로 유지하라고 함께 지시한다.
- **새 Gemma 호출을 만들지 않고, 생성된 답변에서 문구를 지우는 후처리도 하지 않는다.**

### 약한 전사 거절 (`Server/speech_gate.py`, `realtime_dialogue.py`)

- 판단에 쓰는 값은 Whisper가 **같은 전사 호출에서** 세그먼트마다 준 지표뿐이다.
  추가 추론이나 별도 모델을 돌리지 않는다.
- 같은 세그먼트 안에서 `no_speech_prob >= 0.75` **그리고** `avg_logprob <= -0.35`가
  **표기 내용이 있는 모든 세그먼트**에 성립할 때만 후보를 조용히 거절한다(`weak_text`).
  정상 세그먼트가 하나라도 있으면 보존한다. 지표가 없거나 범위를 벗어난 세그먼트는
  unknown이며, 모르는 것을 근거로 버리지 않으므로 역시 보존한다.
- `compression_ratio`는 진단으로만 모은다. 거절에 쓰지 않는다.
  글자 수·단어 수·같은 음절 반복·RMS로도 거절하지 않는다. 마이크 점검이나 음절 연습도
  정당한 발화이기 때문이다.
- 거절은 `accept_candidate` **전에** 일어난다. 그래서 진행 중인 답변의 보류·재개·취소,
  `speech.started`, 화면 전사, 대화 기록, 기억은 전혀 바뀌지 않는다.
- 세그먼트 지표는 서버 내부 판정 전용이다. `Observation.metadata()`가 `quality`를 제외하므로
  Unity로 나가는 공개 메타데이터에는 들어가지 않는다.

### 바뀌지 않은 것

Silero 입력 검증(`threshold` 0.7 / 최소 200 ms), 말끝 무음 700 ms, 끼어들기 정책
`semantic_v1`, TTS 생성 스트리밍과 Unity 재생 계약은 그대로다.
**AEC와 스피커 에코는 이번 작업 범위가 아니다.** 이 변경은 잡음 오작동을 줄이는 것이고
잡음이 완전히 사라진다고 보장하지 않는다.

## 3. 검증과 한계

결과 파일은 `tools/_work/input_style_fix_20260917/`에 있고 Git에서 제외한다.
아래 검사들은 확인 범위가 다르므로 건수를 하나의 품질 점수로 합산하지 않는다.

### 모의 계약 검사 (`checks-release/report.json`)

`python tools/check.py --area all` **456개 통과, 건너뜀 0**
(하네스 160 + 서버 247 + Tripo 작업자 5 + 웹 44).

### 말버릇 — 실제 Gemma 여러 턴 비교 (`style-comparison.json`)

할머니와 친구 두 인물로 각각 12턴 × 3 seed를 돌려 변경 전 72턴, 변경 후 72턴을 비교했다.

| 관찰 | 변경 전 | 변경 후 |
|---|---|---|
| 연속한 두 답변에 같은 말버릇이 나온 쌍 | 8 | 0 |

| "진짜" 사용 | 11/36 | 1/36 |

**이 대본에서** 말버릇 반복이 거의 사라졌고 기억·정정 동작은 유지됐다.
모든 인물과 모든 상황에서 자연스러움이 최적이라는 뜻은 아니다.

### 입력 경로 전후 비교 (`actual-input-comparison.json`)

최종 0.75 설정으로 실제 WebRTC → 말끝 → Silero → Whisper 입력 경로에 73가지 조건 × 3회 =
**219건**(앞선 168건 + 그때 쓰지 않은 51건)을 통과시켰다.

- 정상 99건 중 변경 전후 모두 **96건 채택**. 새로 놓친 입력은 **0**이다.
  나머지 3건은 합성 "네" 단독이며 변경 전후 모두 기존 Silero 단계에서 누락됐다.
- 잡음 120건은 변경 전후 모두 **응답 0**이다.

이 회차의 음향 모델과 STT는 실제이지만 **LLM은 stub이고 TTS는 없다.**
아래 전체 클립 실험의 잡음 차단 15건과 같은 결과로 합치지 않는다.

### 임계값 재적용 (`quality-calibration-release.json`)

`asr-quality.json`의 기존 실측값(공개·합성 56가지 조건 × 3회 = 168건)에 최종 0.75 / -0.35
순수 함수를 다시 적용한 계산이다. **모델을 새로 돌린 것이 아니다.**
정상 72건은 72건 그대로 유지, 기존 게이트를 통과해 문자로 전사됐던 잡음 15건은 0건이 됐다.

### 임계값을 0.7에서 0.75로 올린 이유 (`short-candidate-probe.json`)

첫 후보값 0.7은 짧은 맞장구 "으음" 3건을 새로 거절했다. 그 자리에서 배포를 멈추고 잘린
후보에서의 값(`avg_logprob -0.791015625`, `no_speech_prob 0.7021484375`)을 확인한 뒤
0.75로 보완했다.

### 배포 후 운영 확인 (`live-release.json`, `deployment.json`)

승인된 5개 실행 파일만 백업 후 반영했고 배포 해시 일치를 확인했다.
`/health`는 `status=ready`, `llm_ready=true`·`tts_ready=true`, `prompt_version=gemma4_dialogue_v3`,
`weak_text` `weak_transcript_v1`(0.75 / -0.35), 연결 수 0이다.
백업은 서버의 `~/capstone-server/backups/input_style_20260916T162304Z`에 있다.
LLM·TTS·웹 프로세스는 재시작하지 않았다.
실제 모델 확인: `/v1/models`의 root는 `gemma-4-31B-qat`이고 `exaone`은 API 호환 이름이다.

운영 8002 WebSocket에 실제 VAD·Silero·Whisper·Gemma·Qwen TTS를 연결해 확인했다.

- 공개 한국어 음성, 합성 "으음", 숫자 "3"의 3가지 입력 × 3회 = **9/9 PCM 수신 성공**.
- 무음·백색 잡음 대조 **2/2에서 새 응답 없음**.
- 공개 메타데이터에 `quality`가 없음을 확인했다.

재생 확인은 가상 `playback.done`이다. **Unity 실사용, 실제 스피커, 실제 마이크 검사는 아니다.**

### 남은 한계

- 이 지표는 오디오가 아니라 전사 결과만 본다. **다른 사람의 말소리나 스피커에서 나온 캐릭터
  음성은 실제 사람 말이므로 체험자의 말과 구분하지 못한다.** 에코 대책(AEC)은 별개다.
- 합성 "네" 단독 3건은 이번 변경과 무관하게 기존 Silero 단계에서 누락된다.
- 실제 마이크·이어폰 청취·Quest 기기 검증은 하지 않았다.

## 4. 로그에서 확인하는 법

서버 진단 로그는 [음성 재생 끊김 진단](음성_재생_끊김_진단.md)의 설정을 그대로 쓴다.

- **거절**: `input.rejected`의 `reason=weak_text` 줄. 연결 누계는 `weak_text` 계수다.
- **채택**: `input.candidate`의 `reason=accepted`, 그리고 응답 턴과 잇는 `input.assigned`.
- `input.verified`는 채택·거절 판정이 아니라 전사가 끝났다는 줄이다. 채택된 입력에도 같은
  숫자를 남기는 것은 임계값을 다시 정할 때 정상 입력의 분포를 봐야 하기 때문이다.
  **`input.verified`가 있다고 채택된 것이 아니다.**
- 숫자의 뜻:

| 이름 | 뜻 |
|---|---|
| `no_speech_pct` | 표기 내용이 있는 세그먼트의 `no_speech_prob` **최댓값** × 100 |
| `avg_logprob_x100` | 같은 세그먼트들의 `avg_logprob` **최솟값** × 100 |
| `compression_x100` | `compression_ratio` **최댓값** × 100 (진단용) |
| `text_segments` | 표기 내용이 있는 세그먼트 수 |
| `weak_segments` | 두 지표가 함께 약했던 세그먼트 수 |

평균이 아니라 **가장 약한 쪽 값**이다. `weak_segments`가 `text_segments`와 같아도
지표를 모르는 세그먼트가 있으면 실제로는 보존될 수 있다.
집계 숫자로 혼합·unknown 입력의 최종 판정을 대신하지 않는다.
로그에는 발화 원문과 오디오를 남기지 않는다.

## 5. 시험해 보는 법

Scene_2에서 기존 등록을 그대로 두고 체험을 새로 연결하면 새 공통 규칙이 적용된다.
**웹에서 인물을 다시 등록할 필요가 없다.**

1. Scene_2에서 Play → 등록된 인물로 체험 시작.
2. 5~10턴 이어서 말하며 같은 인물의 답변 첫머리가 매번 같은 말로 시작하는지 본다.
3. 아무 말도 하지 않고 종이·의자 소리만 나는 구간을 두고, 캐릭터 답변이 까닭 없이 멈추거나
   새로 시작하는지 본다. 다른 사람의 말소리는 이 검사의 대상이 아니다(§3 「남은 한계」).

실제 마이크 입력과 Unity 재생 확인은 사용자 후속 테스트다.
이어폰으로 먼저 들어 보면 스피커 반향과 이번 변경의 효과를 구분하기 쉽지만, 필수 조건은 아니다.
