# T포즈 전처리 후 Tripo 리깅 비교

2026-09-10

## 현재 상태

**서로 다른 인물 두 명을 T포즈로 전처리해 생성·리깅·9개 동작 적용까지 완료했다.**
Unity에서는 [전용 모델 테스트 씬](Tripo_모델_테스트_씬.md)을 열어 모델과 동작을 바꿔 확인한다.
두 모델 모두 편집 모드와 Play Mode에서 9개 동작의 재생·관절·메쉬 변형 검사를 통과했다.

| 로컬 결과 폴더 (`tools/_work/` 아래) | 삼각형 | 관절 / 동작 | 실제 Tripo 사용량 |
|---|---:|---|---:|
| `tripo_trial_20260910_tpose` | 48,534 | 41 / 9 | 155크레딧 |
| `tripo_trial_20260910_tpose_male` | 49,524 | 41 / 9 | 155크레딧 |

각 155크레딧은 생성·리깅·앉기 75와 나머지 8개 동작 80의 합이며 이미지 편집 도구 사용량은 제외한다.
최초 팔짱 입력 실험의 75크레딧은 별도다. 그 모델은 테스트 목록에서 제외했고 로컬 원본은 남아 있다.

현재 흐름은 내장 `image_gen`으로 전처리 → `tripo_trial.py`로 생성·리깅·앉기 적용 →
`tripo_motion_pack.py`로 나머지 동작과 팩 구성 → Unity 로컬 검사다.
웹 등록·서버 자동 전처리·대화에 따른 동작 선택·얼굴 및 손가락 애니메이션은 이 작업에 통합하지 않았다.
사진과 GLB는 로컬에 보관하며, 커밋에는 코드·테스트 씬·문서를 남긴다.

## 첫 번째 인물의 비교 배경

팔짱을 낀 사진으로 만든 첫 모델은 생성 원본과 리깅 원본의 정지 자세에서는
팔 형태가 유지됐지만, 앉기 클립을 적용하자 팔과 손이 띠처럼 늘어났다.
같은 인물을 T포즈로 바꾼 입력으로 이 문제의 개선 여부를 비교한다.

## 전처리에 사용한 도구

이번 전처리는 대화에 연결된 **내장 `image_gen` 이미지 편집 도구**로 수행했다.
프로젝트 서버의 자동 전처리 기능으로 연결한 것은 아니다.
기반 모델의 정확한 제품명과 버전은 이번 도구 응답에서 제공되지 않았다.

- 입력: 이전 실험의 `reference.jpg`, 209 × 577px.
- 출력: `tools/_work/tripo_tpose_preprocess_20260910/reference_tpose.png`, 1254 × 1254px.
- 편집 요청: 얼굴·나이·머리·옷을 유지하고 정면 전신 T포즈로 변경.
- 확인 항목: 팔과 몸통의 분리, 수평으로 뻗은 팔, 손끝·발끝의 포함, 다리 사이 간격, 단순한 배경.
- 전체 프롬프트: `tools/_work/tripo_tpose_preprocess_20260910/prompt.txt`.
- 입력·출력 해시와 확인 기록: 같은 폴더의 `preprocessing.json`.

원래 사진은 보존했다. 전처리는 자세와 함께 정면 구도·해상도·세부 표현을 바꾸므로
이번 결과를 T포즈 하나만의 효과로 해석할 수는 없다. 인물 유사도도 별도로 확인한다.

## Tripo 실행 조건

첫 실험과 생성 버전, 시드, 폴리곤 목표, 텍스처 품질, 리깅 버전, 앉기 프리셋을 동일하게 사용한다.
실험 스크립트는 Python 3.9 이상에서 실행하며 기존 `Survey/core/tripo.py`와 표준 라이브러리를 사용한다.
실제 호출은 환경변수 `TRIPO_API_KEY`, 없으면 로컬 `Web/.env`에서 키를 읽는다.
키를 결과 파일이나 커밋에 복사하지 않는다. `--dry-run`에는 키가 필요하지 않다.

```powershell
python tools/tripo_trial.py --image tools/_work/tripo_tpose_preprocess_20260910/reference_tpose.png --out tools/_work/tripo_trial_20260910_tpose
```

동일 출력 폴더로 재실행하면 저장된 task ID로 이어서 진행한다.
현재 결과와 다른 이미지·설정을 쓰려면 새 출력 폴더를 지정한다.
`--dry-run`은 API를 호출하지 않으며, 새 실험 1회 예상 사용량은 75 Tripo 크레딧이다.
내장 이미지 편집 도구 사용량은 이 Tripo 크레딧 수치에 포함되지 않는다.

Unity에서는 `Assets/Scenes/Tripo_Model_Test.unity`를 열면 모델과 검사 창이 자동으로 표시된다.
편집 모드에서도 생성 원본·리깅 원본·애니메이션을 확인할 수 있다.
실제 로더 비교는 `Tools > Tripo > Trial > Run latest local model`로 같은 테스트 씬에서 실행한다.
자세한 사용법은 [모델 테스트 씬](Tripo_모델_테스트_씬.md)을 참고한다.

## 9개 동작 적용 (2026-09-10)

T포즈로 만든 동일 모델의 기존 리깅을 재사용해 요청한 동작 9개를 적용했다.
기존 앉기 결과는 재사용했고, 나머지 8개 리타겟 요청의 실제 사용량은 **80 Tripo 크레딧**이다.
이 작업에서 모델 생성이나 리깅을 다시 요청하지 않았다.

아래 길이는 첫 번째 T포즈 모델에서 받은 클립의 실측값이다. 두 번째 모델의 길이는
일부 다르므로 실제 재생에는 각 모델의 `motion_catalog.json`과 Unity 검사 창의 값을 사용한다.

| 검사 창의 동작 | Tripo 프리셋 | 첫 모델의 길이 |
|---|---|---:|
| 앉기 | `preset:sit` (기존 결과 재사용) | 7.208초 |
| 주변 둘러보기 | `preset:biped:look_around` | 12.500초 |
| 인사 | `preset:biped:greet_01` | 2.833초 |
| 작별인사 | `preset:biped:wave_goodbye_01` | 5.300초 |
| 동의 | `preset:biped:agree` | 3.233초 |
| 박수 | `preset:biped:clap` | 10.967초 |
| 포옹 | `preset:biped:hug` | 4.500초 |
| 웃기 | `preset:biped:laugh_01` | 4.500초 |
| 흐느끼기 | `preset:biped:sob` | 4.500초 |

**Unity에서 확인하는 순서**

1. `Assets/Scenes/Tripo_Model_Test.unity`를 연다.
2. 자동으로 열린 검사 창에서 `테스트 모델`을 선택한다.
3. 검사 창에서 `3. 애니메이션`을 선택한다.
4. `동작` 목록에서 원하는 항목을 고르고 `재생`을 누른다.
5. `반복 재생`, 시간 슬라이더, `일시 정지`, `처음으로`, `다음 동작`으로 비교한다.
6. 확인이 끝나면 재생을 멈추거나 다른 씬을 연다. Unity Play/Stop을 사용해도 같은 테스트 씬이 유지된다.

동작을 바꾸면 해당 동작의 시작 자세에서 멈춘다. 이어서 `재생`을 누른다.
캐릭터 크기는 리깅 원본의 서 있는 높이로 한 번 정규화하므로 앉기·서기 전환 때 바뀌지 않는다.
`뼈대 겹쳐 보기`는 Scene 탭에서 관절을 검사하는 기능이고, Game 탭에서는 표면을 확인할 수 있다.
이 검사와 재생에는 추가 API 호출이 없다.

검사 창은 같은 폴더의 `animated_pack.glb`가 있으면 우선 사용한다. 없으면 예전 `animated.glb`를 읽는다.
팩은 메쉬 1개·스킨 1개·관절 41개·클립 9개이며 파일 크기는 6,175,208바이트다.
원본 리깅의 메쉬·텍스처·바인드 포즈를 유지하고 동작 데이터만 합쳤다.
노드의 계층 경로, 관절 순서, 초기 변환을 확인하며, 서로 다른 리깅의 데이터는 합치지 않는다.
합친 파일과 각 Tripo 원본의 시간·동작 키프레임 값 408,996개가 일치함을 확인했다.

Unity 2022.3.62f2에서 9개 클립을 실제로 불러왔으며, 클립마다 재생 시간이 약 0.85초 진행했고
실제 재생 중 9~15개 관절이 움직였다. 시작·25%·50%·75%·끝 자세를 비교해 관절·메쉬 변형과
정점 값이 유한함을 검사했다. 결과는 `all_motions_verified`다.
각 클립의 중간 자세도 Unity 화면으로 확인했다. 이 검사는 재생 가능 여부와 일부 자세의 확인이며,
전체 프레임의 관통·발 미끄러짐·의자 접촉까지 검증한 것은 아니다.

웃기·흐느끼기는 몸동작이다. 이 모델에는 얼굴 표정용 morph target과 개별 손가락 뼈가 없어
웃는 얼굴·우는 얼굴이나 세밀한 손가락 동작은 추가되지 않는다. 포옹도 현재 한 사람의 동작만 재생한다.
또한 각 프리셋의 원래 전신 동작을 적용했으므로, 모두 앉은 자세에서 수행하는 제스처는 아니다.
검사 창에서 직접 선택하는 로컬 시험이며, 대화 내용에 따른 자동 동작 선택은 아직 연결하지 않았다.

**재현 도구와 결과**

```powershell
# 기존 작업 ID/파일을 재사용한다. 빠진 동작을 새로 요청할 때만 과금된다.
python tools/tripo_motion_pack.py --trial-dir tools/_work/tripo_trial_20260910_tpose

# API 호출 없이 기존 파일로 팩만 다시 묶는다.
python tools/tripo_motion_pack.py --trial-dir tools/_work/tripo_trial_20260910_tpose --build-only
```

`--dry-run`은 네트워크를 호출하지 않고 요청 목록과 신규 생성 기준 예상량을 보여준다.
`--motion look_around`처럼 하나만 받아 API 호환성을 확인할 수 있다.
`tripo_motion_pack.py`는 제출 중 연결이 끊겨 task ID를 확보하지 못하면 중복 과금을 피하기 위해 자동 재제출하지 않는다.
`tripo_trial.py`는 저장된 task ID가 있는 단계만 재사용한다. 제출 응답을 받기 전에 끊겨 ID가 기록되지 않았다면
Tripo의 실제 작업 상태를 먼저 확인하고 재실행해야 한다.

`tools/_work/tripo_trial_20260910_tpose/`의 추가 파일:

- `animations/*.glb`: Tripo에서 받은 동작별 원본.
- `animated_pack.glb`: Unity에서 선택해서 재생하는 9개 클립 팩.
- `motion_tasks.json`: 작업 ID, 응답, 실제 사용량. 서명 URL이 포함된 비공개 기록.
- `motion_catalog.json`: 한글 이름, 원본 파일 해시, 길이·관절·클립 정보.
- `unity_motion_validation.json`: Unity의 실제 재생과 변형 검사 결과.
- `unity_motion_visual_review.json`, `previews/tripo_pack_*.png`: 각 동작의 중간 자세 관찰과 화면.

자동 검사는 `3. 애니메이션`을 연 뒤 `Tools > Tripo > Rig view > Validate all animations`으로 다시 실행한다.
동작 이름은 [Tripo 공식 리타겟 문서](https://developers.tripo3d.ai/en/docs/animations-retarget)의
리깅 v1.0용 목록을 참고했다. 이번 호출은 기존 작업 ID에 맞춰 v2 OpenAPI의 `animate_retarget`을 사용했다.

## 서비스에 자동화할 때

이번에 사용한 `image_gen`은 대화의 내장 도구 이름이다. 같은 종류의 전처리를 서버에서
자동화하려면 원본 사진과 편집 지시문을 받는 [OpenAI Image API의 Edits 기능](https://developers.openai.com/api/docs/guides/image-generation#edit-images)을 연결할 수 있다.
구현 흐름은 사진 업로드 → T포즈 이미지 생성 → 이미지 확인 → Tripo 생성 → 리깅 → 애니메이션이다.
이번 실험에서는 이 서버 기능을 추가하거나 운영 파이프라인을 변경하지 않았다.

## 두 번째 인물 추가 (2026-09-10)

사용자가 제공한 베이지색 카디건 인물 사진에도 같은 과정을 적용했다.
내장 `image_gen`으로 정면 전신 T포즈를 만들고, 놀란 표정은 입을 다문 중립 표정으로 바꿨다.
원본·전처리 이미지·전체 프롬프트·해시는 `tools/_work/tripo_tpose_preprocess_20260910_male/`에 보존했다.
각각 `reference_original.png`, `reference_tpose.png`, `prompt.txt`, `preprocessing.json`이다.

새 모델은 `tools/_work/tripo_trial_20260910_tpose_male/`에 저장했으며 기존 모델을 덮어쓰지 않았다.
같은 생성·리깅 설정과 9개 프리셋을 사용했다. 최종 `animated_pack.glb`는
